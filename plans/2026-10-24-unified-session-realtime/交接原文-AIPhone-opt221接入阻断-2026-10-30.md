## 源码核对与修复要求

只读核对正式 wheel 的 `agent_orchestrator/host/delegation.py`，当前委派键为：

```python
key = f"session:{self.session.session_id}:{turn_id}:{digest(spec['goal'])}"
```

目标正文由模型生成，重放时同义改写即可改变键。当前在途限制只阻止尚未终态的委派；首个任务
完成后不再挡住第二次创建。这解释了实测中的两条 delegation 记录；最终修复方案由 SDK 决定。

必须在 SDK 中建立稳定的“已接纳用户回合 → 委派意图/调用槽位 → mission”绑定，使未知结果
恢复不依赖模型再次生成完全相同的 goal 字符串。已有委派的结果必须能在原输入回合恢复；
不得再次创建任务、重复记账或重复设备操作。规格冲突需显式报告，不得把原回合解释成新意图。

请同时解释并修复原回合在委派成功后仍没有 Session receipt 的恢复路径。公开中断和同键恢复
必须有可诊断、有限等待的结果，不能要求宿主修改 SDK 数据库或丢弃原输入键。

不接受以下消费者绕行作为修复：

- App 做目标语义去重，或复制 SDK 的委派状态机。
- 写 SDK 私有表、替换内部 delegate、合成 committed receipt。
- 禁止所有重试后声称恢复已通过。禁用只属于临时隔离。

请发新的正式 wheel、SHA256SUMS、兼容说明和新增回归结果。开发期允许新数据根，但应明确
本次数据是否可继续读取；AIPhone 保留本次证据目录，不自行尝试 schema 修补。

## SDK 修复后的必需复验

1. 同一 key、同一文本在委派成功、Session receipt 未提交时重放，仍只有一个 mission。
2. 第一条任务已 `COMPLETED`、`CANCELLED` 或 `FAILED` 后重放；不再委派第二条任务。
3. 模型用中文/英文、空白变化或同义句改写同一目标，不能改变原意图身份。
4. 在接纳输入、写入委派、创建 mission、工具结果落账、最终 receipt 落账各边界杀进程，重启后
   同键恢复；不得重复执行或重复消耗配额。
5. 新 key 的明确新请求仍可创建新任务；原 key 携带不同原文应拒绝。
6. 第一条任务仍在执行时并发重试；不得出现第二条任务或永久 busy/turn_pending。
7. 原输入可得到确定的最终回执，任务结果可入 inbox、应用于后续对话并由用户显式 ack。
8. AIPhone 从 App 重新完成文字任务闭环、取消、服务崩溃恢复、整机重启、安装回退。
