# 统一主会话 + 按需委派 + Realtime：评估与深度计划

日期：2026-10-25。对象：AIPhone 2026-10-24 交接文（原文存 `交接原文-AIPhone-2026-10-24.md`）。
写法：先答图片里的四个问题，再给改写后的任务书，最后是分阶段计划。
所有"已核实"条目都是今天亲自查源码、制品、官方文档或跑试验得来的，不是转述交接文。

## 0. 一句话结论

交接文的方向对，范围过大。合理做法是：**拆成三个可独立发版的制品，按"先验线路、再写代码"的顺序做，每一阶段都有外部裁判。**

1. 编排 SDK：文本主会话 + 内置委派 + 结果 inbox（不依赖语音，先发）。
2. Service SDK 0.3.13：Realtime 工具循环 + 上下文注入 + 改钉版（依赖冲突今天已证明只是钉版问题）。
3. 联合桥（放在编排 SDK 的可选 extra 里）：把语音工具调用接到主会话，负责播报调度与重连。

三者之前先做 2 天"可行性门"。门里的 6 个试验决定后面哪些承诺能写进合同，哪些要退回 AIPhone 重定。

## 1. 四个问题

### 一、顶尖专家会做、而交接文没要求的

| 专家会做的事 | 交接文的状态 | 本计划怎么补 |
|---|---|---|
| **先在真线路上证伪，再写合同。** 语音工具调用、后台结果注入、会话中文字输入，三件事都没有官方文档保证。专家会先花半天各写一个 60 行脚本去撞真实线路，拿到服务端回执再定接口。 | 要求"第一阶段必须验证"，但验收表 A06/A08 已假定能成。 | 阶段 0 可行性门，6 个试验，每个有通过/不通过判据和不通过时的替代路线。 |

| **把"对方不在本机"写成风险。** AIPhone 源码和 chinzy 中继源码都不在这台 Mac 上。 | 交接文默认 SDK 侧能看到。 | 凡依赖中继行为的判断，都用线路回执（`session.updated` 回显）证明，不用本地适配器标志。 |

### 三、专家会用的方法与工具

1. **线路探针脚本**（阶段 0）：用 Service SDK 自己的 `RealtimeClient` + TokenSeller 凭据铸造器写，不用 curl 手拼。原因是本项目有教训：探线路必须用 SDK 自己的解析器逐行喂，否则复现不了真实失败。
2. **录音固定集**：三段 16 kHz PCM 录音（"查一下家里哪台设备没电"、"帮我整理这周的照片做个相册"、"取消刚才那个任务"），每次试验都用同一组文件，结果才可比。
3. **路由标注集**：60 条用户输入，四类标签，两个人独立标，分歧条目讨论定稿后冻结。
4. **故障注入**：沿用编排 SDK 已有的"每个持久关键点退出再恢复"测试写法（`accounting_recovery` 一类），对 session→delegation→mission→inbox 四个持久点各注一次。
5. **幂等矩阵**：同键同规范 / 同键异规范 / 新键同目标 / 新 call_id 同意图，四格各一条测试。
6. **发版门**：编排 SDK 的部署清单字节校验 + 验收门；Service SDK 的 BOM 溯源门 + 公开接口 JSON（`tests/public-api.json`）+ conformance kit。两边都已存在，不新造。
7. **独立评审**：主体写完后交一个 Opus 5.5 子代理按"只报阻断级"评审（项目既定规则）。
8. **仓库外验收**：`~/sh-ext-accept6/`，只装发布轮子，两个示例脚本（文本委派→重启恢复；录音三轮→委派→播报→打断/挂断）。

## 3. 改写后的任务书（给 SDK 侧自己用）

> 做一个"深"的版本，不是"大"的版本。
>
> **目标**：AIPhone 的文字和语音进同一个逻辑主会话；日常对话直接答；模型判断需要时，用 SDK 内置的委派命令建一个关联任务，任务走现有 HTN/TaskGraph；结果回到原会话，在线就播报，离线就留着。
>
> **先证伪再写**：开工前 2 天只做 6 个真线路试验（工具目录回显、函数调用闭环、三种后台注入、通话中文字、打断后记忆、路由标注集）。每个试验有判据；不过的那条能力不写进合同，写进"限制"。
>
> **三个制品分开发**：编排 SDK（会话+委派+inbox，可独立验收 A01–A05、A14、A15）→ Service SDK 0.3.13（工具循环+注入+改钉版，A06、A07、A12）→ 联合桥（A08–A11、A13）。
>
> **外部裁判**：上游 `session.updated` 回显、`function_call_arguments.done` 回执、冻结的路由题集与阈值、对方测试套件、故障注入对账、仓库外空环境装轮子、Opus 独立评审。
>
> **不做**：跨进程隔离方案；"转写→文本→TTS"静默替代；为了"都在 SDK"把手机音频代码塞进核心库；多层委派；多在途。

## 4. 分阶段计划

### 阶段 0：可行性门（约 2 天，不写产品代码）

| 编号 | 试验 | 做法 | 通过判据 | 不通过时 |
|---|---|---|---|---|
| S0-1 | 依赖组合 | 已做 | 对方全套测试通过 | — |
| S0-2 | 工具目录与函数调用闭环 | 在探针里给 `session.update` 加 `tools`（一个 `delegate_task` 假工具），放录音"帮我整理这周照片做相册" | `session.updated` 回显 tools；收到 `function_call_arguments.done` 带 `call_id`；回 `function_call_output` + `response.create` 后有音频续答 | 若回显没有 tools：中继剥了字段，出 TokenSeller 配套需求。若模型不调：改提示词再试两次，仍不调则记为模型限制 |
| S0-3 | 后台结果注入（三条路，按序试） | (a) `conversation.item.create` 带 `message/input_text` + `response.create`；(b) 会话中第二次 `session.update` 改 `instructions` + `response.create`；(c) 关闭连接，用含已提交上下文与待播结果的 `instructions` 重开 + `response.create` | 用户不说话，模型主动把结果说出来；只说一次；之后对话还能接上 | (a)(b) 都不过就用 (c)，并把"结果播报会重建连接，上下文按 SDK 规则压缩"写成公开行为 |
| S0-4 | 通话中文字输入 | 同 (a) | 模型用语音回答文字 | 首版规则：通话中文字排队，挂断后文本引擎处理 |
| S0-5 | 打断后的记忆 | 让模型说 30 秒，2 秒时 `response.cancel`，再问"你刚才说到哪" | 记录模型认为说到哪 | 无通过/不通过，只产出"限制说明" |
| S0-6 | 路由标注集 | 60 题四类，两人标，DeepSeek 跑三次 | 误委派 ≤5%，漏委派 ≤10%（取最差一次） | 改提示词最多两轮；仍不过则阈值放宽须用户签字 |

产出：`阶段0-可行性门-记录.md`（每个试验的原始事件日志摘要，不含密钥与音频），和一页"能力与限制表"，这张表就是后面合同的边界。

### 阶段 1：编排 SDK——文本主会话与委派（约 5 天）

改动范围：`agent_orchestrator/host/`（新 `session.py`、`delegation.py`、`inbox.py`），`chat.py` 加控制命令通道，`host.py` 暴露公开入口，`docs/orchestration-host.md` 新增 §2d。

1. **聊天池 v2**：新池编号带 `-chat-v2-`，带配置版本；v1 池、提示词、工具表一字不改。旧会话继续在 v1 上聊；新策略只对 v2 会话开。
2. **会话实体**：`session_open/send/snapshot/history/events/respond/interrupt/close`。持久台账在数据目录 `sessions/`，事件带 `schema_version`、`event_id`、`session_id`、`seq`。历史只认已提交回合。
3. **委派控制命令**：不是 DomainTool。它是聊天池里 SDK 注入的内置命令：模型只给目标、成功条件、资料引用、原因；SDK 注入 principal/session_id/turn_id/call_id，过 `door()`，用 `create_mission` 建任务，幂等键 = 会话号 + 已提交输入回合号 + 目标规范化哈希。同键异规范拒；新回合同目标可建新任务；一在途即 `busy`。
4. **关联与 inbox**：`delegation ↔ mission` 关联表；mission 终态事件写 inbox（outbox 式，至少一次、幂等应用）；下一回合把结果作为"资料"注入历史，不作为指令；默认不派生新任务。
5. **预算**：会话账本只引用聊天台账与任务账，不重复结算；给结果回传留固定额度；耗尽时无模型也能读任务事实。
6. **取消与审批**：`task_cancel` 走现有 `cancel`；`session_respond` 走现有 `decide`/`answer_planning_question`，绑定 request_id 与版本；创建中取消先持久化、创建成功后收敛。
7. **测试**：幂等矩阵 4 格；故障注入 4 个持久点；一局 DeepSeek 真实模型（A02）；相关测试只跑改动文件对应的（项目规则）。
8. **发版**：opt.217 起；部署清单重生成；验收门；回执。

### 阶段 2：Service SDK 0.3.13——Realtime 工具循环（约 3 天，可与阶段 1 并行，不同仓库）

1. `RealtimeOpenRequest` 加 `tools`（schema 目录，字节上限按 `tool_payload_bytes`）；Qwen 适配器 `session_update` 下发；`SessionReady` 带回显结果，回显缺 tools 即报 `unsupported`。
2. `ManagedRealtimeSession` 工具循环：只接 `function_call_arguments.done`（完整参数），delta 只记日志；调用交给注入的 `ToolDispatcher` 协议；结果 ACK 用已有 `submit_tool_result` + `followup_response`；旧 generation 的调用拒绝；重连重放去重。
3. 上下文注入入口 `inject_context()`：实现 S0-3 通过的那条路；不通过的路不留接口。
4. 播放回执：`local_channel` 已有 output ack，补"实际播放位置"字段与"过期帧不播"。
5. 改钉版：Harness 钉私有 opt 轮子（`==` + 哈希），BOM 更新，`public-api.json` 更新，OpenAI 适配器 conformance fixture 不动。
6. 版本 0.3.13，私有分发，回执含 SHA-256。

### 阶段 3：联合桥（约 4 天）

位置：编排 SDK 可选 extra `[realtime]`，模块 `agent_orchestrator/host/realtime_bridge.py`。理由：逻辑主会话的权威只能有一个；Service SDK 保持 provider 中立，不反向依赖编排。

1. `realtime_attach/detach`：绑定 session，装配工具目录（委派/查询/取消 + 宿主只读工具 schema），返回 binding_id、generation、协商结果。
2. 工具调用 → 阶段 1 的控制命令，同一套准入、幂等、预算。
3. 播报调度：inbox 新结果 → 用户在说话则延后；有输出时排队；错误/审批与进度分级；被打断保留未播内容，不自动重播。
4. 重连：业务 session_id 不变，generation 递增；退避、次数、费用上限；恢复时按 S0-3 的方式重建上下文，不重放音频。
5. 挂断/关 App：释放音频与网络，会话与任务保留。

### 阶段 4：验证与发版（约 3 天）

1. A01–A15 逐项证据，目录 `.local-test-evidence/<日期>/unified-session/`，每项标"通过 / 阻断 / 未执行"。
2. 仓库外 `~/sh-ext-accept6/` 两个示例；Lima `sh-linux`（ARM64，Python 3.13）跑一遍安装与文本示例。
3. Opus 5.5 子代理独立评审，只报阻断级。
4. 兼容表、迁移/回退说明、AIPhone 接入指南、TokenSeller 配套需求（若有）。
5. 回执：两个轮子的版本与 SHA-256、源码提交、协议版本。

### 时间与并行

阶段 0 两天 → 阶段 1 与阶段 2 并行（不同仓库，不同车道）→ 阶段 3 → 阶段 4。总计约 3 周。
阶段 1 核心代码由主代理写；阶段 2 可派一个 Opus 5.5 车道；评审另派。

## 5. 决策点

子代理可裁决（不打扰用户）：桥放哪个包、会话台账格式、幂等键的规范化规则、播报优先级细则、接口命名。

必须用户定：
1. 若 S0-2 发现中继剥掉 `tools`，TokenSeller 侧要改；谁改、何时上线。
2. 若 S0-3 三条路都不过，后台结果只能"重建连接"或退到"转写→文本→TTS"。两者听感不同，要用户选。
3. 真线路试验要消耗 chinzy 额度；大约 30～50 次短会话。
4. 本计划与现有主线的先后。
5. 路由阈值不过时是否放宽。

## 6. 不做的事

- 跨进程隔离方案（已无必要）。
- 多层委派、多在途（首版一层一在途）。
- 把手机麦克风/扬声器代码放进 SDK。
- 用旧的三轮记录当本次验收。
- 静默切换到"转写→文本→TTS"。
