## 0. 手机隔离区修复

问题：老内核（4.14）上，一次同时开"用户隔离"和"进程隔离"会报错，隔离区建不起来。分两步开能成功。

- 改启动方式：先开用户隔离，再开其余隔离。
- 安全规矩不变：普通用户、不提权、断网、隔开文件和宿主通信、不挂宿主 /proc、隔离区里不能再开用户隔离、清空特权、资源上限。
- Ubuntu 新版也必须能用（它对谁能开用户隔离有限制）。
- 启动检查照跑全套，不走捷径，不伪造结果。
- 再核老内核上的防误杀：没有 pidfd 时的身份核对与退回办法；进程身份、开机号、启动时刻。
- 再核收尾：超时、取消、脱离进程树的后台进程、宿主被杀、重启后认领。
- 给 AIPhone 一条在手机上直接跑的检查命令。
- 发新版本，不覆盖 opt.200。交回：版本、提交、安装包与清单哈希、支持前提、已知限制。
- 未验：手机实测、三个手机工具接入、语音并行——归 AIPhone。

## 1. 中途决定动作

例子：搜照片 → 看结果决定归档哪几张 → 等批准 → 执行 → 核对 → 接着做 → 回答。
例子：看桌面 → 点击 → 再看 → 决定下一步。

- 模型能看到当前可用的动作：名字、参数说明、风险。
- 模型只能"提议"，真正执行由 SDK 调应用的连接器。
- 提议先过检查：参数格式、应用自己的预检（路径、权限、设备能力）。预检可以整理参数，但只能在批准之前。
- 冻结后再批准：目标、完整参数、引用的产物、版本都钉死。参数变了就要重批。
- 越出原来的目标：交审阅员判断，需要的话进入"改要求"确认，不能自己批自己。
- 自动模式代批；"总要人批"的动作照样等人。
- 等批准时不占模型、不花 token；重启后接着等。
- 执行结果（成功、失败、被拒）交回原步骤，任务接着往下做。
- 公开入口：读提议、读审批详情、提交决定。
- 身份只认 SDK 和宿主给的，模型参数里写的身份不算数。

## 2. 动作兜底

- 每个动作一个持久编号，串起提议、审批、每次执行、回执、对账。
- 重复提交不重复执行；回应丢了能查回原结果。
- 结果不明时不自动重做（沿用现有规则：只有权威且封口的"确实没生效"才换新键重做）。
- 新增：不能去重的动作（如桌面点击）只发一次；结果不明就停下，等人判断。
- 写操作次数、尝试次数上限：跨子任务、跨重启、跨换模型累计，不能绕过。
- 取消：没发出去的不发；已经发出去的继续对账，照实显示。

## 3. 接 Luna/Sol

- 先查 MEETRAN 线路：有哪些模型、工具调用、流式、用量字段的写法。
- 通用 OpenAI 协议模型接入，不再只认 DeepSeek。
- 用量：发请求前保守估算（宁多不少）；回来后按实际用量记账；拿不到就标"未知"，不当成零。
- 换模型：首选失败换备用；同一任务后面沿用备用；新任务回到首选；不叠加重试；已经输出过文字的不整轮重放。
- 事件里写明：请求的模型、实际用的模型、换模型原因、用量。
- 图片描述：接多模态模型，管住用量、取消和图片权限。

## 4. 快速聊天（轻量模式）

- 简单问答、短工具任务不走完整规划，照样有权限、预算、记录、取消。
- 必须调工具却空回答：有限次纠正。
- 实测三种情况的首字时间、总时间、调用次数、用量：普通问答、一次查询、一次要审批的动作。

## 5. 逐字输出

- 应用能订阅正在生成的文字片段：带任务、步骤、序号、结束和出错信号。
- 审阅否决或重写时，旧版作废，给出终稿。
- 写清断线重连规则；终稿能持久读取，不会把两次生成拼在一起。
- 事件格式定版本；写清分页、保留期、去重规则。

## 6. 看计划、执行某步、跳过、停止

- 读计划：每步有稳定编号和版本。
- 执行指定步骤、跳过没执行的步骤、停止任务。
- 跳过不算成功，不能跳过必需的动作；跳过后重新评估剩下的目标。
- 重复点击不重复执行；过期的决定被拒；停止后旧批准不能再唤醒动作；重启后等待点还在。

## 7. 子 Agent、多成员、完整结果

- 子 Agent：工具白名单、层数和轮次上限、共用父任务预算；权限只缩不放。批准父动作不等于批准子 Agent 的动作。
- 多成员：一人一个宿主的做法写清，并演示两人互相看不到、动不了对方的任务。
- 资料和技能注入：带来源和版本。
- 外部内容（网页、NAS、MCP）当作不可信，不能变成授权。
- 工具和技能更新：旧任务用旧集合，新任务用新集合；在途的待批和未结清动作不丢。
- 超过 32 KB 的工具结果能完整读取；大文件给受控的读取引用。

## 8. Linux x86_64 / NixOS

- 本机虚拟机模拟 x86_64 + Python 3.12，跑代码执行、文件核对、pytest 核对、超时清理、越界拒绝。
- 写清 NixOS 要点：bwrap 位置、/nix/store 只读、需要的内核设置。
- 缺依赖时给清楚原因，不悄悄关掉隔离。
