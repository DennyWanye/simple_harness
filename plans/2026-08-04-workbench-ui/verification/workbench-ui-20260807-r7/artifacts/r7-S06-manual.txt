## 步骤5 【判定项④⑤⑥】operations tab 的 cancel / rollback / uninstall 入口
### 现状（实测）
「操作 (17)」全部是启动时的一方安装（backend log:
`capability_platform_ready … first_party_installs=17 recovered_operations=0`），
每张卡片形态一致：`已完成` / 100% / 安装·已发布 / 最近结果 Published /
Verification Receipt 通过·manifest_and_integrity。
**cancel / rollback / uninstall 三个入口均不可见** ✓（r7-S06-05-operations）

### 根因（源码实证，非猜测）
`backend/deskpet/capabilities/ui_projection.py:234-243`：
```
if cancellable and operation.status == "running":   available_actions.append("cancel")
if retryable and operation.status in {"failed","cancelled"}: … "retry"
if operation.status == "succeeded" and operation.pack_id:
    if rollback_available:  … "rollback"
    if uninstall_available: … "uninstall"
```
17 个操作全是 `succeeded`，且 rollback/uninstall 的 available 标志为假
⇒ 三个入口**在当前数据下结构上不可能出现**。这不是 UI 丢了入口，是没有能让它们
出现的操作对象。

### 按用户裁决「造一个进行中操作再测」的尝试与失败原因
经 SkillStore「市场」真机安装 `algorithmic-art`（点安装 → 二次确认「确认安装」）：
- 安装**成功**：SkillStore「已安装」tab 出现该项且带**「卸载」按钮**
  （r7-S06-installing）
- 但「操作」tab **仍是 17**，未新增任何操作
- 落盘实查：`.testenv/cold-A/skills/algorithmic-art`（**skills 子系统**）；
  `.testenv/cold-A/capabilities/packs` 仍为 **17** 个（**capability pack 子系统**未变）
⇒ **SkillStore 装的是 skill，不是 capability pack**，两者不是同一条链路，
  故装技能无法产生 running 的 capability operation。

### 因此
- 【判定项⑥ uninstall 入口存在】：**PASS（用户裁决）**。在 SkillStore「已安装」中
  确有「卸载」入口（r7-S06-installing 真机截图）。TC 步骤5 字面要求是"切到
  operations tab 逐一核对"，该入口不在 operations tab 内；我未自行判定等价，
  已升级用户。用户 2026-08-08 裁决：**「可以，算入口存在」**——按"入口存在
  不回归"的实质口径判⑥达标。
- 【判定项④ cancel】【判定项⑤ rollback】：**未能构造出前置**（需要一个 running
  的 capability pack 操作 / 一个 rollback_available 为真的已安装 pack）。
  本轮未找到可从 UI 触发 capability pack 安装的入口。
