# 编程测评：NL2Repo-Bench 简单档候选题（2026-10-08 夜，待用户过目）

## 测评是什么

- NL2Repo-Bench（ICML 2026）：只给一份自然语言需求文档和一个空工作区，要求从零写出一个能安装的 Python 库；用原项目自己的 pytest 测试打分（平均测试通过率；全过记一次 Pass@1）。
- 共 104 题，按原项目代码量分三档：简单（≤1500 行）26 题、中等 46 题、困难 32 题。最强系统平均通过率不到 40%。
- 官方仓库已下载到 `.local-test-evidence/2026-10-08/nl2repo/`（约 12MB）。**仓库没有声明许可证**：只做内部测评，不外传题目。
- 论文和仓库都没有逐题标难度；下面的"简单档"是我按原项目源码规模估的（GitHub 统计的 Python 字节数含测试，源码约占一半）。

## 候选题（按难度从低到高）

| 题目 | 要写的东西 | 原项目规模（估） | 隐藏测试数 | 运行时依赖 | 沙箱能不能跑 |
|---|---|---|---|---|---|
| decouple（python-decouple） | 配置读取库：从 .env / .ini / 环境变量读配置，按类型转换（布尔、整数、列表），缺省值与报错 | 源码约 350 行 | 67 | 只用标准库 | 能 |
| retrying | 重试装饰器：按次数/时长停止、固定/随机/指数等待、按异常或返回值决定是否重试 | 源码约 300 行 | 23 | six（沙箱已有） | 能 |
| schedule | 定时任务库：`every(10).minutes.do(job)` 这种链式写法、按日/周/时刻调度、取消与标签 | 源码约 900 行 | 81 | 只用标准库（测试用 unittest.mock） | 能 |
| parse | `format()` 的反向操作：按格式串从文本里取出字段，含类型转换、对齐、日期时间 | 源码约 1000 行（单文件） | 96 | 只用标准库 | 能 |
| docopt-ng | 从帮助文本自动生成命令行参数解析器 | 源码约 1000 行 | 614 | 只用标准库 | 能 |

建议先跑前 3 道（decouple、retrying、schedule），过了再加 parse、docopt-ng。

筛掉的：python-dotenv（命令行测试要求 `pip install -e .` 装出控制台命令，沙箱做不到）、schema（测试要 mock、contextlib2，沙箱没有）、markupsafe（有 C 加速部分）、records（要数据库驱动）。jsonlines（依赖 attrs，沙箱已有）可作备选。

## 怎么接进我们的系统

- 需求文档（`start.md`，3～4 万字符，约 1 万 token）作为任务附带资料交进去；任务目标写"按附带的需求文档从零实现这个库，附 pyproject.toml，能 pip 安装，附自己的测试"。
- 隐藏测试**不交给系统**。任务结束后在系统外取出验收过的代码，装进一次性虚拟环境，跑原项目测试，按论文口径记平均通过率和是否全过。
- 每题一局，开发环境跑（沙箱可用、执行者有 run_tests）；墙钟上限暂定 90 分钟，token 上限沿用单任务 2000 万。

## 开跑前还要你点头的事

1. **下载原项目的测试目录**：隐藏测试放在官方 Docker 镜像里（x86、要 Docker），这台 Mac 没装 Docker。改为从原项目 GitHub 取对应版本的 `tests/`（每个几十 KB 到几百 KB）。需要你同意从这 5 个项目的 GitHub 仓库下载测试文件。
2. **题目选择**：上面 5 道是否合适、先跑几道。
3. **已知风险**：规划器拆多步时可能不给步骤接依赖（后面的步骤看不到前面写的文件），库存流水题在正式版里就卡在这里；修复方案另见 `试用前-步骤依赖缺口方案.md`（夜里写）。多模块的题很可能踩到，建议先修再跑，或者先跑一道看实际情况。
