# 第 4 块：快速聊天（SDK 的轻量运行档）——一页方案

日期：2026-10-21

## 现状

- 任务入口一律走分层规划 + 独立审阅：问一句"你好"也要规划器、审阅员各开一轮，几次模型调用、几十秒。
- SDK 的运行面（`RuntimePlaneService`）有上下文、技能、会话历史动词，没有"建一个 Agent 并对话"的动词。
- 执行池（`RuntimePool`）里就是 BaseAgent 的 ReAct 循环：建 Agent → 交输入 → 循环调模型与工具 → 提交结果；工具经同一个网关（身份、许可、参数、预算）。

## 做法

宿主新增聊天入口，直接用执行池跑一个 Agent 的一回合，不进任务编排：

```python
reply = await host.chat({
    "session_id": "chat-1",         # 同一会话续聊：同一个 Agent，历史在 SDK 执行库里
    "text": "今天家里哪台设备没电了？",
    "idempotency_key": "chat-1-turn-7",
    "tools": ["device_status"],     # 可选：只给这几个只读工具；默认给全部注册的只读工具
    "require_tool": False,          # 可选：必须调工具；首轮空回答时提醒一次再问
    "max_tool_calls": 8,            # 可选
})
# reply: {"text", "turn_id", "agent_id", "tool_calls", "usage": {...}, "model", "nudged": bool,
#         "first_output_ms", "total_ms"}
```

| 步 | 做什么 |
|---|---|
| 身份 | Agent 的创建者是宿主的主体（`control_caller`），模型输入里的身份不算数 |
| 池 | 默认运行档（不开思考）；一次聊天的模型调用上限、工具上限、时限由 `HostSettings` 的聊天参数给（默认 8 次模型调用、8 次工具、180 秒） |
| 工具 | 只有注册的只读 `DomainTool`（加工作区读写、列目录：每个会话一个独立工作区）；有副作用的操作不在聊天里做，让模型回答"这要建任务"，宿主给出 `suggest_mission` 字段供应用一键建任务 |
| 预算 | 每回合在全局月账上预留（池的输入上限 + 输出上限），回合结束按模型报告的真实用量结清；月配额用完直接拒绝 |
| 纠正 | `require_tool=True` 而模型首轮既没调工具也没正文：同一回合里再提醒一次（"请先用工具"），仍不调就如实返回 `tool_not_used` |
| 取消 | `host.chat_cancel(session_id)`：取消在跑的回合，已发出的工具调用照旧结算 |
| 记录 | SDK 执行库里有完整的模型调用与工具记录（`agent_session_history_read` 动词可读）；宿主另记 `chat-turns.jsonl`（回合、用量、模型、耗时），`host.chat_history(session_id)` 读取 |
| 性能 | 返回 `first_output_ms`（第一段用户可见文字到达时间，第 5 块接逐字流后才有）与 `total_ms`，验收矩阵 C01 用它实测 |

## 不做

- 不在聊天里做审阅：简单交互的质量由模型自己负责；需要把关的事走任务。
- 不做任意多轮记忆：会话历史只在 SDK 执行库里，应用自己保存 UI 历史。

## 验收（C01）

- 普通问答：一次模型调用、无工具，返回正文与用量。
- 一次只读查询：模型调一次 DomainTool，回执进 SDK 记录。
- 必须调工具却首轮空回答：提醒一次后调了工具；仍不调时返回 `tool_not_used`。
- 月配额用完：拒绝并写明原因。
- 真实模型：Sol 上问答一次、查询一次，记录首输出/总耗时/调用数/用量。
