# 仓库外真实模型一局（发版轮子 opt.227，INT-01，2026-11-02）

目的：AgentOS 补充合同 v1.1 第 6 节 INT-01——真实模型主会话 → A / B 并行 → 授权内续办自动委派 C → 宿主验收器按真实产物登记 → 完成 Goal；全程只用发版轮子与公开接口。

## 环境

- 目录 `~/sh-ext-accept7/`，干净虚拟环境（Python 3.12），`pip install --force-reinstall --no-deps` 换成 opt.227 轮子（SHA-256 `a4f7720b…1584a3f`），依赖沿用。
- 模型：DeepSeek（`.env` 的 `DEEPSEEKER_*`，中继 chunfengapi；`run.py` 注入环境变量并在日志里遮掉密钥）。
- 脚本：`goal_chain_game.py`（主局）与 `goal_chain_finish.py`（续收口）；两份与全部日志归档在 `.local-test-evidence/2026-11-02/ext-accept-opt227/`，并复制进 SDK `examples/orchestration-host/`。
- 宿主侧替身：续办策略先 `hold("await_host_release")`，宿主放行后 `enqueue(controls=["delegate_task"])`；授权端口对所有动作（含 `continue_within_goal`）允许并记录请求；验收器按文件名找产物、读正文、核长度与关键词（机械规则）。

## 两处脚本缺陷（不是 SDK 的）

1. 验收器找产物用了 `logical_path`，任务快照里的键是 `path`（收件箱通知才叫 `logical_path`），第一轮三条 fail 因此而来；改后找到。顺带证明了记录接替：fail → pass，旧记录保留。
2. 主局没等 C 的结果被消费就收口；C 又是主会话自己委派的，不走自动汇总，要用户下一句消费。续收口脚本补了追问。

## 结论

INT-01 走通：hold → 可信重评 → 授权内续办自动委派 C（无人工补发下一步、无伪造审阅）→ 每条必需条件对照真实产物哈希登记 → `succeeded` 绑记录集 → 重开保留。线路慢让一局用了约 32 分钟（11-01 同类任务 6 分钟）。
