# 阶段 8 偏差单：后端不可达的产品代码（8K，新增切片）

日期：2026-10-17。依据：计划 8.4（vulture 扫未引用符号，确认后删）、原则 9、CLAUDE.md"旧路径直接删"、阶段8-偏差单-拆分转出口与重复组.md 第四节裁决（只剩专测它本身的测试在用的才算死代码）。

## 一、怎么发现的

8C 用 vulture 加"按词边界搜名字"判死代码。按词搜会被同名的字段、服务槽位名、注释挡住。这次改成按真实导入算可达性：

- 工具：`scripts/code_quality/backend_reachability.py`（只读分析）。
- 入口：`backend/main.py`（Tauri 只启动它）。
- 边：顶层导入、函数内导入、TYPE_CHECKING 导入、点分字符串常量、同包短名字符串（`deskpet/tools/__init__.py` 按短名清单加载工具模块那种）、包的父子关系。
- 另算根：构建清单、打包配置（.spec）、Tauri、JSON/TOML 等资源文件里按路径或点分名提到的模块。
- backend/scripts 下的脚本是各自的入口，不算死代码，不在本单范围。

结果：后端 1001 个模块，890 个可达。不可达的非脚本产品模块 61 个，约 16400 行（清单见第四节）。

## 二、典型例子（核对过）

1. 旧主循环：`host/agent_factory.py`（构造 `AgentLoop` 的唯一地方）只被测试导入。生产里 `agent.agent_loop` 只被导入事件类型（ErrorEvent、FinalEvent、PipelineEvent 等）。SDK 有自己的 ReAct 循环（`simple_harness/runtime/drivers/react_loop.py`），不导入后端。所以后端 `AgentLoop` 类和 `agent/agent_loop_domains/`（约 5300 行）在生产里不跑。ARCHITECTURE/AgentLoop.md 第 10 行说它"只是 ReAct Driver 内部的引擎"，与代码不符。
2. 服务槽位只读不写：`skill_matcher`、`preference_memory` 等服务名在 `context.py` 声明，`host/startup_background.py`、`host/control_sessions.py` 里有 `service_context.get(...)` 读取分支，但没有任何地方登记，读到的恒为 None，分支走不到。
3. 退役子系统残留：`deskpet/memory/analysis_proposal.py`、`evidence_authority.py`（认知记忆 SDK 2026-09-10 已移除，里面还导入 SDK 里早已不存在的名字）；`tools/memory_tools.py` 文档串自称"退役记忆子系统的兼容处理"。
4. 兼容转出模块：`deskpet/agent/task_work_context.py`、`deskpet/permissions/task_grants.py`、`workflows/trace/redaction.py` 文档串写明"为搬走的契约保留的兼容出口"。

## 三、做法（请裁决）

分三层，每层单独提交，标为行为变更（删除），阶段末交独立核验签字：

1. **整模块**：删第四节里标"删"的模块。只被测试引用的，按 8C-3 裁决处理测试：专测这些模块的测试文件、测试函数一起删；混测的测试只删引用死模块的测试函数，删前读测试体确认测的就是死代码。
2. **整模块删掉后才变死的类与函数**：重跑 vulture 与本工具，逐个核对后删。已知最大的一处是 `AgentLoop` 类与 `agent/agent_loop_domains/` 的 mixin；生产在用的事件类型挪到一个小模块（`agent/agent_events.py`），导入方改过去，不留转出口。
3. **只读不写的服务槽位**：`context.py` 里没人登记的槽位删掉，读取分支一起删（同 F-5 的做法）。

不删（写原因）：
- `deskpet/capabilities/templates/python-json-tool/main.py`：已发布的能力包模板，按约束不动。
- `backend/memory/migrator.py`：禁区。
- `deskpet/migrations/__init__.py`：迁移资源目录的包标记，打包配置按包取资源。
- `deskpet/product_state/downgrade.py`：根目录脚本 `scripts/host_control_downgrade.py` 在用的降级工具。

疑问（请一并裁决）：清单里有几组是"做过、但从没接进产品"的功能，而不是"被取代的旧路径"。用户 2026-09-27 定过"做好的功能都开启，含 SDK 写好没接进产品的"。逐组看：

- 回答质量门（companion/response_quality.py）：只被已不跑的旧主循环 final_gates 读。
- 代理团队与任务图工具（agent/team/*、tools/task_graph_tools.py、agent/task_graph.py、task_kinds.py）：已由 SDK 编排（TaskGraph）取代。
- 代码模式（deskpet/code_mode/*）：ARCHITECTURE/AgentLoop.md 写明"当前没有 Code/普通模式之分"。
- 技能嵌入匹配（skills/skill_matcher.py）、偏好记忆（agent/preference_memory.py）：依赖已移除的向量与记忆能力。
建议：这些都按"被取代的旧路径"删；它们的设计若以后还要，从 git 历史取回重做。
