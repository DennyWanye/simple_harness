## 结论与合同清单

**要让 A08～A11 全过，须同时修通文字 Provider 请求、真实身份／控制错误链路及后继恢复，
再验原业务目标与结果实播；单改 Service 的空 response_id 分支不够。0.3.18 已覆盖的
已确认 user 缺键／空串／null 合同保持有效，当前不能把两个未知角色 item 和 28 次控制路径
终止统称旧缺陷复发。Service 应补齐或明确下列合同；文字侧拒绝须由 Host SDK 的 Provider
适配层与中继／上游共同定位；验收驱动须补控制帧诊断、活跃任务打断断言及跨 binding 汇总。
现有证据不足以给任一端包揽归责，第八次 G2／FAIL 与 Host opt.217 状态保持。**

Service SDK 所需合同（修复条件与待诊断项分开，均不建议全局吞帧或填造 ID）：

1. **身份关联合同**：同代 user 输入／上下文 ACK 的服务端别名及嵌套 item 身份须可完整关联，若两个现场 item 被证实为 user 登记漏项则修该路径，若实为助手输出则要求线路补齐 response_id。
2. **用户附带事件合同**：继续按已确认 user 处理各 response 事件族的缺键／空串／null，保持助手、未知及跨代身份拒绝，并新增现场真实顺序反例而不是重做已绿旧合同。
3. **控制帧合同**：明确并验证 `tokenseller.error` 的 code／retryable／fatal／message_class／related_event_id 等合同，区分合法的终止通知与控制帧校验失败，并以脱敏原因暴露给调用方。
4. **失败诊断合同**：在 adapter 之前的控制路径及所有终止出口关联首个致错事件、连接与字段校验原因，避免只留下形状指纹和笼统 protocol_error。
5. **恢复合同**：重连与同号重绑后的 ACK、历史回灌、资料来源隔离及第一条新用户转写必须连续可用，同时保持零自动输入音频重放、无重复委派／播报及新进程恢复语义。

以上 1、3～5 既含应完善的可观测性和验收合同，也含待证据确认的实现修复；不代表已经
定位五个 Service 源码缺陷。文字 `tool_parse` 不属于这五条 Qwen／Realtime 合同；应先在
`simple_harness/providers/openai_compatible.py` 与 `agents/execution.py` 保留安全的 HTTP
状态、失败阶段、Provider 错误分类与关联号，再据实际拒绝原因修改请求或线路。
任务层当前 FAILED 是耗尽失败后的事实收口，不应靠改成 COMPLETED 或删除失败断言修过。
E5 的原 A08 规划上限／业务目标也未因本轮更早失败而关闭。
