## 两项可复现问题与最小修复

### R1：路径断言未规范化（P2）

包内 `tests/test_v121_readiness_fixes.py:31`：

```python
self.assertEqual(physical_test_path(alias, 'test_a.py::test_a'), real / 'test_a.py')
```

macOS 临时目录可使用 `/var` 别名，函数正确返回 `/private/var` 物理路径，但断言期待值仍为别名。改为：

```python
self.assertEqual(physical_test_path(alias, 'test_a.py::test_a'), (real / 'test_a.py').resolve())
```

不要修改工具使其返回未规范化路径，也不要跳过测试。

### R2：临时 venv 的复制解释器无法加载动态库（P2）

包内 `tests/test_v121_readiness_fixes.py:206` 使用 `venv.EnvBuilder(with_pip=False)`，默认复制解释器。在当前 uv 管理的 macOS Python 3.13.13 上，该临时 Python 因找不到 `@rpath/libpython3.13.dylib` 以 -6 退出；尚未进入补丁 CLI。

本机已验证的最小修复：

```python
venv.EnvBuilder(with_pip=False, symlinks=True).create(candidate/'.venv')
```

若支持其他平台，可按平台选择 venv 创建方式，并测试解释器能正常启动；不要改为跳过 CLI 或伪造运行结果。

以上两行仅在 ignored `test-portability-check/` 副本中修改，业务工具字节未改。该副本随后 90/90 通过。正式交付需把修复写入新包、重新生成 manifest 和 ZIP hash，并重跑原包测试。

## 对计划修订的评价

1. **接受状态纠正。** V1.2 handoff 将“缺行为证明”直接判为 `NON_EQUIVALENT_H1H_FIX_REQUIRED` 过强。V1.2.1 改为 `BLOCKED_NOT_PROVEN` / decision=null 更准确。名称或内部类型不同不单独构成语义缺陷，具体违例需关联 C 编号及证据。
2. **接受新增目标分类。** 11 项 `TASKGRAPH_NEW_TARGET/PLANNED_ABSENT` 是后续实施目标，不要求为了 source-map 完整而提前实现；必要现有/H1 前置来源仍须核对。
3. **接受验证依赖澄清。** C01–C10 micro-tests 用来发现违例，不应先要求 C 已 PASS。业务修复和 candidate 回迁需沿原工作流处理；附件不能自行提供用户授权。

5. **仍需实测。** 本轮只确认 runner 补丁匹配当前代码形状。trigger、真实全迁移、旧数据和进程故障回滚都未由此证明。
