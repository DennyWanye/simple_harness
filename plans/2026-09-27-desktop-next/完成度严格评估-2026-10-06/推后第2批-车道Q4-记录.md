### 1.7 守什么保证

1. SDK 回复不合公开合同时，Host 不转发，报具名协议错。
2. 前端只把合公开合同的数据交给界面。坏消息标协议错，界面保留上次画面。
3. 前后端用同一批 Schema 文件。Host 用的包内文件与仓库源码字节相同。
4. 不合法不变成业务状态：不填 0、不填空列表、不映射成 UNKNOWN。

## 六、偏差单

### 偏差单 Q4-1（编号待定）：没有公开 Schema 的编排消息不在本次范围

- 原计划：HTN §17.2 L856"TS 前端使用同一公开Schema验证"，P9 L1182"前后端共享Schema"。字面是所有编排消息。
- 现状：有公开 Schema 的只有本次覆盖的七个读动词（加两种错误回执）。下面这些没有公开 Schema：
  - `taskgraph.execution_snapshot` / `taskgraph.execution_detail`（执行图主画面、回合详情）；
  - `mission_list` / `mission_get`（Host 自己的任务投影 `projection.project_detail` 等）；
  - `mission_events`、通知、审批等其余控制消息。
- 本车道没给它们造合同。造合同要定字段、上界、谁是权威（执行视图在 SDK，属 Q3 一带；任务投影在 Host），工作量远超"中"。
- 停在这里。请主会话定：补合同（另立条目），还是计划改写为"有公开合同的消息按合同核"。

### 偏差单 Q4-2（编号待定）：Host 核执行图回复用 codec，不直接读 Schema

- U03 条文："DTO 运行时按 schema 校验"。
- 已有裁决：第 2 批 T06（车道 L 记录、`graph/schemas/__init__.py` 说明）定"执行图合同在生产代码里只走 codec 一条路径，codec 与 Schema 一致由 SDK 用例守住"。
- 本次做法：Host 核执行图回复用 SDK 的 codec；核保证回复用 SDK 的 Schema 核对器（`assurance.contracts.validate`）。没有在 Python 里再加第三个核对器。前端没有 codec，直接读 Schema。
- 这与 T06 裁决一致，不是新口径。如主会话认为 Host 也必须直接按执行图 Schema 核，需要扩 SDK 核对器（加 `anyOf`、`contains`），属 SDK 改动，请另定。
