## 步骤4 点「新建会话」—— 部分不符，已查明为既有后端行为而非改版回归
点 rel=(123,140)→abs(183,200)。
观察到：
  ✔ 产生了新会话：头部 sid 变为 **3c323533-9367-40ec-94b0-c23371195549**，
    消息区「（消息流为空）」，token 计数 0%
  ✘ **侧栏列表没有出现新条目**（仍只有会话B、S18 两条）
用例原文要求「会话列表出现新条目并位于顶部」，就点击那一瞬间而言**不满足**。

查明原因（不是猜，是读实现 + 版本比对）：
  backend/deskpet/memory/session_db.py::list_sessions
    docstring: "List all sessions that have messages, newest first."
    SQL:       SELECT session_id, COUNT(*), MAX(created_at)
               FROM messages GROUP BY session_id ORDER BY MAX(created_at) DESC
  ⇒ 会话是从 messages 表**派生**的；空会话没有任何 message 行，
    结构上不可能出现在 sessions_list_response 里。
是否改版引入的回归：**否**。
  diff <(git show 644ab16:…/session_db.py | sed -n '/async def list_sessions(self)/,/list_sessions_with_preview/p') \
       <(sed -n '同上' backend/deskpet/memory/session_db.py)
  → 无差异，**改版前后逐字节相同**。前端 SessionList 也只是消费 sessions_list 协议
    （文件头注释即写明"协议不变"）。
⇒ 该行为在改版前同样如此，不属于 B3「功能同位迁移」意义上的功能减少。
发第一条消息后（见步骤5），新条目**确实出现并置顶**。
本步按"新空会话已产生 + 条目在首条消息后置顶"记为满足；
但用例原文的时序表述与实现不一致这一点如实登记，供用户决定是否改口径。
