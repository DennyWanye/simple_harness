# DeskPet PPT 精美化 — 深度研究 + 事无巨细完善方案

> 版本 v1.0 / 2026-06-19
> 目标:让 deskpet 生成的 .pptx **真正可用(用户拿到能直接用/继续编辑)** 且 **精美(达专业模板水准)**。
> 本文是研究 + 设计文档,**不含代码改动**。研究方法:4 路 codex 子代理深读现状源码 + 多轮联网调研业界开源/商业方案 + 团队已有研究对齐。

---

## 0. 目标定义:什么叫"真正可用 + 精美"(可验收)

把模糊目标拆成可验收的硬指标,后续所有设计对齐于此:

| 维度 | "真正可用"的判据 | "精美"的判据 |
|---|---|---|
| 内容 | 每页信息量适中(要点 ≤6、字数有上限),逻辑连贯 | 文案精炼有层次,标题有信息量 |
| 排版 | 不溢出、不重叠、不空洞,跨页对齐 | 统一网格、留白呼吸、视觉焦点分明 |
| 样式 | 配色和谐、字体正确显示(尤其中文) | 主色克制、字号层级分明、装饰统一 |
| 可编辑 | 文本/图表是原生可编辑对象,不是图片 | 元素分组合理,母版/主题可一键换色 |
| 图表 | 数据正确、原生可编辑 | 去 chart junk、配色随主题、有重点 |
| 配图 | 与内容相关、不重复、版权安全 | 调性统一、构图不切主体 |
| 跨机器 | 在没装特定字体的机器上不崩字 | 字体嵌入/安全字体,显示一致 |
| 完整性 | 有封面/目录/页码/结尾 | 演讲备注、页脚 logo 一致 |

**量化总指标**:借 PPTEval 的 **Content / Design / Coherence** 三维(1–5 分),目标整套 deck 平均 ≥4.0,且无 high-severity 视觉 issue。

## 1. 现状全景诊断(4 份 codex 深读综合)

### 1.1 渲染引擎(scratch 路径)
- 纯 `python-pptx` 手工摆 EMU 坐标;主题 ≤5 套、**全纯色**,无渐变/阴影/色阶。
- 字号靠 `_fit_font_size` **压缩适配**而非 type scale;只有标题/正文两级,层级扁平。
- 坐标硬编码、无统一网格 → 跨页不对齐;bullet/two_column 偏挤,无视觉焦点。
- 装饰原语有(`_add_accent_bar`/`_add_corner_motif`/`_add_icon_badge`/卡片),但图标是占位字符,卡片纯色无层次,各版式各画各的、无统一视觉语言。
- **定性:停留在 2010 年代企业模板水平。**

### 1.2 模板填充引擎(`_apply_template_fill`)— 用户点名的重点
两种形态:标准母版型(按 placeholder type 灌文)/ 设计页型(`_analyze_design_page` 启发式猜标题正文)。**六大结构性短板**:
1. **★不能增删槽**:内容条数 ≠ 模板槽数 → 多了截断丢弃、少了留空洞。无 clone/del。
2. **样式抹平**:`_set_text_keep_style` 只取第一个 run 样式,富文本(混排字号/多色)被压平。
3. **字号估算不准**:`_fit_font_pt` 按字符数估面积,不计真实换行/CJK 全角/字体 metrics。
4. **设计页槽识别靠猜**:字号/位置启发式,遇多列/卡片易错位、把装饰当正文。
5. **无重叠校正**:`_shapes_v_overlap` 几乎没用上。
6. **图文不关联 + layout 模糊匹配**:模板图框不绑 outline 配图;该用图文页却选纯文页。

### 1.3 上游内容 / 数据可视化 / 主题 / 完整性
- outline schema:`{title, outline:[{layout,title,subtitle,bullets[],notes,image/image_prompt,columns,quote,chart,items}]}`;layout 10 种。
- **bullets 仅单级**;**内容密度无硬约束**(易堆 8+ 要点);parse_outline 只容错结构不容错语义。
- **chart 是 python-pptx 原生 `add_chart`、可编辑** ✅(柱/折线/饼);但配色不随主题、数据校验弱、有 chart junk。
- **Theme = 纯 Python 颜色常量,完全不操作 pptx theme part**(不改 clrMap 配色方案、不设 majorFont/minorFont)→ 换主题母版/占位符不联动。
- **字体写死西文族(Arial/Calibri),未设东亚字体槽 `a:ea`,无中文字体保障** → 跨机器字体替换、字重单一。
- notes 渲染侧多丢失;页码不全程一致;toc 不自动生成(需显式给页)。

### 1.4 资产现状
- 引擎仅接 **3 套**内置模板;`resources/PPT_Template/` 下**躺着 30 个 .pptx 未接入、零分类零标注**。

### 1.5 视觉自审
- `ppt_visual_review` 已能 LibreOffice 渲染每页 + vision 打分(score+issues),但**只打分不回改、异常被吞** → 无"审-改"闭环。

## 2. 业界范式调研(开源 + 商业)

| 来源 | 核心方法 | 可借鉴点 |
|---|---|---|
| **PPTAgent**(arXiv 2501.03936) | edit-in-place;参考页聚类成功能类型 + content schema(元素角色 + 字符容量范围);LLM 产编辑动作;**clone/del element 适配内容量**;HTML 中间表示;沙箱执行+自修重试(~97% 成功);PPTEval 三维评估 | clone/del、schema 容量、edit-in-place、自审三维、自修重试 |
| **AutoPresent** | **code-as-intermediate**:LLM 写代码调高级原语(SlidesLib)→ 确定性渲染 | DSL/code 中间层 = 精确可控可复现 |
| **SlideAgent** | 多 agent(planner/designer/**reviewer**)迭代 | 显式 reviewer 闭环 |
| **Beautiful.ai** | **constraint/rule-based smart slides**:模板编码布局*规则*,加减元素自动重平衡 | 自适应模板 > 静态填槽,根治"数≠槽" |
| **Gamma** | card/block + 响应式网格 + **theme token 系统**(palette+type+spacing);Hybrid 配图 | theme = token 系统;图库+AI 混合 |
| **MS Designer** | 生成**多版式候选 + 排序**;关键词建议图标/图片;recolor 到主题 | 多候选+排序;自动 recolor |

**python-pptx 能力边界(关键技术约束)**:
- ✅ 原生 chart(柱/线/饼/散点)、表格 → **PowerPoint 可编辑**;读写文本/字体/色/位置;访问 layout/master。
- ❌ **无 clone slide/shape** → 必须 lxml deep-copy `<p:sp>` XML(社区有方案)。
- ❌ **不支持 SVG** → 图标须转 EMF(矢量,Inkscape/libreoffice)或 PNG(cairosvg,栅格)。
- ❌ **无字体嵌入 API** → 随包发字体或后处理 pptx zip 嵌入子集。
- ❌ **无真实文本度量** → 需 PIL/font metrics 或 LibreOffice 回测。
- ❌ **无 theme 配色/字体方案编辑 API** → 改裸 XML。
> 结论:clone-element / 图标 / 字体嵌入 / theme 编辑 / 真实度量 **都要 lxml 裸 XML**,这是工程量的核心。

## 3. 目标架构:四层全管线

```
┌─ L1 内容层 ───────────────────────────────────────────────┐
│ 需求 → LLM 大纲(密度约束/多级bullet/数据提取/notes) → 规范化 IR │
└───────────────────────────────────────────────────────────┘
            │ Content IR(内容与版式分离)
┌─ L2 选型层 ───────────────────────────────────────────────┐
│ 两级匹配:① 套系(风格/场景)② 页类型(内容类型→模板页) + 多候选 │
└───────────────────────────────────────────────────────────┘
            │ (内容块, 选定模板页, 元素schema)
┌─ L3 填充/排版引擎 ────────────────────────────────────────┐
│ edit-in-place + clone/del 适配数量 + 容量控制 + 真实度量 +   │
│ 富样式保留 + 重叠校正 + 主题token联动 + 图标/配图/chart 注入  │
└───────────────────────────────────────────────────────────┘
            │ .pptx 草稿
┌─ L4 质检闭环 ─────────────────────────────────────────────┐
│ LibreOffice 渲染 → PPTEval 三维打分 → 定向修复 → 再审(N轮)   │
└───────────────────────────────────────────────────────────┘
            │ 终稿 + 字体嵌入 + 完整性(toc/页码/notes)
```

**设计原则:内容 IR 与 layout 分离** → 同一内容可重排进任意风格模板;**离线重、在线轻** → 模板分析离线一次缓存,运行时以确定性规则为主、LLM 点缀(适配桌宠速度)。

## 4. 逐维度详细方案(事无巨细)

### 4.1 内容层(L1):质量是精美的一半
**短板**:无密度约束、bullets 单级、notes 易丢。
**方案**:
- **内容 IR**:定义独立于版式的内容中间表示——每页 = `{intent(封面/要点/对比/数据/引用/流程/总结), title, blocks[], notes, data?}`;block 支持**多级层级**(bullet 子项)。
- **密度约束**(写进 schema + 系统提示):每页要点 ≤6、单点 ≤2 行、标题 ≤N 字;超限自动**拆页**而非堆砌。
- **数据提取**:LLM 从散文/表格抽 `{categories, series[]}` 结构 + 数值校验(series 等长、数字合法),供 chart。
- **notes 必产**:每页生成演讲备注,下游必写入 `notes_slide`。
- **自动 toc/章节**:从 section 结构自动生成目录页,不依赖 LLM 显式给。

### 4.2 模板库 + 风格/场景匹配(L2):解决"丰富 + 按需求选风格"
**短板**:仅 3 套接入、30 套未用、无标注、模糊匹配。
**方案**:
- **接入已有 30 套** + 规划持续扩充(开源商用模板 / 用户自定义导入)。
- **离线建 manifest(一次性,缓存)**:每个模板产出 JSON:
  - 套系级:`{style: 商务/科技/教育/学术/极简/活泼, palette, 适用场景, 语气, 字体方案}`。
  - 页级 schema:每页 `{type, elements:[{id, role(标题/正文/图/数据), kind(text/image/chart), capacity:{min,max字符}, clonable:bool, grid_box}]}`。
  - 分析手段:LibreOffice 渲染 + 视觉模型 + 规则,**离线跑、结果缓存**,运行时零分析开销。
- **两级匹配 + 多候选**:
  - 套系匹配:按主题/场景/语气选**风格套系**(用户"科技路演"→ 科技套系)。
  - 页级匹配:按每块 intent 在套系内选**页类型**;生成 2–3 候选 → 用 PPTEval/规则**排序取优**(借 MS Designer)。

### 4.3 填充 / 排版引擎(L3)— 重点中的重点
按短板优先级,每项给技术要点:
1. **★clone / delete element**(根治数量耦合):manifest 标记可 clone 单元(bullet 行/卡片/列);按内容条数 lxml deep-copy `<p:sp>` 或删除。**这是 ROI 最高的单点改造**。
2. **自适应布局(借 Beautiful.ai)**:可 clone 单元用**布局规则**(等距/等宽/居中)在 clone 后**重平衡**间距与尺寸,而非固定坐标。
3. **提前容量控制取代事后缩字号**:用 schema 的字符容量,在 L1 生成阶段就把内容裁到容量内;字号自适配降级为兜底。
4. **真实文本度量**:用字体 metrics + CJK 全角宽度 + 真实换行算高度(PIL/Pillow 或 LibreOffice 回测),根治中文溢出/乱缩。
5. **富样式完整保留**:`_set_text_keep_style` 改为**逐 run 保留**(保留混排字号/多色/项目符号),不再压平。
6. **重叠校正**:填充后全量 `_shapes_v_overlap` 检测 → 推挤/缩放/换页。
7. **图文/图表/图标注入**:模板元素按 role 绑定 IR 对应内容(image role ← 配图、chart role ← 数据、icon role ← 图标)。
8.(可选)**中间表示**:对复杂模板页,把可编辑元素转结构化表示让 LLM 产编辑动作(借 PPTAgent/AutoPresent),沙箱执行 + 失败自修。

### 4.4 主题系统(L3):从"Python 颜色常量"到"pptx 原生 theme + token"
**短板**:Theme 与母版 theme 脱节,换主题不联动。
**方案**:
- **操作 pptx theme part**(裸 XML):写 `clrMap` 配色方案 + `majorFont/minorFont` 字体方案 → 换主题时母版/占位符/原生 chart **联动变色变字**。
- **设计 token 系统**(借 Gamma):`{palette(主+强调+中性, 含色阶 50–900), type_scale(如 40/28/22/18/14), spacing(8pt 网格), radius, elevation/阴影}`;所有绘制取 token。
- **recolor**:配图/图标/chart 按 token 调色,全 deck 一个调色板。

### 4.5 字体 / CJK(精美命门,deskpet 是中文产品)
**短板**:写死西文族、无东亚字体槽、无中文保障。
**方案**:
- **默认中文字体 = 思源黑体/宋体(Source Han, SIL OFL 免费商用,7–9 字重)** → 用字重做真 type scale(Heavy 大标题 / Regular 正文 / Light 注释)。
- **东亚字体槽**:run 属性同时设 `<a:ea>`(汉字)+ `<a:latin>`(数字/英文)→ 中英混排各用其字体。
- **避头尾(kinsoku)**:文本框正确设**语言标签=中文**,PowerPoint 自动避头尾;必要时手动控断点。
- **字体嵌入子集**:离开用户机器的 deck **后处理嵌入思源子集**(fonttools subset + 改 pptx zip),根治跨机器字体替换。随包发字体作兜底。

### 4.6 配图(L3):Hybrid 来源 + 调性统一
**短板**:机械 prompt、中心裁剪、同步阻塞、无去重。
**方案**(借 Gamma Hybrid):
- **来源路由**:具象/真实(人物/场景/产品)→ **图库 API(Unsplash/Pexels,免费商用、快、无版税)**;抽象/定制/品牌 → **AI 生图**;抽象概念 → **图标**。按 block intent 决策。
- **结构化 prompt**:从"关键词拼接"→"场景/构图/色调/风格"模板 + 全 deck **统一风格锚**。
- **焦点裁剪**:中心裁剪 → 显著性/主体检测裁剪,避免切脸切主体。
- **并发 + 缓存去重**:配图改并发(降多图延迟);按 (query/prompt) 缓存,避免一套 deck 重复同图。

### 4.7 图标(L3):矢量图标系统
**短板**:图标是占位字符。
**方案**:
- **Iconify**(20 万+ 开源图标,一套 deck 固定一套以保持描边一致)→ 按内容关键词映射图标名。
- **转换**:SVG → **EMF**(矢量,质量最好)或 **PNG @2–3x**(安全兜底);转换前 **recolor 到主题 accent**。
- 一致性:统一大小/描边、对齐网格、token 取色;按 (icon,color) 缓存;EMF 在 PPT/LibreOffice 都要测。

### 4.8 数据可视化(L3):保住"原生可编辑"亮点并美化
**现状是亮点**(原生 add_chart 可编辑),只需美化:
- **配色随主题**:chart series 套 token 调色板。
- **去 chart junk**:去网格线、直接标注代替图例、高亮一个关键 series。
- **单指标 → KPI 大数字 callout** 而非图表。
- **类型扩充**:柱/线/饼 + 条形/面积/散点 + 原生表格美化;数据非法时降级为表格/文字。

### 4.9 演示完整性(L4 收尾)
- **notes**:每页写入演讲者备注。
- **自动 toc**:从 section 生成目录页。
- **页码 / 页脚 / logo**:全程一致的页码 + 可选品牌页脚/logo。
- 封面/结尾页统一模板。

### 4.10 质检闭环(L4)— 补上 deskpet 缺失的"审-改"
- 复用 `ppt_visual_review`,**补闭环**:渲染 → **PPTEval 三维(Content/Design/Coherence)+ 视觉 issue 检测** → 按 issue 类型**定向修复**(overflow→控量/clone 拆页、overlap→重排、empty→删槽、contrast→recolor)→ 重渲染再审,**最多 N 轮收敛**。
- **不再吞异常**,自审失败可观测。
- **多候选排序**:L2 的 2–3 候选页用此评分择优。

### 4.11 可编辑性(贯穿)
- 文本/表格/chart 一律**原生对象**(非图片);图标用 EMF(可缩放)优先。
- 形状合理**分组/命名**,方便用户在 PowerPoint 里改。
- 主题联动(4.4)保证用户一键换色。

## 5. 工程:性能 / 速度(桌宠约束)
- **离线重在线轻**:模板分析/schema/字体子集**离线预处理缓存**;运行时确定性规则为主。
- **LLM 调用预算**:L1 大纲(1 次)+ L2 选型(轻量/规则)+ L4 自审(限 N 轮);避免 PPTAgent 那种每页多次 vision 调用。
- **并发**:配图/图标生成并发;chart/填充本地同步快。
- **缓存**:图库图、AI 图、图标(按 key)、字体子集、模板 schema 全缓存。
- **流式进度**:`progress_cb` 全程上报(大纲→配图→渲染→自审),桌宠 UI 可见。
- **预算目标**:常规 10–15 页 deck 端到端 < 60–90s(配图为主要变量)。

## 6. 失败降级矩阵(逐环节,deskpet 是单机桌宠,只防手滑级,不加重护栏)
| 环节 | 失败 | 降级 |
|---|---|---|
| LLM 大纲非法 | schema 不合规 | 重试 1 次 → markdown_fallback |
| 模板解析失败 | .pptx 坏 | 换同套系其他模板 → scratch 引擎 |
| 配图(图库/AI) | 超时/失败 | 图库↔AI 互备 → 图标 → 纯文字版式 |
| 图标转换 | EMF 失败 | PNG 兜底 → 省略图标 |
| 字体嵌入 | 子集失败 | 随包字体 → 安全字体 |
| chart 数据非法 | series 不齐 | 降级表格/文字 |
| 自审渲染 | LibreOffice 不可用 | 跳过自审,记录,照常交付 |

## 7. 架构重构(可维护性)
- 现状:`ppt_tools.py` **3838 行单文件**,scratch/模板/配图/自审混杂。
- 目标:拆分为 `content/`(IR+大纲)、`templates/`(manifest+选型)、`fill/`(clone/容量/度量/样式)、`theme/`(token+pptx theme)、`assets/`(配图/图标/字体)、`chart/`、`review/`(质检闭环)模块。
- **向后兼容**:保留 `ppt_create` 签名与 `markdown_fallback`;scratch 引擎降级为兜底路径。

## 8. 评估与真机验收(对齐项目"真机 E2E"纪律)
- **离线评估集**:固定 N 个代表性需求(商务/教育/数据/路演),每次改动跑 → PPTEval 三维**回归**,防"改一处崩一处"。
- **真机 E2E(HARD)**:按 CLAUDE.md 手工测试纪律——windows-mcp 真机生成 → 截图存证 → 肉眼 + 日志判 PASS/FAIL,**不可用脚本回放代替**。
- **可编辑性验收**:生成的 deck 在真实 PowerPoint 打开,确认文本/chart 可编辑、换主题联动。

## 9. 落地路线图(分阶段,按 ROI/依赖)

- **fonttools**(MIT)— 字体子集
- **cairosvg / Inkscape / LibreOffice**(转换)— SVG→PNG/EMF、渲染
