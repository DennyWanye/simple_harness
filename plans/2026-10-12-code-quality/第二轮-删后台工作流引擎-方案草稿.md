# 第二轮：删后台工作流引擎（方案草稿）

日期：2026-10-18。状态：草稿，待用户拍板第 6 节三点。
依据：用户 2026-10-18 决定"删后台老工作流引擎，统一用 SDK 那套"。

## 0. 结论先行

- 两套引擎在生产里**都不开新运行**。后台引擎只剩恢复、排空和查看面板。SDK 引擎在生产里根本没接上执行器。
- 后台引擎登记的 11 个定义，**全部跟着删，一个都不挪**。理由：SDK 已有替代版本，或者没有任何产品入口。
- 后台引擎有一处真依赖：全产品的执行账本（`execution_uow`）挂在它的服务对象上。先把账本独立出来，再删引擎。
- SDK 一行不改，不发 SDK 版本。冻结工具清单不重签。
- 估算 6～7.5 个工作日，要 1 次全量回归授权和 1 次真机点击。

## 3. 方案

### 3.1 每个工作流：挪还是删

| 工作流 | 决定 | 依据 |
|---|---|---|
| deep_research v1～v7 | 删 | SDK 有 v7-sdk1；无入口；0 存量；v7 恢复本来就坏 |
| ppt_pro v1 | 删 | SDK 有 v2；无入口；0 存量 |
| code_complex v1 | 删 | 无入口；0 存量；恢复链导入坏模块 |
| durable_task v1 | 删 | SDK 有官方版；无入口；0 存量 |
| personal_workflow v1 | 删 | SDK 有 personal_v1；唯一调用方 `turn_authority.py` 生产零导入，一起删 |

挪到 SDK 的：0 个。SDK 两份产品定义（`definitions/sdk_v7`、`sdk_v2`）从 `deskpet/workflows/` 挪到 `deskpet/sdk_adapters/product_workflows/`。它们的节点函数本来就在那个包里，定义身份不变。

以后要让深度研究或 PPT 真正持久运行，做法是：在 `production_runtime_factory` 里传 SDK 的 `workflow_runner`，把 `workflow.deep_research`/`workflow.presentation` 加进档案表，再决定模型能不能看见（F-WF-1）。这是新功能，不在本方案。

### 3.2 删完后 `deskpet/workflows/` 只剩

`store/execution_uow.py` 与 `execution_uow_domains/`（删掉只服务引擎的方法，例如 `workflow.py` 域、`inspection.py` 里读 `workflow_runs` 的段）、`store/schema.py`、`store/write_lane.py`、`contracts.py`（只留工具效果类型）、`effects.py`（只留类型，`EffectJournal` 随引擎删）、`harness_delivery.py`。包文档串改成"执行账本与工具效果契约"。

不改包名。改包名会改 `tools/registry.py` 的导入行，而它的哈希钉在 71 条冻结工具清单里。
