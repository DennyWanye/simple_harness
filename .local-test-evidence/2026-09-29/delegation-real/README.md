# 收口第 4 项：委派工具接回——真实模型验证（2026-09-29，隔离环境 ui-full，开发模式控制通道，DeepSeek 经本机日卡转发）

| 轮 | 做了什么 | 结果 |
|---|---|---|
| 1 `run1.*` | 主对话让模型用 `agent` 委派"列出三种排序算法"，不重启 | **通过**：子运行 `delegate-9f34…` 完成，主对话原样转达结论；子运行回答只在工具结果里；4 次模型调用都记账，上下文用量样本只有主对话 3 条 |
| — `run2-workspace-collision.json` | 测试会话名前缀相同 | 自动工作区目录撞名，主对话直接报错（既有问题，另记欠项；之后会话名改为时间戳开头） |
| 2 `run2-before-fix*` | 子运行进行中重启 | **失败**：关应用时取消子运行出错；重启后父运行挂在"结果不明"上，没人判定。修：关应用不取消子运行；委派服务替挂起的父运行写对账结论并唤醒 |
| 2 续 | 再重启一次，让卡住的父运行被唤醒 | 唤醒了但立刻失败：启动恢复名单里没有它，找不到模型绑定。修：加入"卡在委派调用上的等待运行" |
| 3 `run3-auth-conflict*` | 子运行进行中重启 | **失败**：重放委派调用被 Host 授权记录判身份冲突（重启后授权票据重签）。修：从不重放，子运行结束后直接替父运行写"已完成 + 结论" |
| 4 `run4*` | 子运行进行中重启 | 父运行挂起 → 子运行跑完 → 父运行被唤醒并**完成**，但结论没写回会话（主对话恢复展示在挂起时已退出）。修：唤醒后重新挂上恢复展示 |
| 5 `run5*` | 子运行进行中重启 | 重启后子运行的模型调用撞上游 240 秒超时，挂起。修：子运行等待超 2 分钟先对账、再 2 分钟取消。重启到修复版后：先对账、后取消均按设计发生，父运行被唤醒，但此时已过 26 分钟，撞主对话 10 分钟墙钟上限结束（`react_wall_clock_exceeded`） |
| 6 `run6-upstream-down.json` | 短子任务再试 | 原上游不通（请求 850 秒后 503），未进行 |
| — `probe-*` | 用户换了上游：重启转发程序（读新上游地址）与应用（读新密钥）后，短对话 2～8 秒回复 | 线路恢复 |
| — `run6-workspace-collision.json` | 测试会话名撞自动工作区目录（同上既有问题） | 会话名改为随机串开头 |
| 6 `run6-finished-before-restart*` | 新上游上的短子任务 | **正常委派通过**：还没来得及重启父子运行就都完成了，子助手结论原样写回会话 |
| 7 `run7*`（脚本 `restart_round.sh`） | 长子任务（约 3000 字教程），子运行进行中重启 | **通过**：重启时父子运行都在运行中 → 重启后父运行挂起、子运行继续跑完 → 父运行被唤醒并完成 → 三句概括写回主会话 |

脚本：`chat_run.py`（第 1 轮）、`restart_run.py send/watch`（重启轮）。执行库只读打开，主会话记录从副本读取。
