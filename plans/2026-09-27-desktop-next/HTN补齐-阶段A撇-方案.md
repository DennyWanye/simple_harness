## 二、范围

### 1. 执行图可以关 → 删

因为改成建任务时绑定，`taskgraph_enabled` 的 48 处调用不再分三类，统一处理成"分层任务必须已绑定"：
- **单个任务上的判断**：未绑定就具名报错 `TASKGRAPH_NOT_BOUND`（属内部合同错）。探针测得等待期会走到的 9 处，原因随等待期一起消失，也按此处理。
- **全局扫描**（`taskgraph_action_settlement.py:43` 每轮遍历所有任务）：改成"只看已绑定的任务"的过滤，不报错。开发库里保留的旧会话不能打断全局循环。
- **Host 读执行图状态和历史任务页**：未绑定的旧任务按"执行图不可用"如实显示，不报内部错误。
- 两个同名的 `taskgraph_enabled` 合成一个。
- 删 Host 的 `strict_taskgraph` 设置、`_require_strict_taskgraph`、`_enable_required_taskgraphs`（其中按异常文字做的分类一并消失），以及界面上的"正在启用"。
- 删 SDK 的 `taskgraph_requirement.py` 等待机制：`awaits_taskgraph`、`awaiting_taskgraph`、`missions_awaiting_taskgraph`。"授权当前是否有效"现在有两份判断（`current_planning_grant` 与 `_delegation`），只留一份。

### 2. 不走保证通道的旧审阅 → 删

- 删旧根审阅员、`_judge`、自拟组合记录、自签许可、`CRITIC` 模板。审阅结果的解析部分保证通道还在用，保留。
- 删"选不选保证通道"这个开口：`select_profile`，以及建任务时"不选就走普通完成通道"的分类。分层任务一律走保证通道。
- `mission_coverage(assured=False)` 已在 opt.134 删除，不再列入。

**风险表述**（裁决已核实）：删 `CRITIC` 不会让已有执行池或编排服务起不来，执行池身份和模型调用准入身份都不含角色模板。实际影响只有三条：
- 开发库里没跑完、还走旧审阅路径的任务会报错（第 6 步先取消，已覆盖）；
- 新建库的策略版本号会变，无害；
- 部署清单要重新生成，这是发版常规步骤。

### 3. 连带删除

- 旧执行池：`runtime/assembly.py` 的 `native is None` 分支，以及原生平面下仍会创建的旧检索器、旧索引泵。
- 旧 2000 条窗口检索：`simple_harness/agents/memory/retrieval.py` 的 `SessionRetriever`、`_RecallAdapter`、旧 `SessionHistoryTools`。**`simple_harness/agents/arp/retriever.py` 的同名类原生池在用，不动。**
- 测试和评测共用的安装口 `install_hierarchical(planning=...)`。产品只走 `install_hierarchical_deployment`。
- 评测分层臂与强单代理对照臂：`htn_hierarchical`、`htn_executor`、`htn_batch`、`htn_deployment`、`htn_domains`、`htn_single_agent`，以及只为它们服务的其余 `htn_*` 模块（做孤儿扫描确认）、`scripts/acceptance/run_v14_runtime.py`、`prepare_h8_deployment`，连同它们的测试。
- 命令行 `mission create`。
- 两个等待期真实模型探针脚本。
  - 改正删除理由：它们保护的是规划器"先等一等"这个决定，普通真机局不保证模型会这样选。
  - 保护改由"等待生命周期"那组 15 个用例承担：迁到产品同形世界，用脚本化回复钉住，并列入改坏检验名单。

## 三、部署组装：SDK 只收与领域无关的职责，桌面世界留在 Host

新模块 `agent_orchestrator/deployment/`，作为唯一的一份部署组装，**Host 和 SDK 测试都调用它**。

**收进 SDK 的**
1. **通用根初始化**：根类型、任务号前缀由调用方传入。
2. **要求书构造只留一份**，以 Host 的 `root_requirements` 为准。
   - SDK 默认的 `mission_spec_requirements` 和测试世界用的 `root_review.root_requirements` 删除。
   - 只有一条成功条件时，SDK 默认构造的哈希会变，开发期接受。
3. 开工条件：完成映射已确认。
4. **建分层任务的同一事务里**：写保证通道记录、绑定执行图（部署验收不合格当场失败）、做根初始化。规则落在 SDK 的建任务入口。
5. 无损检查策略投影，以及做法计划策略投影。组装对象持有 `MissionControlV1` 和缓存集合。
6. 自动确认内容完成、自动授权规划：Host 只传入"现在是不是自动模式"这一个布尔量。删掉 `decision_loop.auto_grant`。
7. 上述职责都挂在主循环的 `set_between_cycles` 上。
8. **原生执行池**，两块都搬：
   - `native_plane.py` 的拼装：配置行、身份引用、所有者合同、根目录、落盘路径；
   - `runtime_profile.py` 的 `source_runtime_options` 里不涉及本机资源的部分：尺寸档列表、思考池规则、上下文策略、输出上下限、`provider_kind`、目录所有者池的选法。

**留在 Host 的**
- 桌面规划世界：`desktop.*` 类型、层级、工作区工具名，以 `world_factory` 参数传入组装；
- 读权限模式、通知推送与唤醒、Host 构建指纹、设置页；
- 本机资源：DeepSeek 用量计数器与思考提供方的创建、模型权重路径、沙箱执行器。

## 四、字节钉死（第 1 步就加）

**怎么比**：比对的是"真的拼一个执行池到临时目录后，落盘和入库的东西"，不在测试里用抄来的公式重新算摘要。基准值在搬迁前，用当前 Host 代码对同样输入生成，然后写进测试。

**要钉住的内容**
- 执行池配置行的整行（同号不同内容会被拒绝）；
- 上下文身份旁挂文件的全文；
- 准入身份指纹；
- 授权策略号（工具名排序后取摘要）；
- 所有者合同摘要；
- 模型权重引用（含权重指纹）；
- 根目录号；
- 配置修订号；
- 落盘路径名 `.arp-root`、`.skill-runs`；
- 目录所有者池的选法；
- 命令号与回执号格式：`host-native-root`、`host-check-policy:{key}`、`host-auto-planning:`、`host-auto-completion-`；
- 批准来源字串 `HOST_LOSSLESS_AUTO`、`HOST_AUTO_PERMISSION`；
- 要求书哈希（多条成功条件时）。
- 执行图绑定的命令号会随"建任务时绑定"改变，不在钉死之列。

**固定输入要覆盖的变体**：每个尺寸档（小于 524288 时会缩放策略）、思考池与非思考池、所有者池与成员池、有权重与无权重。

**发版前的一次性检查**（不留成测试）：第 1 步发版前，用新版在开发数据目录的**副本**上启动一次，确认执行池起得来，然后停掉。

## 五、测试迁移

### 分诊口径（机械判定）

| 类 | 判定 | 做法 |
|---|---|---|
| 主循环类 | 起 Orchestrator 主循环 | 共用构造器（`production_fixture`、`_assured_loop`、`decision_loop`、`test_h1i_production_entry`、`_assured_fixture`）换芯为产品同形世界 |
| 旧运行时类 | 直接建旧运行时 | 改用原生运行时构造器 |
| 提交层·要改动 | 文件里出现"提交计划 / 建尝试 / 记结果 / 验收 / 结算 / 审阅"任一项 | 不能留在提交层：重写成主循环用例，只补主循环里还没覆盖的断言；否则删除，并写明被哪个用例覆盖 |
| 提交层·可保留 | 只建任务、读写分层存储，不进上面那些环节 | 建任务改为经过产品组装（装好工厂和根，不跑主循环） |
| 脱离任务 | 只测存储、编码、合同校验，不需要任务 | 不经过分层任务，照常保留 |
| 只测旧路 | 只测被删除的路径 | 随删除一起删 |

- 分诊表由子代理逐文件提出，我审定。h1h、h1i 两组测试是执行图原计划 §0.3 的前置门禁证据，分诊表里删其中任何一条都要标为偏离，并写明理由。
- 第 3 步的工作量等分诊表出来后再估一次。

### 防空过

- 改坏检验按"被保护的机制"挑，判据是"迁移后，同一项改坏引起的失败条数不少于迁移前"。迁移前的版本只多跑一次。
- 每个迁移文件里"断言某事不该发生"的用例必须纳入对照。
- "等待生命周期"的 15 个用例列入改坏名单。

### 代表用例

3 条，都在产品同形世界里跑：
1. 整圈：建任务（当场绑定）→ 第一份规划包 → 授权 → 做法审阅 → 执行 → 叶子验收 → 根终审 → 完成；
2. 子目标；
3. 对外操作。

### 只跑必要的测试

不跑全量回归，不做不必要的测试。每步只跑：被改文件对应的测试、迁移批次本身、代表用例、发版脚本自带的钉版测试。
