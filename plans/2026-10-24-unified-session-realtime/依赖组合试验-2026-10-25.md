# 依赖组合试验（2026-10-25）

目的：验证交接文"依赖冲突"一项是代码不兼容，还是只是钉版问题。

## 做法

1. 新建 Python 3.13 虚拟环境（仓库外临时目录）。
2. 先 `--no-deps` 装 Service SDK 0.3.12（从源码 `47f372a` 用 `uv build` 出的 wheel）。
3. 再装编排 SDK 私有 wheel `simple_harness_sdk-0.13.0.dev20260925+opt.216`，加 `httpx`、`websockets`、`prompt-toolkit`、`pytest`、`pytest-asyncio`。
4. 在 Service SDK 仓库里跑它自己的整套测试。

注意：顺序反过来会出事。先装 Service SDK（带依赖）时，它钉的公开 `simple-harness-sdk==0.6.2` 会把 opt.216 整个换掉（同一个分发名），`agent_orchestrator` 随之消失。

## 结果

| 项 | 结果 |
|---|---|
| 两个包同环境导入 | `simple_harness`、`agent_orchestrator`、`simple_harness_service`、`simple_harness_service.realtime` 全部导入成功 |
| Service SDK 测试 | 337 条：335 过，1 条跳过（BOM 溯源），1 条失败 |
| 失败原因 | `test_bom_architecture`：兼容清单硬写 Harness `0.6.2`、执行 schema 6；`test_release_scripts_pass_strict_mypy`：试验环境没装 mypy |

## 结论

Service SDK 0.3.12 的代码在 opt.216 核心上能跑。冲突只在钉版和兼容清单（BOM）。

解法：发 Service SDK 0.3.13，把 Harness 钉到私有 opt 轮子（`==` 精确版本加哈希；PEP 440 不允许带本地版本号的 `>=`），更新 `compatibility-bom.json`。不需要跨进程隔离方案。
