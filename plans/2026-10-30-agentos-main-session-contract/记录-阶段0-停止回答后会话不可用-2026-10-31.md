# 记录：阶段 0 —— 修"点一次停止回答，会话就报废"（AIPhone F1）

日期：2026-10-31 凌晨。做法：先在仓库内复现（红），再改，再绿。不碰编排、不碰池身份、不碰提示词。

## 现象

用户在请求已交给线路、答案没回来时点"停止回答"。之后这个会话任何新输入立刻失败，`react_cost_exceeded`，模型调用 0 次。重启也一样。AIPhone 真机 2026-10-30 报告，本机复现成功。

## 根因（源码核对）

1. 取消让在途那次模型调用的费用记成"不明"（`provider_cancelled_after_handoff`，金额为空）。这符合"可以多算不可以少算"，本身是对的。
2. `host/chat.py` 的 `_given_up` 只在两种情况换执行者：Agent 已关闭，或开着的回合卡在结果不明的调用上。取消后回合已结束、Agent 仍开着，于是继续复用这个 Agent。
3. `simple_harness/runtime/termination.py:625`：只要预算快照里有不明费用，下一次输入在调模型前就按 COST 终止。加预算没用。

## 改法

- `host/chat.py` 的 `_given_up` 返回"为什么不能再用"：`executor_closed` / `provider_result_unknown` / **新增** `unknown_charge_after_cancel`（没有开着的回合、但 `uow.read_provider_budget(run).has_unknown_charge` 为真）。
- 换代时记下原因，回执新增 `executor_replaced_reason`（没换代为 `None`）；`history_reset` 字段不变。
- 旧 Agent 与它的不明费用原样留在执行库里：不清零、不重放。新 Agent 预算干净。
- 不改任务层、不改任何工具说明与提示词、不改并发默认值；池身份不变。
- 文档 §2b 加"用户停止回答"一行。
