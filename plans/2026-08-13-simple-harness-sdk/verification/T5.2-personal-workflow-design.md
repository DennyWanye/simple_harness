# T5.2 Personal Workflow v1 - Design Document

> Created: 2026-08-15
> Status: Phase 1 - Design
> Target: `src/simple_harness/workflows/personal_v1/`

## Overview

**Personal Workflow v1** is a wrapper workflow that delegates execution to a frozen personal workflow interpreter. Unlike `durable_task` (10-node graph with HITL gates and convergence logic), `personal_v1` is a **single-node wrapper** that:

1. Accepts a `PersonalWorkflowSelectionV1` (frozen graph + tool bindings)
2. Delegates to `PersonalWorkflowRuntimePort` for execution
3. Returns outputs mapped from the interpreter's result

**Key Differences from durable_task:**
- **Complexity**: ~700 lines vs ~3920 lines (T5.1)
- **Graph**: 1 node (`execute`) vs 10 nodes
- **Loop budgets**: None (interpreter handles iteration)
- **HITL gates**: None (interpreter handles checkpoints)
- **Port interfaces**: 1 port (`PersonalWorkflowRuntimePort`) vs 5 ports

## Architecture Principles

### 1. Wrapper Pattern

```
┌─────────────────────────────────────┐
│ personal_v1 Workflow (SDK)          │
│                                     │
│  ┌───────────────┐                 │
│  │ execute node  │                 │
│  │ (single step) │                 │
│  └───────┬───────┘                 │
│          │                         │
│          ▼                         │
│  PersonalWorkflowRuntimePort       │
│  (interface only)                  │
└──────────┬──────────────────────────┘
           │
           ▼
┌──────────────────────────────────────┐
│ Product Implementation               │
│ (backend/deskpet/companion/...)      │
│                                      │
│ - Interpreter loop (tool_call nodes)│
│ - Checkpoint/resume logic            │
│ - Effect identity tracking           │
└──────────────────────────────────────┘
```

**SDK Responsibility**: Workflow graph definition, state management, port interface
**Product Responsibility**: Interpreter implementation, execution runtime

### 2. Selection Security Model

`PersonalWorkflowSelectionV1` is a **frozen, cryptographically verified** capability snapshot:

- **selection_id**: Deterministic ID from identity payload (owner/pack/version/graph_hash/query_hash)
- **selection_fingerprint**: Hash of full snapshot (identity + tool_bindings + lease_entries)
- **graph_hash**: SHA-256 of canonical JSON graph
- **tool_bindings**: Frozen `ToolSpec` topology per tool (stable_handler_id, effect_policy_hash, idempotent=True)

**Security Constraints:**
- Only `read_only` or `idempotent_read` tools allowed (enforced by `parse_personal_workflow_v1`)
- Tool bindings must match frozen specs (stable_handler_id + schema_hash)
- Graph must be acyclic (DAG validation)
- Max 32 steps enforced by schema

### 3. Port Interface Design

```python
class PersonalWorkflowRuntimePort(Protocol):
    async def execute(
        self,
        *,
        child_run_id: str,
        selection: PersonalWorkflowSelectionV1,
        inputs: Mapping[str, JsonValue],
        execution_identity: Mapping[str, Any],
    ) -> Mapping[str, JsonValue]:
        """Execute personal workflow and return outputs."""
        ...
```

**Minimal surface area**: Single method, no streaming, no incremental state updates.

### Phase 3: Graph Definition (~100 lines)

**File**: `src/simple_harness/workflows/personal_v1/definition.py` (~100 lines)

Workflow definition:
- `WORKFLOW_NAME = "personal_workflow"`
- `WORKFLOW_VERSION = "v1"`
- `STATE_SCHEMA_VERSION = 1`
- `create_definition()` factory returning `WorkflowDefinition`
- Single node: `NodeDefinition("execute", _execute_handler)`
- Single edge: `Edge("execute", END_NODE)`
- No conditional edges, no loops
- `recursion_limit=4, max_supersteps=2` (minimal)
- `create_initial_state()` helper

Node handler signature:
```python
async def _execute_handler(
    state: WorkflowState, context: WorkflowContext
) -> StatePatch:
    runtime = context.ports.get("personal_workflow_runtime")
    selection = PersonalWorkflowSelectionV1.from_authoritative_mapping(
        state["values"]["personal_workflow_selection"]
    )
    result = await runtime.execute(
        child_run_id=str(state["run_id"]),
        selection=selection,
        inputs=dict(state["values"].get("inputs") or {}),
        execution_identity=context.identity,
    )
    return StatePatch({
        "values": {
            **state.get("values", {}),
            "outputs": dict(result),
            "terminal_status": "success",
        }
    })
```
