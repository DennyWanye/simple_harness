## 2. 两个数据库的迁移号

- 执行库：当前 fresh 描述符 v10（`0010_fresh` = v9 + base_agent DDL）。ARP 在此登记 **v11**：`fresh_descriptor()` = v10 SQL + `execution_additive.sql`；旧 v10 库用显式 `migrate_execution_to_v11`（同 v10 迁移器的备份/校验模式）。`accepted_descriptor_rows` 扩展 `(…, ten, eleven)`。
- 分区库：每 Session 一个 `index.sqlite3`，全新创建，按 `session_partition.sql` schema v2。
- 编排库：本次不加业务 DDL（计划明确）。
- 冒烟核实：计划 `execution_additive.sql` 直接叠在 v10 fresh 描述符上 `executescript` 成功（22 张 `arp_*` 表，外键指向 `base_agent_bindings_v1` / `base_agent_turns_v1` 均存在）；`session_partition.sql` 在空库成功；本机 SQLite 3.53.1，含 `ENABLE_FTS5`。

1. RP-A：`simple_harness/agents/arp/` 包——严格 codec（内置计划 schema 副本）+ 语义规则移植、错误目录、执行库 v11 描述符与迁移、分区库 owner、连接级 `_locked` Store、`NativeCreationService`（creation intent → kernel → 同 UOW 激活）、`ARP_V1_1_1` profile、授权 receipt 记录器。

4. RP-D：close/drain/destroy/purge、Host verbs/events/errors、retention。
5. RP-E：BODY_WIRED 后统一验收；Assurance 接入在其前完成 BW09。
