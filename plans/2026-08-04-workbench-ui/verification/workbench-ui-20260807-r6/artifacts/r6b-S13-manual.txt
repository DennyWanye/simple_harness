# S13 真机道 — 后端未就绪错误态（TC-WB-13，negative-safety）
执行：AI (manual-mcp / cliclick HID)；2026-08-07；relay dev，基线 9a19261
注：本记录晚于 2026-08-07T19:58 的 re-attestation
构造手段（TC 允许的 (b) 分支，原样入账）：正常启动后 `kill -9 <backend pid>`
  精确杀掉 backend（`.venv/bin/python main.py`）。禁止 mock 前端状态——本轮未 mock。
过程记录（含两次手段调整，如实说明）：
  ① 首次 kill 后 supervisor **秒级 respawn**，截图只拍到已恢复态 → 手段不足以观测降级；
  ② 改用 SIGSTOP 冻结 backend：进程 STAT=T 但 TCP 连接未断，前端仍显示「已连接」
     → 冻结不产生断连信号，手段无效；
  ③ 改为持续击杀（每 0.7s 一次，共 60 次）→ **supervisor 耗尽重试彻底放弃**，
     弹出「启动失败」模态（文案 "Backend supervisor gave up after repeated crashes。
     请打开日志目录排查。" + 重试/打开日志目录/退出 三按钮）。这是比 TC 目标更重的失败
     模式，属手段过激，其证据见 r6b-S13-down；
  ④ 最终采用**单次 kill + 0.8s 间隔连拍**，捕获 respawn 窗口内的**瞬时降级态**——
     即 TC 步骤1/3 所指状态。本判定以 ④ 的证据为准。

步骤1 后端不可用时停留聊天视图（r6b-S13-statusbar，单次 kill 后第 2 帧）：
  - ChatView 顶部出现**黄色连接状态条**：「后端启动中，聊天通道等待就绪…」
    —— 明确的未连接/连接中提示，非静默空白 ✓
  - 状态条右侧有**「重试」入口** ✓
步骤3 侧栏底部连接徽章：橙色「● 未连接」——最差态，与 ChatView 状态条**口径一致**，
  无"徽章绿但拒发"的分叉 ✓
步骤4 点击重试入口触发真实重连：
  - ③ 场景下点模态「重试」（屏幕坐标 709,600，经 retina→逻辑换算）→
    backend 进程计数 0 → **1**，真实重启进程 ✓ 无崩溃无白屏
步骤5 恢复后端后：模态消失、状态条消失、徽章回绿「● 已连接」、会话列表 30 项完整
  （r6b-S13-recovered）✓
步骤6 恢复后四视图切换一轮正常，无错误态残留（同 S03 轮转证据）✓
判定：步骤1、3、4、5 全部满足 → S13 PASS
附带发现（非缺陷，环境事实）：supervisor 有重试上限，连续崩溃达阈值后进入
  「启动失败」终态模态并提供重试/日志/退出三出口——降级链路有兜底，不会静默死亡。
