## 缺陷 WBUI-DEF-S08-01：设置页「云端 API key 管理」relay 托管项两侧都不显示
现象：relay 已登录（后端每次启动 relay_provider_ensured id=relay-cloud
  account_ref=… base_url=https://chinzy.com/v1 key_fp=…，聊天 kimi-k3 真实往返正常），
  但设置页 LLM Providers 区显示空态「请添加你的第一个 LLM provider」，
  无 relay 行、无 API Key 掩码、无「重置 key」（r8-S08-rr-04-providers2）。
根因（源码核对，非环境问题）：
  - 前端：`SettingsProviders.tsx:602` — `if (!relayAdapter || RELAY_MANAGED_PROVIDER)
    { setRelayProviders([]); return; }`，而 `relayConfig.ts:34` 的
    `RELAY_MANAGED_PROVIDER = true` ⇒ WI-3 起**主动关闭**前端 relay 虚拟行，
    注释称改由后端 registry 提供真实 `relay-cloud` 行（WI-4 补 readonly 徽章）。
  - 后端：`settings_providers_list_request` 返回 `_reg.list_providers()`
    （main.py:12588），而 `backend/llm/registry.py:122` 的 list_providers 仅返回
    `ad.available()` 的适配器名 —— relay 托管项不在该 registry 列表中。
  ⇒ 前端虚拟行已退役、后端 registry 行未落地，**判定项⑥两侧都不显示**，
    属 WI-3→WI-4 迁移未完成的跨层缺口（r6 挂起未决异常的确切根因）。
影响：设置页无法查看/重置云端 key；不影响聊天链路（provider 由 relay 直供）。

判定：步骤 1、2（①②③④⑤⑦⑧）、3、4、5、6 满足，
  **判定项⑥ 不满足 → 按 oracle「缺任一项即 FAIL」→ S08 FAIL**（用户方案 B）
