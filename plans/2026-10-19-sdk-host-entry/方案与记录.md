# SDK 任务编排宿主入口（方案与实施记录）

- 日期：2026-10-19
- 依据：用户"Python 应用，我期望使用这个 sdk 做编排"；两点决定：这一版只支持 DeepSeek；桌面端后端这一轮一起改用新入口。
- 分支：orch-host（主检出）。

## 一、问题

真机测试证明的是"SDK + 桌面端后端自己写的接线"这个整体。接线约 7350 行在 `backend/deskpet/orchestration/`，其中外部应用也必须有的约 2000 行：建模型连接、选计费器、规划世界、拼装与启动、驱动循环、沙箱探测、建任务门口检查。别的 Python 应用只装 SDK 就没有这些，也没有说明文档。

## 二、方案

1. SDK 加公开包 `agent_orchestrator.host`：
   - `OrchestrationHost`：`open(root, principal=, model=ModelConfig, tokenizer_path=, settings=HostSettings, auto_mode=, publish_dir 在 settings 里, models_dir=, notify=)`；也可注入 `provider= / counter=`（测试替身或别的接法）。
   - 拼装顺序照后端：实例锁 → 部署验收门 → 发布连接器 → 沙箱探测 → 部署策略 → 原生执行池 → 用户任务部署 → Orchestrator → 门面。
   - 操作：建任务（含附资料）、资料三动作、列表／详情／事件／审批、授权规划、回答提问、确认完成要求、改要求、提交操作、取消／接管／裁决、评论、取产物、状态、全局月配额。
   - 驱动：`run_forever`（常驻，含退避、重建、降级）、`run_until_settled`、`run_once`／`drain`。
   - 门口检查与后端一字不差：空目标／空要求、密钥、`pytest:` 要沙箱、`action:` 要连接器、补 `file:` 来源、默认运行档与预算（同幂等键重试沿用原任务的）。
2. 随之进 SDK 的：`host/settings.py`（模型配置、运行参数）、`host/provider.py`（提供方与计数器选择）、`host/instance_lock.py`（跨平台文件锁）、`host/script_runner.py`（沙箱脚本执行器，原 `skill_script_runner.py`）、`host/embedding.py`（BGE-M3 向量端口，原 `native_plane.py`）、`host/tokenizer.py`（钉死分词文件的取得与核对）、`deployment/goal_world.py`（规划世界，按 `domain` 加前缀；桌面传 `desktop`，类型名与原来逐字相同）。
3. 证明：SDK 测试 `tests/orchestrator/host/`（脚本模型跑完一局、门口检查、实例锁、无计数器、发布目录）；例子 `examples/orchestration-host/demo.py --scripted`；独立验收：仓库外空项目只装 wheel，真实 DeepSeek 跑完一个任务。
4. 桌面端后端改用同一入口（同一件事只留一条路径）：`OrchestrationService` 只补桌面自己的——配置段读取、提供方链读取、钉版核对与部署清单写盘、进度推送、通知存档、存储用量、界面投影、诊断、技能目录、执行图读写、保证通道读；删 `provider.py`、`runtime_profile.py`、`hierarchical.py`、`native_plane.py`、`skill_script_runner.py`、`lock.py` 与 `settings.py` 的大半。
5. 发版 opt.194，独立核验，真机一局。

## 五、独立核验与仓库外验收（发版前）

- 独立核验（opus 子代理，只读）：`独立核验-opt194.md`，结论 PASS，"必须处理"为空。采纳的建议：①配了 DeepSeek 但缺分词文件时原因说"只支持 DeepSeek"会误导 → 宿主分开说（`_no_pool_reason`）；②驱动循环每轮的存储用量刷新丢了 → 宿主加 `on_round` 回调，桌面挂 `StorageUsage.schedule_if_stale`；⑤没起来时每次列任务、每个节拍各打一条带堆栈的日志 → 这两处降为 debug。记下不做的：③钉版核对在拿锁之前（只在同目录两个不同版本进程同时在时有影响）；④执行池身份测试不经宿主拼装（本次逐行对过参数）。
- 仓库外验收（脚本模型）：`~/sh-ext-accept/`，只装从源码构建的 wheel（`uv pip install <wheel>`），跑 `demo.py --scripted`。**第一次 FAILED（planning_failed）**：任务要求 `file:NOTES.md` 由沙箱里宿主解释器跑 pytest 核对，空项目没有 pytest → 核对失败 → 修复轮把脚本回复用完。这是只在仓库外才暴露的缺口（仓库虚拟环境一直有 pytest）。改法：`pytest>=8.3,<9` 从 `testing` 扩展改为 SDK 正式依赖（锁文件随之变），接入说明写明。改后重装重跑：**COMPLETED（verification_passed）**，用量 settled 1050。

## 十、安装简化（用户 10-19 晚："安装这么麻烦吗"）→ opt.195

- 原来三步：装轮子带 `[deepseek-tokenizer]` 扩展、自己取分词文件、写代码。现在一步：`pip install <轮子>`，再写几行代码。
- `deepseek-recipe==0.1.1`（22 MB，无依赖）改为 SDK 正式依赖，`deepseek-tokenizer` 扩展删除；宿主启动时 DeepSeek 端点没给分词文件也没给计数器，就按钉死哈希下载到数据目录 `deepseek-v41-tokenizer.json`（`OrchestrationHost._ensure_tokenizer`，只下载一次；下载失败按"宿主没起来"报原因）。给了 `tokenizer_path` 或计数器就不下载；非 DeepSeek 不下载。用例 1 条（含失败路径）。
- 文档与示例同步：接入说明安装一行、最短程序少两行；`demo.py` 的 `SH_TOKENIZER` 可不给。
- 顺带查清前面"SDK 宿主测试首次运行偶发 1 条失败"的原因：改过 SDK 源码后没先重生成部署清单，`test_a_mission_runs_to_completion_through_the_host_entry` 报 `installed source bytes changed`；不是时序波动。做法：改源码后先重生成清单再跑测试。
- 核验员三轮复核 PASS（f02226ece、3f125f87e、50fa8c192）；采纳：Windows 平台标记、线程里下载 + 连接 10 秒超时、下载挪到拿锁之后、给了路径下到那里、哈希不符拒绝不覆盖；记下不做：Windows 上先报不支持（产品只做 macOS）。
- 回执 `review-210414.json`；**SDK opt.195 = deb9e006c，Host 钉版 097bd443c**，钉版用例 167 条通过，已推送。
- 一步安装验证：全新空项目 `~/sh-ext-accept2` 只装轮子，脚本模型一局 COMPLETED；发版后 `~/sh-ext-accept3` 只装 opt.195 轮子、不给分词文件，真实模型一局见下。
