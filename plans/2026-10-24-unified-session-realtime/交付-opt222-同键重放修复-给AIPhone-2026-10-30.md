# opt.222 同键重放修复交付给 AIPhone

最后更新：2026-10-30。**修复已提交、96 项专项验证通过；opt.222 发版与 Host 钉版因缺独立核验回执阻断，当前仍 opt.221。**

## 缺陷与根因

AIPhone 使用同一文本、同一 key 重试已受理回合，原委派任务已完成但 Session receipt 没落账。
旧 `host/delegation.py:82` 使用 `session_id + turn_id + digest(goal)` 作为 mission 幂等键。
模型把中文目标改写成英文后，键改变；旧在途检查只拒绝未终态任务，故原任务终态后又建 mission。
`call_id` 也随执行变化，不能独立充当用户意图身份。用户原文的冲突检查仍应严格保持。

## 修复方案

- 委派键采用 `session:<session_id>:<turn_id>:slot:<n>`；同一执行者的调用序号从 0 起。
  `delegation_calls` 把 `(turn_id, Agent run_id, call_id)` 与槽位同事务落账。
  原 Agent 恢复保留调用槽位与进度；替代 Agent 从槽位 0 重放，按既有槽位返回同一 mission。
  新增调用只有在此前槽位已遍历后才分配下一个序号；既有在途限制不变。
- 槽位的原 request、spec_hash、sources 均保持，不把漂移目标用于创建或修改任务。
  不同规格在委派行的 `spec_drift` 列表记录新旧哈希、时间与事件编号，写入
  `delegation_replayed_with_drift` 事件；同一执行调用与新哈希的重复核对不重复留痕。
  工具结果增加 `intent_binding: created|replayed`、`spec_drift: bool`。
  Session 最终 receipt 增加 `delegations`，其中含槽位、原 mission 与漂移标志。
- `Session.send()` 仍在 `_send_lock` 内检查同 key 原文与已落账 receipt；第二个并发请求
  等第一个结束后取其 receipt。不同原文保持 `idempotency_conflict`，新 key 仍可新建任务。

## receipt 恢复链路

原链路为 `Session.send → SessionChatService._complete → ChatService._complete/_wait → Agent`。
用户输入先持久化，委派先记意图，再用 Host 幂等键创建 mission；委派回执随后落账。
Agent ReAct 工具执行器会持久化 effect 结果，工具消息与 `tool_result_progress` 再由 checkpoint CAS 保存。
工具成功后、effect 结果写入前崩溃时，control command 的 `observe()` 会重新调用同一绑定以收敛，
并非直接证明外部效果未发生。稳定槽位与 mission 幂等键共同保证此处不重复执行设备任务。

不能把所有重启都解释为重新调用模型：原 Agent、已记录工具结果与 checkpoint 均可恢复时，
runtime.recover_pending_turns 会继续原回合；`agent.submit` 同 input_id 也具备持久重放。
`ChatService.turn` 原本已经通过 `_find_turn/_rows` 使用 `chat_receipts`，它并不是完全被忽略。
本次 `Session.send` 直接补用该回执，明确收口聊天回执已落账、外层 receipt 未提交的窗口。

需要重新调用模型的关键情形是执行者已经关闭，或它卡在结果未知的 provider 调用，
`ChatService._agent/_given_up` 会换代。旧实现的新执行者不沿用旧工具效果进度，
故模型可能重新委派，且改写 goal 后穿透旧键。这条路径仍可重试，但委派由稳定槽位收敛。
另一个可修缺口是原 Agent 的成功结果已提交、聊天 receipt 尚未生成时：旧逻辑对关闭的 Agent
直接换代，丢弃了可读取的成功结果。本次在 `turn_agents` 记录 turn 与 Agent 关联，
优先重用原 Agent 的 committed 结果，跳过已关闭 Agent 的重新 submit，继续记账和 Session 落账。
失败执行者仍保留原有换代恢复规则，不把失败结果冒充成功。

结果仍通过原 `SessionInbox.catch_up` 生成唯一 inbox，后续成功对话把其 `applied_turn_id` 落账，
用户可调用 `ack()`；ack 权限不变。没有改工具说明、提示词、工具 schema 文字、模板或并发默认值。
