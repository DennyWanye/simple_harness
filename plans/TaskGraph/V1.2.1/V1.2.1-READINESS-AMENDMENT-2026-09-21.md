## 2. 物理路径修复：不硬编码macOS前缀

旧缺陷：`(root / relative).resolve().is_relative_to(root)`只规范化了被检查路径；root可能仍是`/var/...`，真实路径却是`/private/var/...`。

现在：

```python
physical_root = root.expanduser().resolve(strict=True)
target = (physical_root / relative_test_path(nodeid)).resolve(strict=True)
if not target.is_relative_to(physical_root) or not target.is_file():
    raise ValueError("target missing/outside snapshot")
```

不使用`str.replace('/var','/private/var')`，不casefold，不把root-extra当root。绝对path、`..`、Windows drive/backslash输入拒绝；内部symlink逃出物理root仍拒绝。用户选择的root本身可以有合法系统alias。

边界：这是可信离线快照的路径核验，不宣称能抵抗不可信进程并发替换symlink的完整沙箱攻击。采集/collection前后仍验证文件hash。

macOS原例必须在**新包未改字节**上重跑；本地Linux模拟alias通过不能宣称macOS实机通过。

### 3.2 精确绑定规则

1. registry写完整参数nodeid：只匹配该exact item，缺失则BLOCKED。
2. registry写基础Function selector：匹配`base_nodeid`精确相同的**所有**参数项。
3. 同名prefix、另一个Class、另一个文件不匹配。
4. 基础selector与显式参数selector重叠：该case需修registry/审查，不能无声dedupe。
5. 旧collection只有nodeids时可以绑定exact item，但不能猜参数展开；重跑新版collection。
6. `-k/-m`或conftest显式deselection出现时不能签全量覆盖。工具清除本进程PYTEST_ADDOPTS并固定rootdir；不写.env、不改系统环境。
7. 每个case保留`registry_selectors`、`parameter_expansions`、`actual_nodeids`、`required_assertions`；collection通过仍`execution_status=NOT_RUN`、`assertion_coverage_review=PENDING`。

对本次handoff中的`test_state_free_decisions_stop_before_shape_or_operation_preview`，其基础selector应展开[wait]、[no-change]、[declare-blocked]。**不猜它对应P几**，让本地registry决定。case要求三分支时，未来运行必须全部通过；不得只挑[wait]代表整组。

36 case/35基础selector是允许的一对多/多对一映射。展开后unique item数可以大于35，不强制等于36；每个case的断言覆盖分别审。

若原stage runner只接受`nodeid: str`并且由基础selector运行pytest，原调用可继续；它的收据必须列出实际展开item。若要消费展开list：在H1H原工作流里给registry reader增加`selectors: tuple[str,...]`和`collected_nodeids: tuple[str,...]`分层，并保留旧单字符串读取，不改原36 case ID/断言。
