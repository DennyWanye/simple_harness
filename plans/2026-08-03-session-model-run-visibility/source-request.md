# 原始需求摘录

本计划冻结下列用户原始意图；它们共同限定范围，不用派生总结替代：

1. “现在的 UI 看起来还行，不过我希望更加合理的绑定起来，像是多步骤任务的，需要显示有哪几步，当前执行到了那一步。之前每一步做了什么，用了什么工具。工具的相关的消息框更加的紧凑，不要占用太多页面信息。每一步都可以进行隐藏和下拉展开，方便用户查看。”
2. “现在的问题，我需要明显的在消息框里面看到相关的 agent 的思考结果和它做了哪些操作……然后调用了工具就要用工具的消息框，也展示出来，以及调用工具的结果（这个默认隐藏，可以点击下拉展开。）”
3. “它好像卡住了，另外，我明明选择使用 kimi3 模型，但是点击发送了之后，又变成 glm5.2 了。”
4. “请你按照最佳实践，进行修复。”
5. 用户确认的模型规则：“所有 Session 相关工作使用该 Session 选择的模型；只有真正跨 Session 的系统维护任务可以使用单独的后台模型。”
6. 用户确认的发布拆分：“模型路由 / Context / 附属失败隔离”与“根子任务聚合 / 运行图 / 紧凑工具详情”分成两个独立切片；Godot 项目本身不进入本计划。
