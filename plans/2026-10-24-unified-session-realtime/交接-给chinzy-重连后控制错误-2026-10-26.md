## 当前结论

Service SDK 0.3.19 的本轮最终七条分支没有收到 `tokenseller.error`。另做无输入音频的控制恢复诊断，路线 a 实播 3200ms，真实断线后回灌、同号重绑回灌均通过，也没有控制错误。这只能说明这些路径本轮未复现旧问题，不能补写 live6 的 28 条错误字段或宣告 A11 全通过。

当前有两项可定位阻断：语音输入同一 item 的角色元数据矛盾，导致 SDK 严格身份校验拒绝；文字 MEETRAN gpt-6.1-sol 对原请求返回 HTTP 403，安全分类为 `quota_precharge_rejected`。两者独立，不归为 ASR 超时、busy、开线耗尽或模型质量失败。

## 控制恢复单独复验

`live7/control-probe1`：公开 announce 路线 a → 生成/传输完成且实播 3200ms → 人为关闭当前 socket(code=1011) → generation 1→2、历史回灌成功 → detach/关闭会话后在同一 Host 挂回同一 session_id → 新 binding generation=3、回灌成功。输入 PCM 0 帧，没有重放输入或重复业务命令。分代实播分别 3200/0/0ms，汇总保留初始 3200ms；新绑定为零不能抹掉旧绑定播放。

本轮控制错误清单为空，所以不能提供不存在的 code/message_class/related_event_id。live6 的 28 次历史控制路径终止仍缺这些字段，原件不改、不猜测其 code 或终止原因。本轮接收边界已覆盖控制帧：未来若出现，将保存 code、message_class、related_event_id、retryable、fatal、retry_after_ms、connection、correlation、binding/generation、触发事件类型和匹配是否确证。未白名单值明确记 redacted，不能将最近事件猜成精确关联。
