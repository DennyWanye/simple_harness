## 计划原文的出入（已裁决）

- "字数统计模块搬到 SDK 正式位置"：它是测试夹具，产品代码不用，不搬；改为"产品代码不许引用 testing"并由检查卡住。
- "后端 9 处 sqlite 内部引用"：产品代码已无子模块引用；sqlite 包根是公开接口（第 1.1 节），进清单。
- "每个包 `__init__` 列 `__all__`"：空包入口不导出东西，不加；公开边界由公开模块清单表达。
- Host 预算账户名字继续从 commit_service（其 `__all__` 里有）导入；budget_accounts 为内部模块；阶段 3 交接里"改从 budget_accounts 导入"作废。

## 中途发现与修正

- **调研失准**：初版设计说产品代码引用 SDK testing 为 0、字符串打桩为 0，裁决员核出一致性工具引用 testing、两个测试按字符串打桩端到端钩子。原因是我用的 grep 正则在 macOS 上不支持 `\w`，漏匹配。之后统一用语法树扫描。
- **uv sync 不能在工作树里跑**：工作树的虚拟环境是主检出的符号链接，在工作树里 `uv sync` 会把 SDK 包的安装来源改成工作树路径，主检出的 SDK 候选身份检查依赖它。处理：回主检出跑 `uv sync --extra dev --inexact` 改回来。
- **改坏清单锚点**：TG4-02 用"两行函数内导入"定锚，阶段 3 把它们上提了，锚点不再存在，发版门挡下。手工重锚为"在函数开头遮蔽 record_request"，用改坏执行器确认仍然 KILLED。阶段 3 各批没跑改坏清单资产测试（记忆里有这条教训，没照做）；批次脚本已改为 SDK 改动必跑。
- **启动耗时基线**：机器状态漂移，基线改为在同一时刻测主分支代码后重写（8.91 秒），改动后 8.71 秒。
- **macOS 大小写**：判断"名字是不是子模块"时文件系统不区分大小写（`Runtime` 会被当成 `runtime` 目录），检查脚本改为按目录列表区分大小写。
