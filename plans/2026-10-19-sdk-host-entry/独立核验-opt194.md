### 逐项结论

1. pytest 改为 SDK 正式依赖（`pyproject.toml`、`uv.lock`）。
   - 插件不是这次才自动加载。`[project.entry-points.pytest11]` 在 c5dfa656a 就有；只要环境里同时有 SDK 和 pytest，插件原来就会加载。这次只是让 pytest 一定在。
   - 插件 `simple_harness/testing/pytest_plugin.py` 没有副作用。它只加 4 个 `--simple-harness-*` 选项、1 个标记和 3 个按名取用的 fixture。没有 autouse fixture，没有收集或运行钩子，不改外部应用的测试结果。没给 `--simple-harness-host` 时，这些 fixture 跳过。插件只导入标准库和 `simple_harness` 自己的模块，没有可选依赖，不会因为缺包让外部应用的 pytest 起不来。
   - 实测：在仓库外临时目录放一条普通测试，用 SDK 虚拟环境的 pytest 跑。`--trace-config` 显示插件已加载，测试照常 1 条通过。插件导入约 65 毫秒。
   - 依赖链：沙箱核对用的是宿主自己的解释器（`SeatbeltExecutor.for_interpreter(sys.executable)`），pytest 必须装在同一个环境里，所以做成正式依赖是对的。冻结包里沙箱本来就不开，不受影响。
2. `_no_pool_reason()`（`host.py`）：只在"没给计数器、有模型、模型是 DeepSeek、没给 `tokenizer_path`"时报缺分词文件，其余仍报 `ONLY_DEEPSEEK_REASON`。
   - 给了路径但文件不在时，计数器构造会抛错，宿主照常以"启动失败：…"起不来，不会漏报。
   - 桌面：`tokenizer_path()` 找不到文件时返回 None，会走到新原因。非 DeepSeek 时 `test_native_plane_host` 断言的仍是 `ONLY_DEEPSEEK_REASON`，测试通过。
3. `on_round` 回调：位置在 `run_forever` 的 try 里、`_note_quiet_round()` 之后、`_failures = 0` 之前。
   - 回调抛错时会按一次循环失败计数，进入退避；累计到 `rebuild_after_failures` 还会重建。
   - 这与改动前一致：原 `_drive` 的 `self._storage.schedule_if_stale()` 也在同一个 try 里、同一个位置。
   - 桌面挂的 `StorageUsage.schedule_if_stale` 只判断是否过期、建一个后台任务，在跑着的事件循环里不会抛错。测量本身在后台任务里，失败只记 warning，不回到驱动循环。所以不算阻断。
4. 两处日志降为 debug（`_tick`、`recovery_isolated`），都带 `exc_info`，返回值不变。
5. 接入说明补了两句：pytest 随 SDK 装、`file:`／`pytest:` 由沙箱里的 pytest 核对；常见问题加了"缺分词文件"一行。与代码一致。

### 建议（非阻断）

1. `on_round` 是公开的扩展点，建议宿主自己包一层 try/except 并记日志，不让外部应用的回调错误按循环失败处理，进入退避和重建。另外类型写的是 `Callable[[], Any]`：外部应用如果传异步函数，返回的协程不会被等待，回调永远不执行，只留一条 "never awaited" 警告。建议要么像 `auto_mode` 一样识别并等待可等待对象，要么在说明里写明只收同步函数。
2. pytest 成了运行依赖，`<9` 的上限也随之压给外部应用。应用如果已经用 pytest 9，装 SDK 时会解析冲突。建议在接入说明里写明这个范围，或者评估放宽上限。
3. `[testing]` 扩展已删，但下面几处还在用：
   - `sdk/simple-harness-sdk/.github/workflows/platform-tests.yml:118`
   - `sdk/simple-harness-sdk/.github/workflows/release-candidate-conformance.yml:87`
   - `sdk/simple-harness-sdk/docs/consumers/aiphone-handoff.md:72`
   - `uv pip install wheel[testing]` 遇到没有的扩展一般只告警，pytest 照样会装；但 `uv sync --extra testing` 会直接报错。建议把这三处里的 `[testing]` 去掉。
4. 缺分词文件的新原因写的是"请传 tokenizer_path（见接入说明）"，桌面界面会照原样显示，桌面用户看到的是开发者用语。建议桌面覆盖成"模型目录里缺 DeepSeek 分词文件"之类。
