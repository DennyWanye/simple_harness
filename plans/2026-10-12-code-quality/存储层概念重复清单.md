## 看到的重复（供下一轮设计）

1. **两份执行存储**：SDK 与后端各有一个 `SqliteExecutionUnitOfWork`（302 与 258 个方法），认领、结清两类方法名大量同名同义（租约、心跳、终态）。根源同阶段 8 重复片段甲组：后端与 SDK 两套工作流引擎并存。统一前要先决定后端引擎去留。
2. **租约概念各写一遍**：执行存储、能力存储、伴侣存储各自实现"认领 + 心跳 + 释放"（能力存储 31 个认领类方法）。下一轮可抽一个通用的有期限认领表与状态机，各存储只登记自己的对象种类。
3. **结清路径分散**：结清类方法在执行存储里最多（SDK 68 个），伴侣、能力存储各有自己的终态写法；统一时先列出每种对象的终态集合与幂等键。
4. **提交类大多是"写一行事实 + 事件"**：会话账本、编排存储以提交为主，几乎没有认领；它们更像追加型账本，统一时可与执行存储分开对待。
