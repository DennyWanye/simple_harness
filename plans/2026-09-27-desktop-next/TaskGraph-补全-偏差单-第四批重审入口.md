# 偏差单：第四批"按现行范围重审已有结果"的入口怎么接

日期：2026-10-04。方案第 3.4 版第 4 节第 3 条。

## 方案原文
新开"按现行范围审已有结果"的入口：审查对象是原结果、原产物、原冻结输入，范围用现行计划给这一步冻结的范围；切包与验收提交**只放宽"尝试冻结范围 = 现行范围"这一条**，其余核对不变。不建尝试、不调执行者。

## 施工发现（只读摸底，见 `TaskGraph-补全-第四批-施工设计.md` 第一节）
"只放宽一条"不成立。现行验证 → 验收整条链对"已验收的同一份结果再审一次"有约十处挡着，其中几处不是放宽核对能解决的：
1. 验证只挑"待验证 / 验证中"的结果，并且全程持有尝试的租约；已验收结果的尝试、任务都已结束，续不了租。
2. 验证层记录按（结果, 层）唯一，已验收结果的记录不可改——重审要另存一份。
3. **保证机制的唯一性规则**：同一份结果（按信封摘要）只能有一条内容审阅绑定；出现第二条后，取审阅记录、取有效记录的两处都会报"来源有歧义"。重审必须改这条规则（改成按审查包区分）。
4. 审阅员调用按尝试找旧记录、旧调用、尝试的保护预算，并要求尝试活着。
5. 验收编号按（任务, 结果）算、命令号按结果算，与旧验收撞号，会被当重放。
6. 验收提交与打回都会改尝试 / 任务 / 产物状态、结清预算。
7. 本地检查绑在结果冻结的范围上。

## 两个接法

**甲：按方案原文直接接。** 验证流程加"重审"参数：不要租约、验证层另存新表、审阅记录唯一性改为按审查包、审阅预算记任务账户、验收编号带要求版本、验收不动尝试 / 任务 / 产物、打回走修复请求。约九处改动加一张新表，其中第 3 条改的是保证机制的身份规则。

**乙：系统建一个"复核尝试"。** 不调执行者：系统新建一个尝试，它的结果由系统按原结果的产物原字节登记（标明"沿用自原结果某某"），冻结输入沿用原结果的输入清单，然后走现成的验证 → 验收流程，一处不改。通过 → 照常写验收（新结果、新编号，天然不撞号）；打回 → 不进重试，改发 `CARRIED_RESULT_REJECTED` 修复请求交规划器。要改的是：派发处多一种"复核"尝试（不提交给执行者）、产物登记的来源、打回分流、这种尝试不计入任务的尝试次数上限。与方案原文的出入：会建尝试记录（但不调执行者、不重做）。
