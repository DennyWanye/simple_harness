# 阶段 9 · 9I 内联样式设计（请裁决）

日期：2026-10-17
依据：计划 2.10 修订 9.7（内联样式 849 → ≤ 200）；阶段9-切片设计.md 裁决执行条件 4（WebKit 真浏览器逐元素比对计算样式、深浅两套主题；先由 tokens.ts 生成间距、字号 CSS 变量，CSS 类只引用变量；指标同时计 `style={{` 与 `style={变量}`）。

## 现状（实测）

- `style={{…}}` 840 处（非测试 .tsx）。全是字面量或主题令牌（tokens.*、dark.* 等常量）的 587 处；除展开（`...button` 之类模块常量）外全静态的 117 处；依赖运行时值的 136 处。
- `style={变量}` 612 处（棘轮已计，不许增加）。
- 颜色已经是 CSS 变量（`--sh-*`，tokens.ts 的 THEME_CSS 运行时注入 `<style id="sh-theme">`，TS 侧是 `var(--sh-x, 深色兜底)`）；间距、圆角、字号、字重、阴影只在 tokens.ts。
- 全局样式文件 7 个（index.css、App.css 与 5 个组件 css），另有第三方 `@xyflow/react/dist/style.css`。
- 本机没有 WebKit：主检出后端虚拟环境有 Python Playwright 1.61，但浏览器二进制未装（`playwright install webkit` 要下载约 70 MB，按规则须用户同意）。

## 方案

1. **令牌变量**：tokens.ts 增加由 space / radius / text / weight / shadow / font 生成的 CSS 变量块（`--sh-space-md: 12px` 之类），并入 THEME_CSS（同一处注入）；用例锁住"变量值 = 令牌值"。
2. **转换工具**（入库，`scripts/code_quality/ts_inline_to_class.mjs`）：
   - 只转小写标签（真实 DOM / SVG 元素）上的 `style={{…}}`；组件元素上的 style 属性不动（可能不是 DOM 样式）。
   - 只转全静态对象，以及"静态 + 展开模块级静态常量"的对象；有运行时值的整处不动（不拆一半，避免同一元素一半类一半内联的顺序问题）。
   - 元素已有 className 时只处理字符串字面量 className（拼接）；表达式 className 的元素不动。
   - 声明文本由 React 自己生成：工具在 node 里用 `react-dom/server` 渲染 `<div style={对象}/>`，取 React 序列化出的 CSS 文本，保证与原内联逐字一致（单位、数字加 px 的规则、属性名都与 React 相同）；再把来自令牌的值换成对应的 `var(--sh-…)`（值由第 1 步保证相等）。
   - 每个源文件生成一个同目录 `Xxx.styles.css`（组件里 `import`），类名 `sh-<文件简名>-<序号>`；同一文件里声明完全相同的对象共用一个类。
3. **优先级**（内联样式原本压过所有作者普通规则）：把现有 7 个样式文件与第三方 xyflow 样式放进 `@layer sh-base`，生成的类不分层。按层叠规则，不分层的普通声明压过分层的普通声明，与内联原来的地位一致；分层里的 `!important`（如减少动效时的 `transition: none !important`）照旧压过它们，也与内联一致。换了 hover/focus 的现有规则，原来被内联压住、现在仍被生成的类压住，不会冒出新的悬停效果。
4. **核对**：
   - 静态核对（工具自带，入库）：从 HEAD 重新求值每处原内联对象，用 React 序列化，与生成类的声明（把 var 换回令牌值）逐条相同；被转元素的 JSX 除 style→className 外语法树相同。
   - 浏览器核对：用应用内浏览器（Chromium）打开 Vite 开发服务器上的样式画廊页（夹具挂载可脱离后端渲染的组件：设置页各区块、消息气泡各形态、技能商店、添加服务商弹窗、上下文明细、执行轨迹、任务视图等，用假通道喂数据），深浅两套主题各取全部元素的 getComputedStyle，转换前（HEAD）与转换后逐元素比对，必须全等。
   - 与裁决条件 4 的出入：**浏览器用 Chromium 不用 WebKit**。理由：比对的是同一引擎里转换前后的结果，证明的是"声明与优先级不变"，不依赖引擎；WebKit 需要下载。若裁决坚持 WebKit，就请用户同意下载后再做。
5. **分批**：按文件分 4～5 批提交，每批：工具转换 → 静态核对 → 画廊浏览器比对 → 相关 vitest。

## 风险

- 第三方样式进层后，它与我们样式文件之间的先后关系不变（同在一个层里按原顺序）；但它们相对"不分层的 THEME_CSS 变量定义"的关系不涉及冲突（后者只定义变量）。
- 打包后的类名全局唯一靠文件简名前缀；工具检查重名。
- 画廊覆盖不到的组件只靠静态核对。

### 实测核对

- src 里读写 `element.style` 共 9 处：CopyMessageButton（临时 textarea）、InputBar 自动增高（textarea 的内联样式没有 height，可转）、InputBar 聚焦描边、ConfirmDialog 悬停底色。后两处写回的是同一属性，转换后仍等价，但必须排除（见条件 5）。
- 样式文件实际引入 6 个；**App.css 没有任何文件引入**（死文件）。xyflow 样式在 LiveGraph.tsx 用 JS 引入。
- **还有 4 处不分层的作者样式，设计没有列出**：index.html 的 `<style>`（html/body 底色）、App.tsx:1049 的 `<style>`（keyframes pulse）、StartupOverlay.tsx:95 的 `<style>`（keyframes）、RunInspectorPanel.tsx:62 的 `<style>`（媒体查询，含 `!important` 与普通声明）。
- 测试读内联样式：7 个测试文件共约 35 条 `.style.x` 断言。其中 MessageStreamPanel.workflow.test.tsx:254-258 断言 `style.height` 等为空字符串，转换后会**空过**。
- 发版配置最低 macOS 13.0（tauri.macos-release.conf.json），系统 WebKit 为 Safari 16 起，支持 `@layer`（15.4 起）。vite.config 没有写 build.target，用 Vite 8.1.3 默认目标（含 safari16.4）。
- 在临时目录用本项目的 Vite 8.1.3 实测构建：
  - `@import "@xyflow/react/dist/style.css" layer(sh-base);` 在产物里正确包进 `@layer sh-base{...}`，懒加载块也一样。
  - **产物 CSS 经过 Lightning CSS 压缩并按目标改写声明**：`backdrop-filter:blur(8px);-webkit-backdrop-filter:blur(8px)` 变成只剩 `-webkit-backdrop-filter:blur(8px)`；`padding:8px;padding-left:4px` 合并成 `padding:8px 8px 8px 4px`；`rgba(127,178,170,0.32)` 变成 `#7fb2aa52`；声明顺序被重排。内联样式从来不经过这一步。开发服务器也不经过这一步。
- 用本项目 React 19.2.7 实测 `react-dom/server` 序列化：
  - 属性值做 HTML 转义：`"SF Mono"` 输出为 `&quot;SF Mono&quot;`（tokens.font.ui 与 font.mono 都含引号）。
  - `color:'red !important'` 原样输出；客户端用 `style.color = 'red !important'` 赋值，浏览器判无效、整条丢弃。写进 CSS 类后会变成 important。
  - 值里有分号时，服务端原样输出，CSS 里会变成两条声明；客户端整条丢弃。
  - `cssFloat` 输出为无效的 `css-float`；客户端能正确设置。src 里目前没有 cssFloat、没有值含 `!important`。
  - 数字补 px 的规则、无单位属性表，服务端与客户端共用同一张表，一致；null/undefined/布尔/空串两端都不输出；自定义属性两端都去首尾空白，不补 px。
  - 客户端是逐条 CSSOM 赋值（`style[name] = value`，自定义属性用 setProperty），不是整段文本。因此"逐字一致"只对合法值成立。

### 对四个关键论断的结论

1. **层叠层保持优先级：修改后同意。**
   - 规则本身成立：内联普通声明压过所有作者普通声明，但输给作者 `!important`；"不分层普通 > 分层普通、分层 `!important` > 不分层普通"与之一一对应。动画、过渡的层叠位置在作者层之上，两种写法相同。内联样式与类规则都不作用于伪元素，伪元素只靠继承，两种写法相同。`:hover`/`:focus` 等规则若在分层里，原来输给内联、现在输给生成的类，相同；若带 `!important`，两种写法下都赢，相同。
   - 成立前提：**除生成的类与 `sh-theme` 外，所有作者样式都必须在 `sh-base` 层里**。反例：留在层外的普通规则会按选择器优先级与生成的类比较（原来内联总是赢）；留在层外的 `!important` 会被层里的 `!important` 反超（层里的 important 优先于层外的 important）；层外的 keyframes 会压过层里的同名 keyframes。上面 4 处 `<style>` 都属于这种情况。
   - `<style id="sh-theme">` 不受影响：它只在 `:root` 上定义 `--sh-*` 变量与 `color-scheme`，与层里的规则没有同名属性；生成的类引用变量，在计算值阶段解析。新增的间距、字号变量放进同一块即可。
   - WKWebView：最低 macOS 13，支持 `@layer`，不阻断。
2. **react-dom/server 取声明文本：修改后同意。** 单位与属性名规则可信，但必须解码 HTML 实体，必须拒绝含 `!`、`;`、`{`、`}`、`/*`、`\`、`<` 的值与 cssFloat 键名。另外，设计里的静态核对用同一个序列化器生成两边再比较，是循环论证，查不出转义一类的错。
3. **Chromium 代替 WebKit：不同意（作为最终核对）。** 理由：
   - 生成的类进入产物后要经过 Lightning CSS 按目标浏览器改写（实测删掉了无前缀的 backdrop-filter、合并简写、改颜色写法、重排顺序）。内联样式不经过这一步。所以"转换前后声明不变"在产物里本身不成立，只能比较计算结果。
   - 改写结果依赖引擎：同一份产物，在 Chromium 里会丢掉毛玻璃（Chromium 不认 `-webkit-backdrop-filter`），报出假差异；在 WebKit 里等价。反过来，开发服务器不压缩，在 Chromium 开发服务器上比对查不出压缩器带来的真差异。
   - 产品只跑在 WebKit 上。只有"WebKit + 产物构建"上的比对能证明等价。
   - Chromium 开发服务器比对可以留作每批的快速检查，不算核对通过。
4. **边界：修改后同意。** 只转小写标签、不拆一半、只拼字面量 className 是对的，但还漏了展开属性、ref、事件里写 `.style`、读内联样式的测试、按值反查令牌，见下面条件。

### 阻断级执行条件

1. **最终核对用 WebKit + 产物构建。** 每批用 `vite build` 的产物（预览服务器提供）在 WebKit 里逐元素比对 getComputedStyle，深浅两套主题，转换前（HEAD 的产物）与转换后全等，或仅有《阶段9-偏差单-压缩器改写背景》裁决列明的等价差异，才算通过（2026-10-17 按该偏差单裁决条件 6 修改）。下载 Playwright WebKit（约 70 MB）先问用户；用户不同意时 9I 停下等用户，不许只用 Chromium 交付。
2. **全部作者样式进层。** 6 个已引入的样式文件、xyflow（改为在 LiveGraph.css 顶部 `@import ... layer(sh-base)`，删掉 JS 引入）、App.tsx/StartupOverlay.tsx/RunInspectorPanel.tsx 的 3 处 `<style>`、index.html 的 `<style>`，都放进 `sh-base`。App.css 没被引入，不算在内（要删另走删除清单）。加一条入库检查：读产物 CSS，除生成的 `sh-<文件简名>-<序号>` 类之外，每条规则都必须在 `@layer sh-base` 里；运行时 `<style>` 只允许 `sh-theme`，且它只许含自定义属性与 color-scheme。
3. **静态核对不许循环。** 原内联一侧：求值得到的对象按 React 客户端规则（逐属性、补 px 表、跳过空值）得到"属性→值"表；生成一侧：用 CSS 解析器（如 postcss）读生成的 .styles.css，把 var 换回令牌值，得到"属性→值"表；两表逐条相同。序列化文本要先解码 HTML 实体。核对工具要过金丝雀：故意改坏一处（例如一个值、一个转义）必须报出。
4. **转换工具拒绝危险值。** 值含 `!`、`;`、`{`、`}`、`/*`、`\`、`<`，或键名为 cssFloat、含连字符，整处不转并列出。
5. **排除会被代码改写的元素。** 带展开属性（1 处）、带 ref（5 处）、事件处理里出现 `.style`（2 处）的元素不转。工具输出排除清单。
6. **令牌变量按来源替换，不按数值反查。** 只有语法树上值来自 tokens 成员（space/radius/text/weight/shadow/font）的才换成 `var(--sh-…)`；字面量 12 不许因为等于 space.md 而换成变量。用例锁住变量值等于令牌值。
7. **读内联样式的测试不许空过、不许删。** 被转元素上的 `.style.x` 断言（7 个文件，约 35 条）必须先列清单：要么该元素不转，要么断言改成检查 className 对应的生成声明。尤其 MessageStreamPanel.workflow.test.tsx:254-258 的"为空"断言，转换后必须改写成真能失败的断言。
8. **指标与目标对账。** 前次裁决要求指标同时计 `style={{` 与 `style={变量}`。现在两者合计约 1446 处；本设计最多转 704 处，剩下约 136 + 606 = 742 处，到不了计划 9.7 的 ≤ 200。开工前必须二选一：扩展工具处理指向模块级静态常量的 `style={标识符}`，并给出到 ≤ 200 的算术；或者写偏差单交裁决。不许只按 `style={{` 一种写法报完成。
