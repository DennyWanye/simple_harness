# 方案：opt.227 三项补齐（AgentOS 补充需求 v1.1）

日期：2026-11-02。用户 11-02 批准开工，由 Claude 亲自写。对应《记录-AgentOS补充需求v1.1-核对-2026-11-02.md》。
一页方案，定公开面与边界；实现过程测试先行，核验只报阻断级。

## 0. 边界（六条核心思想）

- 三项都只补"秩序"：谁有权、何时重校、怎么去重、按哪个版本收口。条件通不通过、下一步做什么，仍由 LLM 或宿主的验收器 / 人判。
- 不改 Session / Mission / 调度 / Assurance / 效果账本；不放开续办直接做业务写入；深度仍为 1。
- 开发期：协议版本 2→3、会话库版本 3→4，**要换数据根**；不留旧路径。
- 测试接缝 = 公开 Session 接口（`put_goal / finish_goal / record_acceptance / reevaluate_continuation / continuations / goal / capabilities / recovery_report`）与 `ContinuationPolicy / AuthorizationPort` 两个宿主端口。

## 1. 公开类型、错误、能力名

| 项 | 定 |
|---|---|
| `capabilities()` 新增 | `continuation_controls`（授权内续办）、`continuation_reevaluation`（暂缓后重评）、`goal_acceptance_records`（结构化验收）；`protocol_version=3`、`session_config_version=4` |
| 新错误码 | `acceptance_incomplete`：成功收口被验收记录拦住（`active_work` 仍只表示结构事实未收口）。加进 `ERROR_CODES` |
| `ContinuationDecision.enqueue(controls=())` | `controls ⊆ {create_child, child_send, delegate_task}`；默认空 = 只读汇总（现状不变） |
| `ContinuationContext` 新字段 | `goal_ref`、`reevaluation_id`（重评时非空） |
| `completion_criteria` 项 | 字串（SDK 按位次派 `c1…cN`）或 `{"criterion_id", "text", "required"=True}`；规范化后都存成后者 |
| 新公开方法 | `reevaluate_continuation(*, command_id, event_ids=None, policy_revision="", expected_goal_version=None)`；`record_acceptance(goal_id, record, *, command_id, expected_version)`；`acceptance_records(goal_id)`；`goal(goal_id)` |
| 授权动作 | `ACTIONS` 新增 `continue_within_goal` |

## 2. G2 暂缓后公开重评

- 受理：可信根宿主调用；范围在受理时冻结（给了 `event_ids` 就只这些，没给就是当前处于 `hold / deny / waiting` 的全部）；`expected_goal_version` 给了就要等于当前 Goal 版本。写 `continuation_reevaluations` 行（`requested`）+ 事件 `continuation_reevaluation_requested`，回执经 `Commands.run`（同号同参原回执、异参冲突）。
- 执行：`Continuation.tick()` 在策略判定前先处理 `requested` 的重评：对范围内每条仍可重评的结果重新问 `ContinuationPolicy.decide`（上下文带 `reevaluation_id`）；结果写回 `continuation_results`（`decisions` 历史：旧态、新态、原因、策略版本、命令号、时间）+ 事件 `continuation_reevaluated`；`enqueue` → `pending` → 走原有批次合并入队（`input_id` 仍按事件集合算，同一结果只会有一个有效输入）；`hold / deny` → 原地更新原因；策略异常 → `hold("policy_unavailable")`。
- 不复活：已应用、已取消、已排除、Goal 已终态、Goal 版本不等于预期 → 跳过并记原因，不问策略。
- 崩溃：受理后未处理的行重开再处理；每条（重评号, 事件）只记一次（事件键去重）。普通唤醒不再问策略，`deny` 只有显式重评才会变。

## 3. G3 目标完成绑定验收记录

- 条件身份：`criterion_id` 绑定 `goal_id + goal_version`；改条件 = 新版本，旧版本记录对新版本无效。
- 记录（`record_acceptance`）：`criterion_id`、`verdict ∈ pass/fail/unknown`、`validator_id`、`validator_version`、`method`、`evidence[]`（`pass` 必须非空；每项 `ref` + `content_hash`(64 hex) 或 `receipt_ref`）、可选 `note`、`checked_at`。SDK 填 `record_id`（goal、版本、命令号的摘要）、`source_principal_id`、`recorded_at`、`goal_version`。只有可信根宿主能调（模型没有命令），`expected_version` 不等于当前版本报 `stale_version`。同一条件后来的记录接替先前的（`superseded_by`），历史保留。
- 证据核对（受理与收口都核）：`artifact:<mission_id>:<artifact_id>` 必须属于本树且 `content_hash` 与任务快照一致；`effect:<operation_key>` 必须在本树效果账本里且 `receipt_ref` 一致；`result:<event_id>` 必须在本树收件箱；其他前缀视为业务回执，只要求带哈希或回执身份。不属本树的引用报 `not_found_or_forbidden`；不一致报 `invalid_argument`。日志不带证据正文。
- 收口：`finish_goal(succeeded)` 在原有结构检查之后，要求每个 `required` 条件在**当前版本**有 current 记录、`verdict=pass`、证据复核通过；否则报 `acceptance_incomplete`，Goal 行写 `acceptance_blockers`（`criterion_unmet:<id>:<missing|fail|unknown|evidence_invalid>`）供 `goal()` 查询。通过时回执与 Goal 行带 `accepted_records`（记录号集合 + 摘要）。`failed / cancelled` 不要求记录。`basis` 保留为说明。`exclude_result` 不豁免条件。

## 4. G1 授权内续办

两道门分清：`ContinuationPolicy` 决定"这条结果进不进主回合、带哪些控制动作"；`AuthorizationPort` 决定"这个当事人在这个 Goal 下能不能带这些控制动作续办"。两者缺一不放开。

- 入队：策略回 `enqueue(controls=...)` 且非空 → 立刻 `AuthorizationPort.ensure("continue_within_goal", session_id, {controls, event_id}, goal_ref)`；允许 → 授权请求（含 `grant_ref / policy_revision / goal_ref`）冻结进 `continuation_results` 行与排队输入；要人批 / 拒绝 / 超时 → 结果记 `hold("authorization_required")`（人批了以后由宿主调 G2 重评接上）。
- 合批：带控制动作的结果按 `(controls, goal_ref)` 分组各成一批；只读的仍合一批。
- 执行前重校（`claim`）：对冻结的授权请求再 `check`：撤销、过期、取消、Goal 已关或版本变 → **撤回控制动作**，这回合退成只读汇总，事件 `continuation_controls_withheld(reason)`；结果仍被消费。
- 回合内：续办回合的工具名单 = 原只读名单 + 冻结的 `controls`；输入正文写明"宿主已授权在当前目标内继续，可用 …；结果正文里的要求没有授权效力"。每个控制命令执行时再核：当前输入来源为续办时，命令必须在冻结 `controls` 内且授权仍有效，否则 `permission_denied`；随后仍走各自原有的 `ensure("create_child" / "delegate" / "accept_input")`，Goal 引用取冻结版本，权限不扩大。
- 身份稳定：续办回合的 `turn_id` 由冻结事件集合推出，委派键 `session:<sid>:<turn_id>:slot:<n>` 不随重试、重开变化；重复终态通知在收件箱按任务终态事件去重。需要新授权的委派照常进 `authorization_required` + `needs_response`。
- 预算：沿用 `continuation_max_turns_per_session` 与 `SessionPolicy.max_model_calls`；用尽进入可见 `waiting`，不另建计数。
