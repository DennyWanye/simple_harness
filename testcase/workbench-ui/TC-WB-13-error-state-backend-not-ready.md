# TC-WB-13 — 错误态：后端未就绪时 ChatView 状态条与重试

> 对应 AC：非功能「错误态」条款（承接 WB-4 链路）｜ gate_type: negative-safety
> manual_required: true
> 前置：能构造"前端起、后端不可用"状态。可选手段（记录所用手段）：a) dev 模式只起前端不起 backend；b) 启动后精确杀掉 backend 进程；c) 用防火墙/端口占用挡住 WS。禁止 mock 前端状态。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 在后端不可用状态下打开/停留在聊天视图。 | ChatView 显示**连接状态条**（明确的未连接/连接中提示，非静默空白），并提供**重试入口**（按钮或等价交互）。 |
| 2 | 尝试在输入栏发送一条消息。 | 不出现"看似发送成功但消息黑洞"的静默失败：或输入被禁用，或发送后有明确失败反馈。 |
| 3 | 观察侧栏底部连接徽章。 | 徽章显示**最差态**（未连接/错误色），与 ChatView 状态条口径一致——"徽章绿但发送拒发"的分叉 = FAIL。 |
| 4 | 保持后端不可用，点击重试入口。 | 触发真实重连尝试（状态短暂进入连接中再回落错误态），无崩溃、无白屏。 |
| 5 | 释放故障，让 Tauri supervisor/UI 重试恢复后端；**不得**手动 `python main.py` 占用 8100。再次点击重试（或等待自动重连）。 | 连接恢复：状态条消失/转为已连接，徽章转好；此后发送一条消息真实往返成功。 |
| 6 | 回归确认：恢复后切换四视图一轮。 | 各视图正常，无错误态残留。 |

判定：步骤 1–6 全部满足才 PASS；步骤 2 的“无静默黑洞”和步骤 6 的恢复后回归均为阻断项。
