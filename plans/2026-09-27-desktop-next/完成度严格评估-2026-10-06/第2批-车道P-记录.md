# 第 2 批 · 车道 P 记录：全局预算改为按月配额

- 日期：2026-10-06 晚
- 工作树 / 分支：`simple_harness-b2p` / `batch2-p`，基线 main `5683b8d0`
- 来由：用户 2026-10-06 晚拍板——全局预算不再是累计不归零的一个总账，改为每个自然月一个总账，上限 = 配置的月配额（默认 20 亿 token），月初自动是新的空账。

## 一、做法

### SDK
1. **账户编号带月份，只有一处算**：`commit_service.py` 新增 `GLOBAL_ACCOUNT_PREFIX = "budget:global:"`、`global_account_id(at)`（按本机本地时间取 `YYYY-MM`，时刻用 store 时钟）、`is_global_account(account_id)`（按前缀判）。旧常量 `GLOBAL_ACCOUNT` 删除，不留回落。
2. **按任务建立月份计**：建任务时用 `global_account_id(mission.created_at)` 算出建立当月的总账；没有就开；任务账户挂在它下面。这个任务以后的全部用量都记在建立当月，哪怕跨月才跑完（口径写进了代码注释）。
3. **月配额改了要跟上**（对原建议的补充）：原代码 `open_account` 遇到已有账户什么也不做，所以"调大配置并重启即可继续"原本并不成立。现在建任务时若当月总账的上限与部署配置不同，就用新增的 `BudgetLedger.set_limits` 改成配置值（已预留、已结清不动）。生效时机：重启后当月下一个新任务建立时。
4. **"是不是全局账户"只留一种判法**：`event_handler.py` 三处停止判断（规划预留失败两处、步骤预留失败一处）全部改用 `is_global_account`，停止详情仍写 `scope=global`。
5. **工具调用余量**（`_tool_call_room`）：原来按"部署配了全局预算就加固定总账"，现在改为读任务账户的上级账户（即建立当月的总账），同一件事走账本的上下级关系这一条路。
6. `CommitService.global_account()` 返回**当月**总账（当月还没有任务建立时返回 None）。
7. 不新增迁移：账户表本来按编号存，新编号直接写入。开发库里旧的 `budget:global` 账户留在表里无人再用，不迁移、不兼容。
8. 部署清单已重生成并随提交。

### Host
1. 设置项 `global_max_tokens` 改名 `global_monthly_max_tokens`，旧名直接删（写旧名等于没写，取默认月配额）。默认值、下限（单任务默认上限）、上限（10^12）不变。
2. `status().global_budget` 改为：`month`（如 `2026-10`）、`max_tokens`（上限）、`opened`、`used_tokens`（已用 = 已结清）、`reserved_tokens`（预留中）、`remaining_tokens`（剩余）。原 `settled_tokens` 改名 `used_tokens`。月份与账户都由 SDK 算（`global_account_id` / `global_account()`），Host 只做映射；服务没起来时用本机时间算月份、报配置的月配额。

### 前端
1. 设置页只读段标题"任务全局预算"改为"本月全局预算"；状态行前加月份（"2026 年 10 月：上限 20 亿；……"）；说明文字改为按月口径与新设置名。
2. 新增 `formatMonth`；`missionsStore.ts` 的状态类型同步新字段。

## 三、测试

### 先红
- SDK 新测试在实现前收集即失败（新函数不存在）。
- Host 测试改口径后，在旧 Host 代码上失败（旧常量、旧设置名）。

### 新增 SDK 用例（4 条，全过）
1. 月份编号：月末最后一刻仍是本月、次月 1 日是新月、跨年正确；只有全局账户被判为全局。
2. 同月共用 + 跨月满额：月配额 1200 万，同月两个任务挂同一总账；第一个预留 800 万后第二个再要 800 万被拒，拒绝账户是当月总账。拨到 11 月 1 日后新任务挂 11 月新账户，额度满 1200 万；10 月建立的任务在 11 月继续预留仍记在 10 月总账。
3. 月配额改了：重启换大配额，还没有新任务时当月总账照旧；新任务建立后当月总账上限变成新配额。
4. 用完即停：当月总账只剩 1000 token 时建新任务，第一轮规划就以 budget_exhausted 停，停止详情 `scope=global`、`account` 为当月编号。
- 用例 2～4 走产品同形世界（建任务要走部署组装与保证通道，裸 CommitService 建不了任务），用库时钟注入点拨时间。

## 五、留给主会话的事
1. **SDK 发版并重钉 Host 轮子**：Host 依赖 SDK 新函数 `global_account_id` / `GLOBAL_ACCOUNT_PREFIX`，opt.165 轮子没有。合并后需发 SDK 新版并钉进 Host，Host 测试才能只用轮子跑。
2. 用户本机若在 `config.toml` 的 `[orchestration]` 里写过 `global_max_tokens`，改名后不再生效（按开发期口径不兼容），需要改成 `global_monthly_max_tokens`。仓库内 `config.toml` 没有写这一项。
3. `_tool_call_room` 改为读任务账户的上级账户，本车道没有单独为"全局配了工具调用上限"写用例（现部署全局预算只配 token）。
4. 月配额调大后，要等当月下一个新任务建立才写进当月总账；在此之前设置页显示的仍是旧上限。如需"重启即生效"，可在编排服务启动时同步一次当月总账上限（未做，避免扩大改动面）。
