# SDK 任务编排宿主入口（方案与实施记录）

- 日期：2026-10-19
- 依据：用户"Python 应用，我期望使用这个 sdk 做编排"；两点决定：这一版只支持 DeepSeek；桌面端后端这一轮一起改用新入口。
- 分支：orch-host（主检出）。

## 一、问题

真机测试证明的是"SDK + 桌面端后端自己写的接线"这个整体。接线约 7350 行在 `backend/deskpet/orchestration/`，其中外部应用也必须有的约 2000 行：建模型连接、选计费器、规划世界、拼装与启动、驱动循环、沙箱探测、建任务门口检查。别的 Python 应用只装 SDK 就没有这些，也没有说明文档。

## 二、方案

1. SDK 加公开包 `agent_orchestrator.host`：
   - `OrchestrationHost`：`open(root, principal=, model=ModelConfig, tokenizer_path=, settings=HostSettings, auto_mode=, publish_dir 在 settings 里, models_dir=, notify=)`；也可注入 `provider= / counter=`（测试替身或别的接法）。
   - 拼装顺序照后端：实例锁 → 部署验收门 → 发布连接器 → 沙箱探测 → 部署策略 → 原生执行池 → 用户任务部署 → Orchestrator → 门面。
   - 操作：建任务（含附资料）、资料三动作、列表／详情／事件／审批、授权规划、回答提问、确认完成要求、改要求、提交操作、取消／接管／裁决、评论、取产物、状态、全局月配额。
   - 驱动：`run_forever`（常驻，含退避、重建、降级）、`run_until_settled`、`run_once`／`drain`。
   - 门口检查与后端一字不差：空目标／空要求、密钥、`pytest:` 要沙箱、`action:` 要连接器、补 `file:` 来源、默认运行档与预算（同幂等键重试沿用原任务的）。
2. 随之进 SDK 的：`host/settings.py`（模型配置、运行参数）、`host/provider.py`（提供方与计数器选择）、`host/instance_lock.py`（跨平台文件锁）、`host/script_runner.py`（沙箱脚本执行器，原 `skill_script_runner.py`）、`host/embedding.py`（BGE-M3 向量端口，原 `native_plane.py`）、`host/tokenizer.py`（钉死分词文件的取得与核对）、`deployment/goal_world.py`（规划世界，按 `domain` 加前缀；桌面传 `desktop`，类型名与原来逐字相同）。
3. 证明：SDK 测试 `tests/orchestrator/host/`（脚本模型跑完一局、门口检查、实例锁、无计数器、发布目录）；例子 `examples/orchestration-host/demo.py --scripted`；独立验收：仓库外空项目只装 wheel，真实 DeepSeek 跑完一个任务。
4. 桌面端后端改用同一入口（同一件事只留一条路径）：`OrchestrationService` 只补桌面自己的——配置段读取、提供方链读取、钉版核对与部署清单写盘、进度推送、通知存档、存储用量、界面投影、诊断、技能目录、执行图读写、保证通道读；删 `provider.py`、`runtime_profile.py`、`hierarchical.py`、`native_plane.py`、`skill_script_runner.py`、`lock.py` 与 `settings.py` 的大半。
5. 发版 opt.194，独立核验，真机一局。
