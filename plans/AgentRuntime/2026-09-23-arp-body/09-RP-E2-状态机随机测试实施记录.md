## 2. 抓到的问题

- **同创建键在会话清理后再创建会"mkdir 复活"**（种子 11，第 61 步：销毁 → 若干步 → 重启 → 同键创建 → 账本说 PURGED 但目录又出现了）。原因：`create` 对已存在的绑定走重放路径，会话 id 由 (agent, root, 创建键) 确定性推出，C1 步无条件 `write_marker` 到 `sessions/{session_id}`，于是把 marker 又写进了已清理的目录。这违反 R08/RV_R1 的"不能 mkdir 复活"。修法见 §1。
- 账本口径修正一次（种子 59）：一开始账本只允许在显式 tick 后推进 DRAINING/PURGING，但运行时的后台泵每 50–250 ms 调一次 `arp.tick()`，任何 await 之间都可能推进；这是设计行为不是缺陷，账本改为对这两个状态只允许前进。

## 4. 独立核验

opus 5.5 子代理按"只报阻断级"审阅（1 轮，自带一次性探针，未改文件），回 2 条阻断，均已修复并补入回归：

| # | 发现 | 处置 |
|---|---|---|
| 1 | 守卫把所有非 ACTIVE 都拒了，QUARANTINED（可恢复的活会话，目录与 marker 都没动）同键重放本应返回同一 Agent，现在被拒 `SESSION_NOT_ACTIVE` | 只拦"有 destroy 身份或 DRAINING/PURGING/PURGED"的会话；回归测试加隔离后重放断言 |
| 2 | 守卫按创建键全局查（会话表的创建键是全局唯一，而创建身份是按 owner 划分的），另一个 owner 用同名键创建时会在错误里看到别人的会话 id 与状态，违反"他人 Agent 看起来不存在"的规则 | 改按本 Agent 自己的会话 id 查（正是会被写的那个目录），错误只带状态。会话表创建键全局唯一是更早的划分问题，另记 |

另核对：崩溃窗口恢复不受影响（会话行在 C3 一个事务里插入并转 ACTIVE，C0–C2 恢复时行要么不存在要么 ACTIVE）；除 `write_marker` 外只有 `open_partition` 会建目录，其调用方都先核 ACTIVE 或要求 QUARANTINED；把守卫去掉后回归测试与 5 个种子都失败，说明测试确实在测这件事；账本对 ACTIVE 槽位要求精确相等，ACTIVE→PURGED 无销毁会被抓到。
