## 0. 一句话

分八个阶段把代码整理干净。每一步只做一种改动。每一步改完先证明功能没变，再做下一步。

## 2. 原则

1. **只改形状，不改行为。** 整治期间不加功能，不改业务逻辑。
2. **一步一种改动。** 一个提交只做移动、或只做改名、或只做删除。不混做。
3. **先有安全网，再动刀。** 每阶段先补能证明"没变"的测试，再重构。
4. **开发期不留旧路径。** 搬走的代码不留转发层。同一片内把调用点改完。
5. **判断归 LLM，约束归 Harness。** 重构不新增硬编码规则，不替代模型判断。
6. **可单独回退。** 每片一个提交。改坏不用 git checkout 恢复，先 cp 备份。

## 3. 禁区（整治期间不碰）

改了这些会让线上执行池起不来，或让验收门不过：

- 工具说明文字、已发布模板文字、并发默认值。这些是执行池的准入身份。
- 数据库表结构、迁移脚本。
- SDK 部署清单、版本号文件。发版脚本会校验字节。
- 哈希输入字符串。例如 `harness-inspector-v3:` 这类前缀。
- 事件名、状态码、决策类型等字面量。
- 密钥与配置文件读取逻辑。

执行办法：阶段 0 把这些字面量和文件列成清单。每片提交前跑一个脚本，比对清单里的字面量没变。

## 4. 验证手段（每片必跑）

| 手段 | 作用 | 耗时 |
|---|---|---|
| 导入烟雾 | 逐个导入所有模块，抓循环依赖与漏改 | 1 分钟 |
| 禁区比对 | 第 3 节清单的字面量逐条 grep 比对 | 10 秒 |
| 相关测试 | 只跑改动文件对应的测试，加新调用点所在函数的测试 | 几分钟 |
| 启动烟雾 | scripts/smoke_test_app_startup.py | 2 分钟 |
| 服务注册快照 | 启动后导出注册表键集合与注册顺序，比对基线 | 1 分钟 |
| 独立核验 | 子代理一轮，只报阻断级 | 10 分钟 |

每阶段结束加三项：

- **全量回归**。需用户授权。本计划按阶段申请，共 4 次（阶段 2、3、5、8 之后）。
- **发版**。SDK 有改动时走 release_sdk_opt.sh 发 opt 版本。Host 钉版跑 64 条钉版测试。
- **数据副本启动 + 真机一局**。副本放原路径。停后台按端口找 PID。

### 阶段 3：函数内导入与循环依赖（2～3 天）

## 8. 分工

- 核心重构由主会话亲手写。
- 子代理只做两件事：独立核验（每片一轮，只报阻断级）、体力活（脚本跑批、分类统计）。
- 阶段 1、3、4 的按目录分批工作可开并行车道。按目录分车道，用工作树隔离。合并前跑导入烟雾。
- 子代理默认 opus 5.5。并行写代码的车道可用 Fable 5.1（用户 10-06 已授权）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 搬函数后执行池起不来 | 禁区比对脚本每片必跑。工具说明与并发默认值不碰 |
| 删未用导入删掉了有副作用的导入 | __init__.py 与带注释"副作用"的导入手工看。导入烟雾兜底 |
| 上提导入触发循环 | 导入烟雾当场抓。按环处理，不留延迟导入 |
| 改 SDK 源码打断在跑的长跑 | 改前确认无在跑的局。按 PID 停跑 |
| 变异后旧字节码残留 | 每片提交前清 __pycache__ |
| 整治与功能开发撞文件 | 整治期间功能开发避开当片的目录。每片开始前通告目录 |
| 全量回归跑太久 | 只在 4 个节点跑。其余时间只跑相关测试 |

## 10. 需用户拍板

1. **开工时间。** 建议现在开工，先做阶段 0 与 1。这两阶段零风险。
2. **全量回归授权。** 本计划需 4 次。一次授权 4 次，还是每次单独申请。
3. **证据目录移出 git。** 建议移出且不重写历史。仓库会继续带着历史体积。重写历史要所有检出重新克隆。
4. **整治期间功能开发。** 建议穿插进行，按目录错开。不建议停功能开发。

其余技术取舍不问用户。拿不定的按本仓库惯例交独立核验子代理裁决并记录。
