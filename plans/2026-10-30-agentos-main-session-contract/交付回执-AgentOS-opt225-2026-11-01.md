## 3. 合同接口 → 实际公开接口（逐项映射）

合同 §2 要求"本文合同到实际公开接口的逐项映射"。完整名词对照见《交付-命名映射表-草稿-2026-10-31.md》，这里只列 §5.2 操作面与 §5.3 类型。

### 3.1 操作面（§5.2）

| 合同拟议操作 | 实际公开接口 | 差异说明 |
|---|---|---|
| `open_session` | `OrchestrationHost.open(root, principal, model, settings, authorization_port=..., ...)` → `await host.open_session(session_id)`；独立程序也可 `Session.open(...)` | 幂等；重开不调模型；配置不符报 `session_config_frozen`，旧库报 `incompatible_store_version`；`principal` 只能省略或与宿主相同 |
| `put_goal / finish_goal` | `session.put_goal(spec, command_id=, expected_version=)`、`finish_goal(goal_id, outcome, command_id=, expected_version=, basis=)`、`exclude_result(event_id, reason, command_id=)` | 只对可信宿主公开，模型没有 Goal 命令；每根会话同时一个未收口 Goal；收口只核结构事实，`succeeded` 要非空依据 |
| `create_child` | `await session.create_child(child_key, command_id=, purpose=)`；模型命令 `create_child(child_key, purpose?)` | 子身份 `<父>_c_<key>`，深度 1；权限只能收窄；创建不执行业务 |
| `submit`（异步受理） | `await session.send(text, key=, wait=False)` → `{"status":"accepted","input_id","turn_id"}`；追加指令 `await session.child_send(child_key, text, command_id=)`（`directive=next_turn`） | **不另开 submit**，`send` 扩展为可选异步受理（第 5 节第 4 条）。不收合同的 `InputEnvelope` 结构：`goal_ref` 由 SDK 从当前 Goal 冻结，`result_event` 只能由 SDK 内部产生，`grant_ref` 挂在 Goal 上 |
| `delegate` | 模型命令 `delegate_task(goal, success_criteria, sources?, reason?, child_key?)`；宿主没有直接委派的公开方法，委派由模型在主会话回合里发起（用户一句话，或 `child_send` 给工作会话下一句） | **不另开 delegate**，`delegate_task` 扩展为可指定工作会话。每会话一个在途委派，超限报 `busy` |
| `capabilities / receipt` | `session.capabilities()`、`session.command_receipt(command_id)`（`child_send` 的在 `child.command_receipt`） | 都不调模型；回执含 `command_id / request_hash / status / session_id / event_seq` |
| `snapshot / list_children / task` | `children()`、`child(key)`、`tasks()`、`task(id)`、`queued_inputs()`、`continuations()`、`inbox()`、`history()`、`budget()` | 全部校验归属；任务带 `child_key` 与冻结 `goal_ref`；不调模型 |
| `events` | `session.events(after=seq)`（异步迭代，补读持久事件 + 当前正文片段） | 只订阅主会话即可：子结果（`result_ready`）与子提问（`needs_response`）都镜像到父事件流并带 `child_key` |
| `respond` | `session.respond(request_id, decision, version, **fields)` | 一条路径覆盖父与子任务；版本错配报 `stale_request`；非人身份报 `permission_denied` |
| `interrupt` | `await session.interrupt()` | 只停当前文字回合 |
| `cancel` | `session.cancel(target_kind ∈ goal / delegation / session_tree, target_id, *, command_id, expected_version=, reason=)`；模型同名受限命令只限本树 | 回执 `cancel_requested` + 屏障序号；屏障前交出去的如实标 `handed_off / completed / unknown` |
| `close / archive` | `await session.close()`（只放手，任务继续）；`session.archive(command_id=)`（有活报 `active_work`） | 合同的"active close 拒绝"落在 `archive`；归档后再开报 `not_found_or_forbidden`，不删数据 |
| `start / recover / shutdown` | `OrchestrationHost.open` 即恢复；`session.recovery_report()`；`await host.close()` | 重开按 `children` 行重开子、续读游标、补齐未完成续办；不重发自然语言目标 |

### 3.2 类型（§5.3）

| 合同类型 | 实际 | 状态 |
|---|---|---|
| `GoalSpec` | `put_goal` 的字典：`goal_id / objective / completion_criteria[] / stop_conditions[] / budget / grant_ref / policy_revision`；`root_session_id` 与 `goal_version` 由 SDK 填 | 有 |
| `TaskSpec` | `delegate_task` 参数 `goal / success_criteria(1～12) / sources(≤8) / reason`，连同 `goal_ref` 冻结进委派 | **部分**：没有 `requested_capabilities / effect_policy_ref / output_schema`。任务里的副作用统一走连接器申请单→审阅→审批，不按任务文字扩权；产物由审阅员按成功条件判 |
| `AuthorizationRequest / AuthorizationDecision` | `agent_orchestrator.host.AuthorizationRequest`（SDK 注入 principal、根/当前会话、`goal_ref`、委派、动作、目标、参数摘要、`grant_ref`、`policy_revision`、`operation_key`）；`AuthorizationDecision.allow(constraints, revision, expires_at) / needs_approval(request_ref) / deny(reason)` | 有。端口异常或 5 秒超时 = `authorization_required`（可重试），不推导 allow |
| `RecoveryReport` | `recovery_report()` 返回 `store_version / owner_generation / resumed_refs / waiting_approval_refs / held_refs / unknown_effect_refs / rejected_refs / reasons` | 有 |
| 事件信封 | `{"schema_version":1,"event_id","session_id","seq","kind","turn_id?","delegation_id?","mission_id?","request_id?","child_key?","payload"}`，`kind` 表见 §2d | 有（文档表，没有单独的 JSON Schema 文件，见第 6 节） |

### 3.3 错误合同（§5.4）

合同列的 18 个码在 `agent_orchestrator.host.session_ledger.ERROR_CODES` 里全部有：`not_found_or_forbidden / invalid_argument / idempotency_conflict / stale_version / session_busy / capacity_exceeded / budget_exhausted / authorization_required / authorization_revoked / request_expired / cancelled / active_work / unsupported_capability / incompatible_store_version / owner_conflict / cursor_expired / effect_unknown / provider_unavailable`。另有 `busy`（本会话已有在途委派）、`permission_denied`、`stale_request`、`session_config_frozen`、`session_closed`。公开错误 `SessionError.public()` 给 `code / retryable / safe_message`，不把底层异常文字交给模型。

## 5. 五处没有照合同做的地方

| # | 合同要求 | 我们的做法 | 原因 | AgentOS 怎么办 |
|---|---|---|---|---|
| 1 | §11 / SDK-15：store 前向迁移或回退、旧 wheel 可读旧数据、迁移失败可回原版本 | **不做迁移、不做回退。** 只做能力发现与版本探测：`capabilities()` 报协议 / 配置版本与能力集；旧库用新轮子打开报 `incompatible_store_version`，不原地损坏 | 2026-10-30 定继续开发期，对外不承诺数据兼容 | 新版本用新数据根；旧库留给旧轮子读；回滚 = 换回旧轮子 + 旧数据根 |
| 2 | §5.2：新增原生控制命令 | 做了，但控制命令是执行池身份的一部分：聊天池 `chat-v2` → `chat-v3`，旧会话库起不来 | 同上，开发期不留双版本 | 随第 1 条一起换数据根 |
| 3 | I2 / SDK-07：跨 principal 隔离、家庭成员不串 | **一个 SDK 实例 = 一个 Agent 个体，现阶段只服务一个人**；宿主上的当事人就是"这个 Agent 服务的那个人"；`open_session` 传别的当事人报 `permission_denied` | 2026-10-30 定；多人共用一个 Agent 留到以后（届时把人的身份下放到会话层） | 每个成员一个宿主实例、一个数据根；跨成员隔离由此自然成立 |
| 4 | §5.2：`submit` 与 `send`、`delegate` 与 `delegate_task` 并存 | **不并存。** `send(wait=False)` 就是异步受理，`delegate_task(child_key=...)` 就是指定工作会话的委派 | 同一件事只留一条路径 | 按第 3 节映射调用 |
| 5 | §6：模型请求"恰好一次" | 不承诺物理恰好一次；承诺同 key 不重复结算、费用可多算不可少算、不明费用保留可追溯 | 线路取消后结果不可知，只能记"不明" | 以回执与计量账为准对账 |

其余不做的事（深度 1、不改在跑任务 `steer_running_mission`、跨宿主会话树、运行期加工具不重开宿主、主 / 子会话读任务知识库）见《交付-不支持项-草稿-2026-10-31.md》。

## 7. 给 AgentOS 的接入提示（对 AO-01～08 的 SDK 侧说明）

1. **AO-01**：产品 chat → `open_session(chat_id)`，一个成员一个宿主实例（第 5 节第 3 条）。旧任务历史在旧数据根，不自动重放。
2. **AO-02**：服务端持有 `session.send(text, key=, wait=False)` 返回的 `input_id`；SSE 只订阅 `events(after)`；HTTP 断开不影响 SDK。
3. **AO-03**：不要自己 await 父阻塞：模型用 `create_child + delegate_task(child_key)` 开工作会话，结果自动回流；追加输入 `child_send`。
4. **AO-04**：实现 `AuthorizationPort.decide`，可信字段由 SDK 注入；审批用 `respond(request_id, "approve", version)`；业务效果经 `EffectLedger` 对账。
5. **AO-05**：实现 `ContinuationPolicy.decide` 返回 `enqueue / hold / deny`；`HostSettings.continuation_*` 配合并窗口与轮次上限；Goal 用 `put_goal`。
6. **AO-06**：任务列表 `tasks()`（带 `child_key`）；停止回复 `interrupt()`、取消子 `cancel("delegation", id)`、取消目标 `cancel("goal", id)` 三件事分开。
7. **AO-07**：运行中 Mission 配置冻结；换模型用新会话号或新数据根，`capabilities()` 先探。
8. **AO-08**：钉第 1 节的轮子与 SHA；新旧数据根隔离；回滚 = 旧轮子 + 旧数据根，新根里的任务不送旧版本重跑。
