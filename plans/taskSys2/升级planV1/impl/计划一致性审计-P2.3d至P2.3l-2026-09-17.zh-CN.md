## 1. 根评审与决议

### 1.1 计划条款

- **§9.1 决策表**（主文档 560–569 行）：诊断 → 计划动作九行。禁止静默重试。根验收 REJECT 落在「内容缺陷 / 方法前提被推翻 / 重复无进展」，不是「再问同一句」。
- **§8.1 / §8.2**：方法全部叶子通过 **不** 自动满足父目标；`ACCEPT` 与 `GoalResolution` 是两步；Verifier 提交审阅，Commit 再生成 Resolution。
- **§13 v1.4 用途与账户**（770 行）：`MISSION_FINAL → Mission 账户（现有 Mission Judge）`——映射表写的是 **一次**。`COMPOSITION → 父 compound Task 账户`。
- **AER §3.3 I05**：「技术调用成功不是用户目标满足」。§25.1 采纳表把它与 I01–I04、I07 并列。实施侧把派生不变量写成「系统永不自填 PASS」（第三部分 a；`root_review.record_review`）。
- **AER I02**：审阅过程结束不是审阅通过。**AER I07**：未执行/错误的必需检查不等于 PASS。
- **AER §5.1–5.4**：`ReviewPurpose` 含 `COMPOSITION` 与 `MISSION_FINAL`；独立 Reviewer；ACCEPT 仍是候选；禁止重复抽样直到 PASS。
- **AER §6.2 / 附件 TG 设计 §13 / 实现稿 §10**：compound 满足 = 获准方法 ∧ 必需子义务当前满足 ∧ **组合有合法独立审阅** ∧ 原要求覆盖。
- **主文档 §6.3** 是 MethodContract 字段，**不是**「compound 从不被自己评审」。AER §6.3 是「发送不等整个 Mission 完成」的死锁条款。`leaf_acceptance.py` 顶部把「never by a review of its own (§6.3)」写进模块注释，是 **实施侧对错章节的引用**，不能反证计划。

### 1.2 实际实现

**MISSION_FINAL 评审协调器**（P2.3c 第三部分 a，本范围依赖）：`orchestrator/root_review.py` 裁 `ReviewPackage(MISSION_FINAL)` → 独立 `role=root_reviewer` 服务意图（账户 `ReviewAccount.MISSION`）→ `parse_critic_verdict` 落 `ReviewRecord` → 既有根 Resolution → 既有 Mission Judge `_judge`。`record_review` 缺判写 UNKNOWN，`refuse_self_contradicting_accept` 拒「PASS 却有准则 met=false」。P2.3h 测试钉「证据齐全也不能自成 Resolution」。

**P2.3d D5-A**：blocker finding → `PlanningRejected{root_review_rejected}` 重开一轮 Planner（默认 `max_root_review_repairs=1`）。非 blocker 不重规划。P2.3j 核验后上限改为 **每 Mission 累计**，被拒方法跨修订累计。

**P2.3h 包结构**：请求 JSON（即评审员看到的正文，进 `content_hash` / `context_version`）增加 `excerpt`、`covers_root_criteria`、`covered_by`、`carries_root_criteria`、`accepted_at_requirements_revision`、`requirements_revision_semantics`。存库 `ReviewPackage` 契约字节未改。`requirements_revision` 改名是呈现，不改 RequirementsRevision 身份。

**P2.3k N3**：分层 `_evaluate_criteria` 不再走 legacy `merge_accepted`（`dependency_ids=()` 会把多叶同路径打成冲突）。裁决树从根决议贡献 + 端口索引读；linked 端口产物永不丢弃（核验 P1-1）。新事件 `ArtifactMergeNotApplicableUnderHierarchical`。legacy `merge_accepted` 两处调用字节未动。

**P2.3l N7**：非根 compound 在 `composition_review` 由 `CompositionAcceptanceAssembly` **不调模型**、按子叶 CURRENT Acceptance 机械形成子 `GoalResolution`。系统写入 `ReviewRecord(reviewer_agent_id="composition-reviewer", official=True)`，verdict 在全部准则 PASS 且 gating 子验收齐全时为 ACCEPT。核验 P1-2 已删「任意 PASS 即覆盖」fallback；缺 `leaf_criterion_id` 映射 → UNKNOWN + `composition_criterion_uncovered`，不形成 ACCEPT。共享义务的非根决议不 SATISFY 根 duty。`c-composition` 在无 coverage 时仍因「有子验收」写 PASS（核验稿残留 P2）。

## 2. 方法合成与规划梯子

### 2.1 计划条款

- **§7.2**：前提已证真 → 候选实例；未知 → 取证或受限假设；已证假/冲突 → 拒绝或仲裁；**没有适用方法 → MethodSynthesizer**；结构/类型/安全/语义检查后 Commit。
- **§7.3**：四种来源走同一注册协议；状态由 registry 写，Planner 不得自行晋级；P2 只到 `TRIAL_ADMITTED`；`ADMITTED` 被反证 → `SUSPENDED`（P8）。
- **AER I18 / §25.1**：UNKNOWN/CONFLICT 不用于安全前提放行。
- **§18.5 LLM 合同**：Planner 与 MethodSynthesizer 经标签块 + codec；**格式错误走既有 BlockError 有界修复，不另开请求**；**超时/UNKNOWN 不另开新请求洗掉原身份**。
- **§6.3**：注册状态及准入回执由系统填写，模型不能自填 `ADMITTED`。

### 2.2 实际实现

- **P2.3d D2b**：同一观察器对同一命题 `OBSERVED` ≥ N 次（默认 2）仍 UNKNOWN 时，该 `NEEDS_EVIDENCE` 视同可被别的方法绕开，准入合成。测试钉「饱和永不结算命题」。审阅后：合成准入会 publish 进 store、梯子等待在途合成、每条准入方法买一级。
- **P2.3d D5-B**：未细化 nested compound 每修订一轮 Planner，判据 `adopted_instance_for is None`（不用 `NEEDS_REFINEMENT`，遵守 §18.5 约束 4）。
- **P2.3g**：`method-synthesizer-v2` 逐字段对齐 codec；`planner-hierarchical-v4` 删「改为输出 `<method_proposal>`」；codec 读不懂 → 同锚序号 +1 再问一次（`MAX_SYNTHESIS_ASKS=2`，新意图、同账户如实计费）；**宽容别名归一明确不做**。Planner 空 operations → `no_applicable_method`（在进 codec 之前解释，契约未改）。
- **P2.3i**：把 `RejectionCode` 划分为可修正/不可修正（import 时断言划分整个枚举）。可修正含 `PORT_UNAVAILABLE` / `ROOT_COVERAGE_GAP` 等引用形状类；不可修正含 `MODEL_CLAIMED_STATUS`（边界）、`UNKNOWN_PREDICATE`（包无谓词清单，I18）、`UNBOUNDED_RECURSION` / `SIZE_BOUND`。可修正拒绝记 `MethodSynthesisReplyRejected` 后再问一次。
- **P2.3j**：修复轮包按 open goals ∪ 被拒 occurrence 取库；`compile_proposal` 接受「一个 refine + 至多一个 retire_method」；系统置 `REQUEST_STOP_THEN_RECONCILE`。核验后：不得重采用被拒方法、上限 Mission 累计、retire 只限被拒实例且无在途 Attempt。声明无方法后带 `review_feedback` 开合成；候选数排除被拒方法。

### 2.3 判定

| 点 | 判定 | 影响 |
|---|---|---|
| D2b 饱和 → 合成 | **一致** §7.2「没有适用方法」；I18 未把 UNKNOWN 变成 TRUE | N=2 是计划未覆盖的阈值 |
| 准入仍走 registry / 不自填 ADMITTED | **一致** §7.3 / §6.3 | `MODEL_CLAIMED_STATUS` 不可修正，正确 |
| Planner 永不提方法 | **计划未覆盖（收紧）** | §18.5 C8 原本允许 Planner 出 `method_proposal` 块；收紧不破坏不变量 |
| P2.3g/i 第二问（新意图） | **部分偏离** §18.5「不另开请求」 | 身份上同合成轮不同 ordinal；第二次调用计费诚实。不是洗掉原身份，但是字面「不另开请求」已破 |
| P2.3i 可修正清单 | **一致** 准入边界（不重问能力/谓词/策略界限） | `ROOT_COVERAGE_GAP` 可修正 = 允许改覆盖链接，仍过结构检查，未让模型自填状态 |
| P2.3j retire+refine / 被拒历史 | **一致** §9.1「暂停该 MethodInstance，选择替代方法」+ 重复计数不重置 | 退的是实例不是合同；未做 P8 的 `SUSPENDED` |
| 修复轮再开合成 | **一致** §7.2；未越 `TRIAL_ADMITTED` | 真实模型「REJECT→换方法/合成→ACCEPT」未跑 |

### 2.4 建议

- 0.12.2 不要写「格式错误只走 BlockError、不另开请求」——实际对合成器是「最多两问、第二问新意图」。
- 谓词清单进 `SynthesisRequest`（P2.3g 未做）做完后，可重新评估 `UNKNOWN_PREDICATE` 是否可修正；在此之前保持不可修正。
- P2.3j 核验残留 P2-1（拒绝事件键不带 round）与 P2-5（已细化 occurrence 不再取证）记下一版，不挡发布，但会影响「换方法后仍 NEEDS_EVIDENCE」的梯子。

## 3. 证据与谓词

### 3.1 计划条款

- **§6.6**：冲突 → CONFLICT；缺/过期 → UNKNOWN；只有注册域提供完整封闭快照才允许由缺失推 FALSE。OPEN 不做 negation-as-failure（C28）。
- **I18**：UNKNOWN/CONFLICT 不放行安全前提。
- **D2b 实施意图**（journal 第四部分）：OPEN 谓词真否定观察仍是 UNKNOWN，取证活锁 → 饱和后改走合成，不结算命题。

### 3.2 实际实现

- D2b 与 `test_saturation_never_settles_the_proposition`：**一致**。
- 本范围未改观察器 OPEN/CLOSED 极性。CLOSED 权威否认、OPEN 缺失=UNKNOWN、策略拒读=UNAVAILABLE（P2.3c 第三部分 c G8）仍在。
- **P2.3k N2**：`RootReviewRequest` 增加 `mission_goal` / `goal_parameters`（进 hash）。`root-reviewer-v3` 硬约束 1c 原文：「解释它们时以 mission_goal 为准，二者冲突时按 mission_goal 判断准则是否被满足」；对「named failing test 由红转绿」且基线已绿 / 用户目标未点名失败测试，**改为**要求覆盖用户目标的测试由红转绿或新增并通过。seed 的 `c-test-passes` 措辞 **不改**。

### 3.3 判定

| 点 | 判定 | 影响 |
|---|---|---|
| 四值谓词 / OPEN-CLOSED / D2b | **一致** | 饱和只推动梯子，不改 TruthValue |
| N2 把包带上用户目标 | **计划未覆盖（正当）** | AER §5.2 审阅锚应含原要求；用户目标原文本应在 RequirementsRevision 里，包补字段不改准则身份 |
| N2 v3「冲突时按 mission_goal 判断准则」 | **偏离** | 计划口径：准则来自 RequirementsRevision / 方法对 goal signature 的 `coverage_criteria` 与 `criterion_links`（§6.3、AER §4.1–4.2）。**解释权从冻结准则转到提示词对用户原话的临场改写**，触碰 I06「原始要求不能暗中放宽」 |
| seed 措辞不改 | **一致（有意）** | 对真红测试题（C3）仍是更强要求；Host 把实现题包装成 `code.fix-failing-test` 是另一半（诊断已写） |

N2 **确实改变了**「准则以 goal signature 为准」的计划口径：goal signature 的 statement / evidence_requirement 降为「方法作者模板措辞」，满足与否以 `mission_goal` 为准。这能降低 C2/C4 上不可满足字面要求导致的误 REJECT，也引入「评审员按用户原话改写准则、Mission COMPLETED 而隐藏评分器仍红」的 §21.5「错误宣布完成」风险。

### 3.4 建议

- 计划对齐的修法在 **Host**：C1/C2/C4 换签名或指向真红测试（诊断 D2a），不是让评审员改写准则。
- 若 0.12.2 坚持 N2 v3：发布说明必须写「根评审解释权以 `mission_goal` 为准，goal signature 模板在冲突时让位」。不得再写「准则以 goal signature 为准」。
- 下一版：`code.implement-contract` 一类新签名，而不是继续用 v3 1c 当通用解释器。

## 4. 预算与 provider

说明：主文档 **§12 是 Context**，不是账本。预算不变量在 **§6.1**（账户树、UNKNOWN 预留不因计划退出自动释放）、**§10.3**（统一消费、未知费用保守处理）、**§13 v1.4**（用途→账户，保证 §21.5 守恒不漏计）。本项按这三处审，并注明用户口中的「§12」应理解为账本条款而非 Context 章。

### 4.1 计划条款

- **§6.1**：额度授权、预留、受保护尾额、已消费是不同状态；同一笔不能父子重复计入；**计划退出不自动释放 UNKNOWN 对应预留**。
- **§10.3**：LLM 自报费用不进账本；不得把配置窗口当成必然消费；不能删除对未知实际费用的保守处理。
- **§18.5**：超时/UNKNOWN 不另开新请求洗掉原身份。
- **AER §14.3 / 主文档 §14.3 v1.4**：空 ReconciliationResult 不必然 NOT_APPLIED_FINAL；只有服务端证明未应用或同 key 去重可证时才允许重交接。不确定结果要求人工，不自动重发。
- **I13**：已发生费用即使结果过期也必须记录。

### 4.2 实际实现

- **P2.3e**：在途合成意图不计进展 + `run()` 有进展周期 `sleep(0)`。不改账本。
- **P2.3f**：分层服务意图（planner/synthesizer/root_reviewer/critic）在 `min(stall_seconds, 300)` 后 `rehandoff_service_intent`（同 subject/预留，新 `creation_key`），上限 1。再次未知按角色收口。当时口径：旧执行器 invocation 保持 UNKNOWN、**不导入**；只有答过的执行器进 `imported_usage`。
- **P2.3l N5**：重交接前 / give-up 时 `release_held_grants`（grant → RELEASED，SDK invocation 仍 UNKNOWN）。`recover()` 对已改写 intent 不再 `authority_rejected`。核验 P1-1：UNKNOWN 写入 `imported_usage.unknown=1`；`settle_known` 只结算已知；未知 token 不进 settled。守恒：`remaining+reserved+settled==pool`。0 token 的 `provider_outcome_unknown` 停机 `runtime_unavailable`。

### 4.3 判定

| 点 | 判定 | 影响 |
|---|---|---|
| 第二问 / 重交接如实计费 | **一致** §10.3 | 不把失败写成 0 而不记账 |
| P2.3f 无核对即重交接 | **部分偏离** AER §14.3、§18.5 | 针对的是 LLM 服务意图不是 OperationEnvelope；300s+1 次有界。若第一次其实到达模型，可能双记一次调用。计划要求的是人工/核对，不是自动重发 |
| P2.3l 释放 UNKNOWN **grant** | **部分偏离** §6.1 字面 | 预留槽被释放以便下一次 admission；用量 unknown 行留账（P1-1 后守 I13）。「不释放 UNKNOWN 预留」被改写成「不抹掉 UNKNOWN 用量、但释放 grant 槽」 |
| 两次 MISSION 调用 | **部分偏离** §13 映射；守恒仍可成立 | 见 §1 |

### 4.4 建议

- 0.12.2 账本口径写成：`remaining+reserved+settled==pool`；unknown 行独立计数、不进 settled；grant 在重交接时 RELEASED。不要写「UNKNOWN 预留永不释放」。
- 下一版：服务意图 UNKNOWN 走 AER ReconciliationResult（或显式「confirmed-not-started」证据）再重交接；与业务 Operation 的三段交接分开。

## 5. 叶子验收与只读

### 5.1 计划条款

- **§18.5 / ADR-01**：`TaskSemanticBindingV1` 把 form、Obligation、GoalSignature、MethodInstance 绑到既有 task_id；新 Mission 缺绑定是损坏。

### 5.2 实际实现

- **P2.3d D3**：端口集合 = 被 DATA 消费 ∪ 被 `criterion_links` 引用（含终结步）。四处生产读者共用 `output_ports_in_revision`。

- **P2.3k N4**：`read_only_leaf`（side_effect ∈ {none, external_read} 且无写能力且无 resource_writes）默认不加 `code_test`；叶子自带 `pytest:` 仍加；声明策略只收窄。核验后：**criterion_links 指向的叶不豁免**（verify 仍含 code_test）；收集处 `read_only_leaf_rewrote_workspace` 强制只读。

### 5.3 判定

| 点 | 判定 | 影响 |
|---|---|---|
| 叶子准则按 criterion_links | **一致** §6.3 覆盖映射；修正了「每叶盖父准则」的先前偏离 | `c-leaf-verified` 是计划未覆盖的兜底，statement 已写明「不给根目标背书」 |

### 5.4 建议

- 「解释步必须绑补丁」若要硬拦，走契约 `RejectionCode`（journal 已待议），不要继续只靠 v5 提示词。
