# 第 5 块：逐字输出——一页方案

日期：2026-10-21

## 现状

- 提供方本来就是流式收的（SSE），但只在流结束后交一份回执；中间的正文片段没人能看。
- 回执、用量、取消都以"一次模型调用"为单位，这套不动。

## 做法

一条"输出流"，片段只是预览，终稿以持久记录为准：

1. **提供方**（`OpenAICompatibleProvider`）：流里每到一段**用户可见正文**（`content`）就调一次 `delta_sink(request, text)`；思考（`reasoning_content`）与工具调用参数不发。回调抛错只记日志，不影响这次调用。
2. **路由**（`runtime/delta_router.py`，公开）：按请求号里的运行号找订阅者。`subscribe(callback, run_id=None)`：按运行或全局；装在提供方上能穿过回退 / 边际学习装饰器。外层再套一层 `StreamSignals`：一次模型调用结束发 `end`（带 finish 原因、有没有工具调用），抛错发 `error`（错误码）。
3. **事件格式（v1）**：

```json
{"v": 1, "kind": "piece" | "end" | "error",
 "scope": "chat" | "mission" | "unknown",
 "run_id": "...", "generation": "<请求号>", "seq": 3,
 "text": "片",                       // piece
 "finish": "stop", "tool_calls": 1,  // end
 "error": "provider_timeout",        // error
 "session_id": "...", "turn_id": "...",            // scope=chat
 "mission_id": "...", "subject_id": "...", "view": "work"}   // scope=mission（网关绑定能对上时）
```

   - `generation` = 一次模型调用的请求号；`seq` 在一次 generation 里从 1 递增。换了 generation 就是新一次生成，消费端从头拼，**不会把两次生成拼在一起**。
   - 去重键：`(generation, seq)`。
4. **聊天**：`host.chat(body, on_delta=回调)` 只转本回合的 `piece`（`{session_id, turn_id, text}`），回执里 `first_output_ms` = 第一段正文到达的时间。
5. **任务**：`host.output_stream.subscribe(回调)` 全局订阅，片段带 `mission_id` / `subject_id`（执行者绑定了工作区时能对上；规划器与审阅员的调用只带运行号）。
6. **终稿与重连**：片段不落盘（保留期 0、无分页）。断线重连后读持久记录：聊天读 `chat_history()` / 回执 `text`；任务读快照与产物（`snapshot()`、`artifact_read()`）。审阅否决或重写的尝试，它的片段只是草稿，终稿只认验收通过的产物。
7. **事件格式定版本**：`v: 1`；加字段不升版本，改字段含义才升。

## 不做

- 不存片段、不重放片段；不做服务端分页。
- 思考内容不外发。

## 验收

- 流解析器：正文片段按顺序回调，思考与工具参数不回调。
- 真流（假传输）：`delta_sink` 收到的片段拼起来等于回执正文。
- 路由：能穿过装饰器装到最里层；坏订阅者不影响调用；按运行号分发；`end` / `error` 信号与 `seq`。
- 聊天：`on_delta` 顺序正确、`first_output_ms` 有值；不订阅时为 None。
- 真实模型：Sol 上一句问答的首字时间与总时间（收尾 3 局之一）。
