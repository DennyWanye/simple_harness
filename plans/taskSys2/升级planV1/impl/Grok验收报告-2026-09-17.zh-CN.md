### 1.1 G7 判定说明（重要）

`selftest_runner.py B` 的打印文本仍是 `SDK gap G7 (OPEN)`。这是该自测里**探针文本过时**，
不是缺口未修：它的 `open` 标志比较的是两种 git 拼法（`git rev-parse --verify --quiet -- <ref>`
与不带 `--` 的写法）的退出码，而 git 的这个行为与 SDK 改动无关，**永远**会呈现差异。
真正的测量在同一段输出里：`code.regression-commit-known observed TRUE` —— 观察器现在读得到
`refs/bisect/bad`。结论：**G7 在 a8e902a 上已闭合**。

由此带来的判定口径提示（不改任何文件）：M3 的 `expected-mechanisms.json` 里
`task_level_requirements[0].blocked_by` 仍写着 `SDK-G7`。`pair.py::task_level_mechanisms`
的处理是：机制**真触发**→ `PASS` 并置 `blocker_lifted=true`；**没触发**→ 因为 `blocked_by` 存在
而记 `BLOCKED`（不计 FAIL）。也就是说本次若 M3 的共享只读子目标一局都没走到，报告会记
BLOCKED 而非 FAIL —— 这比 G7 闭合后应有的严格度宽松一档。此事在结论中单列，题集与判定
逻辑按纪律**未做任何改动**。
