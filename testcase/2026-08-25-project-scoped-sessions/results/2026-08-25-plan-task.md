## Idempotency review

- Project registration deduplicates by opaque filesystem identity; repeated equivalent registration returns the
  existing Project.
- Session creation is request-idempotent through durable receipts; the same intent replays the same Session, while
  an intent mismatch is rejected.
- Session + binding + Provider snapshot + catalog revision commit in one transaction; injected rollback tests prove
  no half-bound Session.
- v32 semantic backfill is phase-tracked, high-water bounded, verified, and idempotent across restart.
- startup recovery orders migration/backfill before deleted-run reconciliation and SDK ingress; repeated recovery
  does not resurrect deleted Sessions.
- catalog paging uses revision-fenced cursors; mutations invalidate a stale cursor instead of silently mixing pages.
- relocation uses expected project revision CAS and same-filesystem-identity validation; stale and unrelated targets
  are rejected.
