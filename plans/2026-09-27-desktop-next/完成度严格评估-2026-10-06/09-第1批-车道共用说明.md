## 二、每条车道都要守的规则

1. **只改自己车道的文件。** 看到别的车道的问题，写进记录，不动手。
2. **测试先行。** 先写会红的测试，再改代码，测试转绿。每条至少一条测试。
3. **只跑改动文件对应的测试和新测试。** 不跑整个 `tests/`，不跑整个 `tests/orchestrator`。用户硬规则。
4. **改了 SDK 源码后，跑 `taskgraph_exec`、`product_world`、`assurance_exec` 组前先重生成部署清单**，否则用例报 `taskgraph_deployed_source_unverified`：
   ```bash
   cd <工作树>/sdk/simple-harness-sdk && uv run --frozen python scripts/build/taskgraph_manifest.py generate --upstream /Users/taiwan/PROJECTS/SimplaHarness/simple_harness/.local-test-evidence/2026-10-05/f2-upstream/evidence.json
   ```
   然后 `find src tests -name __pycache__ -prune -exec rm -rf {} +`。
5. **跑测试的命令**（在 `<工作树>/sdk/simple-harness-sdk` 下）：
   ```bash
   PYTHONPATH=src uv run --frozen --group dev --extra local-capacity pytest -q -p no:cacheprovider <测试文件或 nodeid>
   ```
   工作树里的 uv 环境可能解析到别处的 src，所以必须带 `PYTHONPATH=src`。Host 测试在 `<工作树>/backend` 下用 `uv run --frozen python -m pytest -q <文件>`。
6. **开发期不做兼容。** 旧路径直接删。不留双分支。不写"legacy"。
7. **核心思想。** 判断交给 LLM，Harness 只管约束与秩序。不按异常文字分类。不加语义规则。
8. **异常按类型码判。** 新的跨边界码必须登记进 `src/agent_orchestrator/contracts/error_table.py`，否则 `classify` 拒绝。
9. **每条做完写一次改坏。** 把修好的地方改坏一处，绑定的测试要红。记录改坏点和结果。改坏后恢复用 `cp` 备份，不用 `git checkout`。清 `__pycache__`。
10. **在自己分支上提交。** 不推送。不合并 main。提交说明中文。
11. **写记录。** 在自己工作树里写 `plans/2026-09-27-desktop-next/完成度严格评估-2026-10-06/第1批-车道<X>-记录.md`，随代码一起提交。内容：每条做了什么、改了哪些文件、测试文件与结果、改坏结果、遇到的偏差与裁决、留给主会话的事。全部中文。句子短。
12. **碰到计划与代码冲突，停在那一条。** 写偏差单进记录，继续做别的条目。不先斩后奏。
13. 不改 `version.py`。不改部署清单之外的 `taskgraph_deployment_manifest.json` 手工内容。不碰 `backend/vendor`。
