# 阶段 8 偏差单：研究工具拆分的转出口、重复组丁与己的处理

## 一、研究工具拆分（8F-5）留一个转出口

事实：

1. `backend/deskpet/tools/research_tools.py` 原 2801 行。不被任何模块按别名取用的定义只有 502 行，纯移动降不到 2000 行以下。
2. 按别名取用的有两类调用方：
   - 编解码钉死文件：`definitions/v7/deep_research.py`、`definitions/v1/deep_research.py`。它们按 `legacy.名字` 读取，或者 `from research_tools import 名字`。钉死文件一字不能改。
   - 普通文件：research_core.py、host/llm_calls.py、host/startup_workflows.py、ppt/research.py，以及 9 个测试文件。
3. 被测试按别名打桩的名字（`setattr(r, "名字", …)`）有 60 多个。打桩只改原模块的属性。被打桩的名字如果搬走，搬走的代码读新模块的属性，打桩就失效。

做法：

1. 用 move_defs.py 的"下沉"方向搬两组定义。两组都不引用任何被打桩的名字，也不含会被重新赋值的模块级变量（`global` 改写的 6 个）：
   - `research_fetch.py`（434 行，26 个名字）：站点与资料包规则、搜索结果与网页抽取解析、来源权威度、JS 渲染名额。
   - `research_report.py`（约 775 行，43 个名字）：数据类型、提示词、引用核对与报告收尾、子报告质检、工具参数表与深度预设、模型回执用量解析。
2. 全仓的 `from research_tools import 名字` 改成从新模块导入。普通文件里的 `别名.名字` 改成直接导入新模块的名字。钉死文件不动。
3. research_tools 从新模块导入自己要用的 38 个名字。另外只为钉死的 v7 定义保留 1 个转出口：`_PLAN_PROMPT`（v7 按 `legacy._PLAN_PROMPT` 读取）。这一行单独放，写明原因，带 `# noqa: F401`。
4. 结果：research_tools 1693 行。每个搬走定义的语法树与搬前逐字相同。新文件加进 execution_build_sources.json（切片设计的裁决已允许），构建身份清单已重生成。

与规则的出入：

- `_PLAN_PROMPT` 有两条导入路径（research_report 与 research_tools）。这是钉死文件强制的，别的名字都只有定义处一条路径。
- 顺带修了 move_defs.py 的一个缺陷：源文件带 `from __future__ import annotations` 时，symtable 不记注解里的名字，只在注解里出现的名字会漏算（这次漏了 `_LLMCall` 等 4 个）。现在先去掉 `__future__` 导入再分析。阶段 6 的搬移有棘轮检查兜底，ruff 未定义名字没有增加，说明当时没有漏。

请裁决：同意保留这 1 个转出口？

## 二、重复组丁不合并

事实（逐段比对后端 `capabilities/builder.py` 与 SDK `capabilities/builder_contracts.py`）：

1. 后端没有任何文件导入 SDK 的 builder_contracts。两份是分叉后各自演变的副本。
2. 同名定义 21 个。去掉文档串与注释后逐字相同的只有 10 个常量（共 10 行）。其余 11 个类与函数有实质差别。后端版用宿主自己的类型，并做更严的校验；SDK 版用通用类型，校验较松：
   - 候选准入：后端要求 `permit` 是宿主签发的 `GrowthCandidateBuildPermitV1`，不是就报 `growth_build_permit_required`；SDK 版 `permit: Any`，不查。
   - 搜索证据：后端用 `CatalogStamp(**…)` 全量校验目录戳；SDK 版只查 4 个键在不在。
   - 构建启动：后端的发布策略是枚举 `CapabilityBuildPublishPolicy`；SDK 版是字符串字面量。
   - 安装请求：后端用 `PackSourceRequest` 对象；SDK 版拆成 3 个字符串字段。
3. 合并就要选一套类型与校验，另一边的行为会变（后端改用 SDK 版会丢掉准入签发检查）。这是行为变更，不是去重。

建议：丁组不合并，和甲、乙一样写成棘轮（只减不增），记剩余行数（约 350 行），列进 11.6"后端能力包构建改用 SDK 实现"，单独立项。

v2、v3 contracts 不合并的原因：

1. 两份分别属于两个冻结的工作流版本。钉死的定义与节点按各自的 contracts 模块导入。
2. 合并后，v2 的 `BranchBudgetState` 等类的定义模块会变（`__module__` 从 v2 变成 v3 或共用模块）。工作流身份按"模块名:限定名 + 源码"计算节点身份，类所在模块变了，有被身份核对拦住的风险，属于身份变化。
3. v2、v3 本身是旧版本，按 8D 的旧版清单走删除，不值得为合并动身份。

建议：v2、v3 contracts 按丙组同类除外（理由同"节点源码是工作流身份"），写进 2.10 修订。

切片设计第 2 条写"只剩测试在用的算死代码，测试一起删"。逐个核对后（脚本 scratchpad testonly.py，按词边界搜全部测试文件，定位所在测试函数）：
