# HTN 一致性补改方案（2026-10-04，第 2 版）

来源：`HTN与原始计划一致性复核-2026-10-04.md`（8 处 + 1 处待确认）；用户 2026-10-04 决定：第 3 处选"交审阅员按原话判"，第 8 处"目前只做 macOS"，第 9 处"对比实验不做；默认 512K、256K 可选"，其余按建议。分支 `htn-h`（基 main `57560720`），发版 SDK opt.150。做完停下问用户是否开始 TaskGraph。

流程照旧：本方案经子代理评估到可执行 → 实施（核心代码主会话写）→ 每项一条功能用例 + 一条改坏（纯记录项除外）→ 只跑改动文件对应的测试 → 完成评估 + Opus 只读阻断核验 → 发版。冲突走偏差单。

## 逐项

### H-1　做法前提被推翻：直接交规划器（复核第 1 处，补）
- **现状**：派发前 `HierarchicalDispatch.issue_condition_witnesses`（`SDK/orchestrator/hierarchical_dispatch.py:1366` 起）已按当前观察重算每个做法的前提，不成立写 `BLOCKED` 的开工许可；步骤停在"等证据"，要等判停滞才以"没有可派发的工作"问规划器一次。`SDK/planning/htn/applicability.py:590` `recheck_method_instance`（及 `RecheckResult`、`RecheckStatus`）没有生产调用方；`SDK/contracts/evidence_state.py:95` `phase_check_points`（"没声明时点就在验收时再查"）也没有调用方。
- **改**：
  1. 规划器修复请求的系统扫描（`SDK/orchestrator/planning_repair_requests.py` 里与 `stale_evidence_triggers` 同处）新增一类来源：本任务现行计划里、还没开工的原子步骤，它最新的开工许可是 `BLOCKED` 且原因是前提（`CONDITION_REASON_PREFIX`）→ 记一条 `EvidenceInvalidated` 请求（**复用现有请求种类，不加新词**），`source_key = "precondition:" + 许可编号`，`detail` 如实给：步骤、做法、哪几条前提（条件原文 + 摘要）、现在读到的真值与观察依据、许可时刻。怎么办（换做法、等、问用户）由规划器定。
  2. 删 `recheck_method_instance`、`RecheckResult`、`RecheckStatus`（同一件事只留派发前重算一条路）。
  3. 删 `phase_check_points`；`evidence_state.py` 在网络编码清单保护范围内，同步更新 `graph/network_codec_manifest_v5.json` 的源哈希（只删函数，不动任何被编码的类型）。若评估认为动编码清单代价不值，改为保留并在计划里记"验收时不复查前提"。
  4. 计划里记有意偏离：前提只在派发前查；执行中变了不叫停在跑的步骤，验收由审阅员判结果本身（作用域纪元变化照旧兜住过时证据）。
- **用例**：产品同形世界，一个带前提的做法；计划提交后、派发前把前提对应的观察翻成假 → 下一轮规划器收到 `EvidenceInvalidated` 请求、`detail` 里有那条前提，**早于**停滞判定；规划器换做法后任务完成。**改坏 H-01**：扫描不看前提许可 → 规划器只在停滞后才被问 → 变红。

### H-2　取消时有结果不明的对外操作：报告与通知写明（复核第 2 处，小补）
- **现状**：`CommitService.cancel_mission`（`SDK/orchestrator/commit_service.py:1463`）直接置"已取消"；`HANDED_OFF` / `UNKNOWN` 的动作留给后台对账，取消报告不提，对账出结果也不通知。
- **改**：取消时把这类动作如实写进任务的最终报告（`final_report.unresolved_actions`：动作编号、目标、状态，及"系统会继续核对"）；Host 把任务终态推到主对话的那条通知（阶段 B 的"通知进主对话"）读到它就加一句"还有 N 个对外操作结果不明，系统会继续核对"；对账把一个**已结束任务**的动作定成成功 / 失败时，经同一条通知路径再发一条"任务 X 的对外操作 Y 核对结果：已生效 / 未生效"。不改任务状态机。
- **用例**：沿用 `T/product_world/test_operation.py` 的"发布进行中、结果不明"局面：取消 → 最终报告有一条未决动作；放开对账 → 主对话通知有核对结果。**改坏 H-02**：取消不写未决动作 → 变红。

### H-3　要求的轻重与"或"交审阅员按原话判（复核第 3 处，用户选 A）
- **现状**：合同 `Criterion`（`SDK/contracts/resolution.py:190`）有要求类别、检查方式、时点、修改权限；产品唯一入口 `SDK/deployment/root.py:42` 一律建"必须达到的结果、语义判断"，组合"全部都要"。审阅侧为"硬约束"写的分支（如 `SDK/verification/acceptance_rules.py:255`）在产品里走不到。
- **改**：
  1. 审阅员提示词（各用途共用的判据段）写明：用户原话里"最好 / 尽量 / 可选 / A 或 B"等由审阅员按原话判轻重——偏好没做到不单独构成打回理由，"或"满足一项即可；判据写在原话上，不靠系统分类。提示词版本号加一，钉哈希基线随之重生成（开发期不留旧版本）。
  2. 删掉产品走不到的分类分支：`RequirementClass` 只留 `REQUIRED_OUTCOME`、`EvaluationKind` 只留 `SEMANTIC`、`Criterion.phase` 删，审阅 / 规则侧按这些分类分叉的代码删掉。先用 grep 核：若这些枚举或字段进了网络编码清单保护的源文件或被编码进网络文档，则改为"保留字段、固定取值"并在计划记偏离，不动编码。
- **用例**：一条要求写"写周报，最好带图表"；审阅员脚本按提示词判据通过无图表的交付 → 任务完成（脚本审阅读的是提示词里的判据段，断言提示词里有这条判据、且交付被接受）。**改坏 H-03**：提示词删掉这条判据 → 用例变红。

### H-4　知识只有一组依据：记为有意偏离（复核第 4 处）
- 不改代码。计划记偏离："知识只记一组依据、读时判定，任一项不当前即过时（偏保守：不会用上过时知识，只是少复用）"；台账 R29 改措辞，删"多条支撑理由已接入"。

### H-5　义务三个没人用的字段：删（复核第 5 处）
- `SDK/contracts/obligations.py:134-137` 的 `authority_ref`、`budget_lineage_ref`、`satisfaction_policy`（及只为它们存在的类型）删掉；满足看完成度读取、花费看义务账、权限看部署策略。先核这三个字段是否被编码进网络文档或在网络编码清单保护的源文件里；是则改为偏离记录、不动。
- **用例**：现有义务用例照跑（只跑 `obligations` 相关文件）；无新改坏（纯删除）。

### H-6　诊断导出补"预算去向"一节（复核第 6 处，小补）
- Host `backend/deskpet/orchestration/diagnostics.py` 加一节：取 SDK 现成的义务账读取（规划包与界面用的同一个函数），只给数字与步骤名，不带正文。
- **用例**：`backend/tests/orchestration/test_mission_diagnostics.py` 加断言该节存在且总数等于任务已结算。**改坏 H-06**：去掉这一节 → 变红。

### H-7　任务详情显示"因改要求或依据变化不再算数的步骤"（复核第 7 处，小补）
- SDK 只读接口把规划包里已有的那份信息（`SDK/orchestrator/planner_views.py:166` 一带）给 Host 快照；前端 `MissionsView.tsx` 任务详情加一行（有才显示，简洁）。
- **用例**：Host 快照用例 + 前端 vitest 各一条。**改坏 H-07**：快照不带这份信息 → 前端用例变红。

### H-8　代码隔离只做 macOS（复核第 8 处，用户定）
- 不改代码。台账 R49 改"不做（用户 2026-10-04 决定：目前只做 macOS；Windows / Linux 上不运行模型写的代码）"；计划"暂不做"清单加一条。

### H-9　窗口容量：默认 512K、256K 可选（复核第 9 处，用户定）
- `backend/deskpet/orchestration/settings.py:56` 默认改 `524_288`；配置 `context_input_tokens = 262144` 仍可选（现有解析只接受这两个值，不变）。只影响新建任务，已有任务沿用冻结的执行池；两档执行池本来都注册，不改执行池身份。计划"暂不做"加"窗口容量对比实验"。
- **用例**：`backend/tests/orchestration/` 里设置解析用例改期望；**改坏 H-09**：默认改回 256K → 变红。
