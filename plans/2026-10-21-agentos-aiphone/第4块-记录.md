# 第 4 块：快速聊天——实施记录

日期：2026-10-21

## 做了什么

| 部位 | 文件 | 要点 |
|---|---|---|
| 聊天入口 | `host/chat.py`（新，公开） | `ChatService`：自己的执行池（`STANDALONE_CHAT`，数据目录 `chat/`）；一个会话一个 Agent；工具名单第一句定下；每回合在全局月账预留、按真实用量结清（报告缺失按上限）；`require_tool` 提醒一次；台账 `chat-turns.jsonl`；同一幂等键原样返回 |
| 宿主 | `host/host.py` | `host.chat()` / `chat_cancel()` / `chat_history()`；聊天池在任务池之后起、重建与关闭时跟着；`status()["chat"]` |
| 设置 | `host/settings.py` | `chat_max_model_calls=8`、`chat_max_tool_calls=8`、`chat_turn_seconds=180` |
| 池 | `deployment/native_pools.py` | `assembly(owner_mode=)`；`native_profile_id(chat=True)`（`…-chat-v1`）；聊天池用自己的授权口实例（共用会把任务的拒绝事件带走） |
| 网关 | `runtime/tool_gateway.py`、`runtime/domain_tools.py` | 绑定视图 `chat`；领域工具在聊天绑定上可调，`ToolCallContext.mission_id` 为 `None`、`attempt_id` 是 `chat-<会话号>`；锁按会话串行 |
| 测试替身 | `testing/scripted_replies.py` | `LayeredScriptedProvider(chat=…)`，角色 `[role:chat]` |
| 测试 | `tests/orchestrator/host/test_chat.py`（6 项） | 问答与续聊与幂等；只读查询调工具；提醒一次与如实返回；月配额不够先拒；聊天池与任务池分开；取消在下一次模型调用前生效 |
| 说明 | `docs/orchestration-host.md` §2b | 用法、上限、预算、错误码 |

相关测试：聊天 6 项 + 工具注册 + 领域工具执行器 + 通用模型宿主 + 宿主 + 运行档 = 43 项通过；
另一批（提供方、步骤动作、月总账、ARP 任务模式）在授权口修复前已通过，改动不涉及它们。

## 做的时候碰到的

1. 领域工具在网关里有一处"必须挂在任务上"的守卫：聊天绑定放行（`view == "chat"`）。
2. 聊天池装配把共用授权口的审计回调改指到聊天网关，任务里"工具不在名单"的拒绝事件丢了：聊天池用自己的授权口实例。
3. 内核只在两次模型调用之间看取消意图：正在线路上的那次调用跑完并计费，之后不再调模型。测试与说明按这个写，不假装能打断。

## 没做 / 留给后面

- `first_output_ms` 等第 5 块逐字输出接上后才有。
- 聊天里不做审阅；不替应用保存界面对话。
- 用一个取消令牌把在途的模型调用也打断：需要内核把回合取消接到提供方取消令牌，属于内核改动，另立项。

## 独立核验（2026-10-21）

第一轮 FAIL，4 条阻断，均已修：
1. 线路回 0/0 的用量被当真实用量结清 → 改用 SDK 自己的 `valid_usage`（0 记未知），按上限结清。
2. 回合在途时关宿主：结算读已关的执行库抛错、预留永久占住，该会话以后每句都超时 → 结算失败按上限结清且不盖原异常；启动时把遗留的聊天预留按上限结清、叫醒在途回合；卡在"结果不明的模型调用"上的 Agent 放弃，会话换新一代 Agent（`history_reset=true`），与任务池放弃执行者同一做法。
3. `require_tool` 的提醒是第二个回合却只预留一回合 → 预留按两回合算，月配额不够先拒。
4. 清单在最后两处改动后没重生成 → 重生成（流程教训：最后一处源码改完再生成）。

`session_id` 未校验、聊天并发名额与任务叠加、聊天工具调用无事件审计、内存表只增不减、台账每回合读两遍、
