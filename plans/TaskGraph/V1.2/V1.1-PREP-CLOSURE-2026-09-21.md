## 2. 唯一 Commit 接缝：允许等价命名，禁止等价猜测

### 2.1 本次明确裁定

`commit_admitted_plan` 是原补遗给出的合同入口名；核心要求是两阶段准入后的安全提交，不是英文单词本身。

| 编号 | 必须核查的合同；结论必须关联 source 行范围、实际文件 hash 和行为 nodeid |
|---|---|
| C01 | 输入是完整 Plan Admission 的 `AdmittedPlan` 或包含同等冻结证明的内部类型；不接受原模型 dict、PreAdmitted 对象作为最终许可 |
| C02 | 原 request/decision/Mission/caller/scope/enablement 完整绑定；两个 decode-only 分支仍无法执行 |
| C03 | Commit 事务内重读真实 planning grant lineage、revision/hash、policy/TTL；不是 applicability bool 或 approval count |
| C04 | 精确 Operation→action join、完整集合 hash、真实在途结果；读失败不为空，旧方法 UNKNOWN 不遗漏 |
| C05 | 同一个 preview/delta/source read-set；未完成校验不按 PASS；不得预览 A 提交 B |
| C06 | 一个外层 Store transaction，同 connection；内层只嵌套已有事务/必要 savepoint，不提前提交；无模型/工具网络调用 |
| C07 | caller 先核对；同 command 同 intent 返回原 receipt，不重派；异内容冲突；撤权后只按当前读权返回历史 |
| C08 | Plan/decision/receipt/outbox 同事务；中途失败共同 rollback，提交后丢响应重送不重复 |
| C09 | DEFERRED 按原决定恢复；WAIT/NO_CHANGE/DECLARE_BLOCKED 不编译/不调用 operation mapper/不改图 |
| C10 | 所有本次新协议真实调用边经过该入口；不能有另一条直调原 `commit_plan_revision` 绕过 guard 的旁路 |

审查表已实际提供在 `h1h/commit-seam-review.json`。其初始状态全为 `NOT_REVIEWED`。

### 2.2 三种审查结果与代码权限

1. **EQUIVALENT_USE_EXISTING**：C01–C10 都有源码和实测依据、独立审阅，才填 `equivalences.json` 中对应 source requirement ID 的实际 path/qualified symbol/hash/nodeids。probe 读取等价记录，不能仅放宽检查为“任意同名函数”。

3. **SOURCE_UNAVAILABLE**：没有实际字节、未核实调用链、producer 尚未完成；保持 BLOCKED。

## 5. H1-H 36-case manifest：case、nodeid、断言、执行分开

### 5.1 36/35 的裁定

36 个 case 可以由 35 个物理 pytest nodeid 覆盖；一个测试可针对同一场景验证两组独立要求。但两组 case 都须指明其自己的断言位置和实际证据。不得按名称相似、同一个 `assert ok` 或总 PASS 数机械复用。

因此：

- **35 unique nodeid 不是自动失败，也不是自动完整。**
- 只有 4 nodeid 的 manifest 不能表示全部 36 case 的可执行映射；缺项必须显式列出。
- 36 `NOT_RUN` 就是没有执行，不得把注册/collection 写为 PASS。
- `test_h1h_stage_runner.py` 的 collection 可能仅收集 runner 自身的元测试；不能假定它展开了 registry 的全部目标。

### 5.2 只读导出实际 registry，不 import / exec runner

工具 `tools/h1h_manifest.py extract` 读取被冻结的实际 runner AST，只支持明确的数据声明：`{case_id: nodeid/list}`、`[{id, nodeid/nodeids}]`；可显式指定关键字型记录构造器。不会执行 runner 顶层逻辑。

```bash
"$PY" "$KIT/tools/h1h_manifest.py" extract \
  --source-map "$EVID/source-map.local.json" \
  --spec "$KIT/h1h-nodeid-map.json" \
  --runner-relative tests/orchestrator/full_target/h1h_stage_runner.py \
  --out "$EVID/h1h/registry.local.json"
```

只有一个静态声明恰好覆盖原 A01–A08/O01–O10/P01–P10/I01–I08 时自动选中；多个匹配或不支持语法时写出 BLOCKED 和候选常量名。WorkAgent 读取**实际源码**后可用 `--registry-symbol 实际常量名`；关键字记录可加 `--constructor 实际类名`。不猜位置参数含义，不用 eval/runpy/import。

若实际 registry 为动态生成或位置参数结构：当前允许仅在 **本包 tools 的 ignored 副本**加入确定性只读导出 adapter，按真实字段映射，附 golden 断言（原36 ID/每ID原nodeid/行号/hash）；不得改 runner 行为或随意填目标。属于工具格式适配，不是 HTN/TaskGraph 语义修改。

### 5.3 真实 collection，只收集 registry 指定的目标

先审阅项目 conftest、测试模块导入及离线环境，确认不会连接生产库/使用模型凭证。collection 会 import 测试代码，**不是安全沙箱**。[W2]

```bash
"$PY" "$KIT/tools/collect_h1h.py" \
  --source-map "$EVID/source-map.local.json" \
  --registry "$EVID/h1h/registry.local.json" \
  --collection-imports-reviewed \
  --out-dir "$EVID/h1h/collection"

"$PY" "$KIT/tools/h1h_manifest.py" bind \
  --source-map "$EVID/source-map.local.json" \
  --spec "$KIT/h1h-nodeid-map.json" \
  --registry "$EVID/h1h/registry.local.json" \
  --collection "$EVID/h1h/collection/collection.json" \
  --out "$EVID/h1h/manifest.expanded.json"
```

工具实际调用 `pytest --collect-only`，使用冻结副本与项目解释器；收据保存 fingerprint、runner hash、真实 nodeids。缺 nodeid/collection error 为 BLOCKED。输出所有 case 的 execution_status 永远为 `NOT_RUN`。

`manifest.expanded.json` 是本包的覆盖清单，**不是未经核查即可传给现有 stage runner `--manifest` 的配置**。先阅读该参数实际是输入、输出还是过滤器；不得用名字推断。H1-H 已有工作流可对 runner/manifest adapter 做窄修改，使它消费相同 ID→nodeid 映射；本次 TG-A-prep 不执行真实 focused suite。

### 5.4 断言审查与后续执行

复制 `h1h/assertion-review.json` 到 ignored run，每项填：实际 nodeid、冻结 test 文件 SHA、断言行/命名 helper、覆盖要求、独立 reviewer。共享 nodeid 必须有两行独立覆盖记录。实际运行后还需 setup/call/teardown 三阶段正常；skip、xfail、意外 xpass、collection-only、环境失败都不能记 PASS。[W2]
