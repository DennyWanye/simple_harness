## 每片标准流程

`scripts/code_quality/slice.sh <目标文件> <说明> <名字列表>`：

1. 按名字算出要搬的顶层语句范围（含闭包依赖）。
2. 搬家，目标文件补导入，源文件加回导入（`# isort: split` 保住导入期顺序）。
3. 导入冒烟 → 打桩目标检查 → 跑引用被搬名字的测试 → 启动快照 → 禁区比对 → 棘轮。

收尾两步（本轮新增工具）：

- `retarget_tests.py`：把测试里对 `main.X` 的打桩改到所属模块。
- `prune_host_imports.py`：删掉主入口从 host 导入、但主入口和测试都不再用的名字。不留转发层。

## 阶段 2 自身引入并已修复的缺陷（2026-10-13）

1. 搬家工具判断外部依赖用的是粗算法，运行栈组装漏导入全局配置。启动快照拦下；工具已改按作用域分析，已审过此前全部 host 模块。
2. 主入口里的 `globals().get("X")` 搬进 host 模块后静默取空，4 处依赖丢失（语音运行时的权限门、能力运行时的插件管理器、上下文投影的服务注册表与回执存储、成长权威的状态库路径打桩）。启动快照只记服务类型，没拦住；静态排查发现。已改显式导入，并加结构测试禁止 host 模块用 `globals()`。
3. 搬家工具删"无用导入"时没查测试，测试经主入口取用的名字被删。工具已改为先查测试。
4. 搬家后去掉语音装配模块的导入，导入期登记顺序改变。启动快照拦下；主入口在原位置保留该导入。
6. 日志记录器名变化：`structlog.get_logger()` 不带名字时取第一次打日志的模块，拆分后所有日志的记录器名从 `main` 变成 `host.llm_calls`。已固定为 `main`。
5. 多处测试打桩或直接赋值打在主入口上，读取方已搬走，打桩不生效，有的会变成永远成立的断言。新增 `hidden_patches.py`、`main_assignments.py` 两个检查，`patch_host_global` 统一处理。
