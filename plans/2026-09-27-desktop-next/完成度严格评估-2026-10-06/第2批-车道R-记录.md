# 第 2 批 车道 R 记录：重启核对隔离的任务让人看得见

- 工作树：`simple_harness-b2r`，分支 `batch2-r`，基线 main `42c897f4`
- 来源：`第2至4批-完成评估.md` 第七节 7.2 第 2 条（被隔离的任务对用户不可见，一直显示"进行中"），以及同处复核的三条小事
- 范围：只改 Host 与前端；SDK 一个字没动

## 一、做了什么

### 1. Host 给被隔离任务带标记
- `backend/deskpet/orchestration/service.py`
  - 新增常量 `RECOVERY_ISOLATED_NOTE = "重启核对没通过，已隔离，不再推进；可以取消"`，列表、详情、主对话共用这一句。
  - 新增 `_recovery_isolated()`：唯一来源 `self._orchestrator.recovery_status()["isolated_missions"]`，整理成 `{mission_id: {"tables": [...]}}`；读不到（旧轮子没有这个方法、库关了等）当作没有隔离，不抛。
  - `list_missions()` 每行、`mission_detail()` 顶层都带 `recovery_isolated`：被隔离为 `{"tables": [...]}`，没隔离为 `None`（键总在，统一）。
  - 任务已结束（完成 / 失败 / 取消）不再标：SDK 名单里可能还留着它，但"不再推进；可以取消"这句已不成立。
- `backend/deskpet/orchestration/chat_tool.py`
  - `mission_status` 回执加 `recovery_isolated`（`{"tables": [...], "note": 那句话}` 或 `None`）；被隔离时 `note` 直接换成那句话，主 Agent 照读即可告诉用户。
  - `mission_list` 每行加同一个 `recovery_isolated`。
  - 工具说明文字一个字没改（工具说明属于准入身份，改了会让已有执行池起不来）。

### 2. 前端显示一行明确状态
- `tauri-app/src/stores/missionsStore.ts`：`MissionRow` 加 `recovery_isolated?: { tables: string[] }`，`toRow` 归一（没被隔离就不带）。
- `tauri-app/src/views/MissionsView.tsx`
  - 列表行：被隔离且没结束时多一行警示色文字"重启核对没通过，已隔离，不再推进；可以取消"；鼠标悬停看对不上的表名。
  - 详情：顶部"下一步"提示条先说这一句，盖过"去确认 / 去审批 / 正在自动进行"等提示（这些都不再成立）；"取消任务"按钮照旧在。

### 3. 复核建议的三条小事
- `assurance_root_diagnostic()` 与 `_assurance_root_status()` 也认 `degraded_recovery`。此前 `handlers.DEGRADED_RECOVERY_READS` 放行了 `mission_assurance_root_diagnostic`，服务却答"不可用"；状态里的保证通道根也读成 None。
- 降级恢复时主对话写入口补挡：`source_command`（换资料）与 `retire_library_entry`（退役方法库条目）照 `create_mission` 的做法先 `_require()` 再 `_refuse_new_work(...)`，具名码 `orchestration_degraded_recovery`。
- `test_recovery_degraded_host.py` 失败步骤名 `reclaim_orphans` 改成 SDK 实际名 `orphan_reclaim`（步骤号同步改成 7）。

## 二、测试

主检出 venv 装的 SDK 轮子是 opt.165，比 Host 代码旧：`service.status()` 引用 `commit_service.GLOBAL_ACCOUNT_PREFIX`（车道 P 加的）在 opt.165 里没有，所以**基线上** `test_recovery_degraded_host.py` 就已失败（`ImportError`）。
本车道改用工作树 SDK 源码跑 Host 用例：`PYTHONPATH=.:../sdk/simple-harness-sdk/src`，再加一个只在本会话草稿目录里的 pytest 插件把执行图部署验收门放行（源码构建的部署清单记为 NOT_RUN）。插件不入库。用例本身仍用 `monkeypatch.setattr(Orchestrator, "recovery_status", ..., raising=False)` 钉值，钉版后用轮子跑也成立。

## 三、留给主会话
1. Host 装的 SDK 轮子（opt.165）落后于 Host 代码（缺 `GLOBAL_ACCOUNT_PREFIX`），基线上降级用例与任何调 `status()` 的用例用轮子跑都会失败；SDK 隔离补完后发版钉新轮子时一起恢复，届时用轮子重跑本车道两个文件确认。
2. "可以取消"这句话的前提是 SDK 对被隔离任务仍接受取消；主会话在 SDK 补隔离时请保证这一点（Host 侧取消入口没动）。
3. 任务结束后 Host 不再标隔离；SDK 若在取消时把它移出 `isolated_missions` 也一致，不需要 Host 再改。
