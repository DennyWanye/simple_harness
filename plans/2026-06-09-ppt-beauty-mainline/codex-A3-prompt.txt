== 改动 1：bundled 模板目录 + 名字解析 ==
- 定义 bundled 模板目录：_TEMPLATES_DIR = Path(__file__).parent / "ppt_templates"。
- 新增 def _list_bundled_templates() -> list[str]：返回 _TEMPLATES_DIR 下所有 *.pptx 的「不带扩展名的名字」列表(目录不存在/空 → 返回 [])。按名字排序。从不抛异常。
- 新增 def _resolve_template_path(template: str|None) -> str|None：
  * None/空 → None。
  * 若 template 是存在的文件路径(Path(template).expanduser().is_file()) → 返回该绝对路径字符串(直接路径优先)。
  * 否则当成 bundled 名字解析：去掉可能的 .pptx 后缀 → _TEMPLATES_DIR / f"{name}.pptx"，存在则返回其路径，否则 None。
  * 从不抛异常(异常 → 返回 None)。

== 改动 2：ppt_create 用解析器 ==
- ppt_create 里现在的 `if template:` 分支改为先 `resolved = _resolve_template_path(template)`，用 resolved 走 _render_with_template；resolved 为 None → log.warning + 回退 from-scratch(原逻辑)。
- 保持：template=None 时行为 100% 不变(根本不调解析、直接 from-scratch)。

== 改动 3：_PPT_SCHEMA 让 LLM 可发现模板 ==
- template 属性描述改成：可传 bundled 模板名(见下)或 .pptx 绝对路径；用模板能产出更专业/精美的可编辑 PPT，**用户要「正式/专业/精美」PPT 时优先用模板**。
- 在描述里【动态】列出当前可用模板名：用 _list_bundled_templates() 的结果拼进 description(若为空则写「当前无 bundled 模板」)。注意 _PPT_SCHEMA 若是模块级 dict 字面量，改成在注册时(或一个 build 函数里)动态生成 description，保证列表反映目录实际内容。找到 _PPT_SCHEMA 的定义与 registry.register 调用处，最小改动实现动态 description(可加 def _build_ppt_schema() 返回带最新模板列表的 schema，注册时调它)。
