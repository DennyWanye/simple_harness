## 5A 执行存储类

### 5A.1 按业务域拆成 mixin（纯移动）

| 项 | 拆前 | 拆后 |
|---|---|---|
| uow.py | 17807 行，一个 15504 行的类 | 约 1000 行：组合类（只剩 close、事务入口、几个只读方法）与少量辅助定义 |
| 领域文件 | — | 子包 execution/sqlite/uow_domains/：20 个领域 mixin、core（公共基类）、support（多域共用辅助函数） |
| 最大的类 | 15504 行 | 1453 行（派生结果 mixin） |

做法：
- 工具 scripts/code_quality/split_class.py，分组写在 scripts/code_quality/split_specs/uow.json。方法源码逐字搬，模块级辅助定义按使用方放置（只一个域用→放进该域；多域用→support；只组合类用→留下）。
- **公共基类 core**：领域 mixin 调用的组合类方法（插入事件、取运行、核对租约与围栏、起始回执等 23 个）和原类的 `__slots__`、`__init__` 一起搬进 `ExecutionUnitOfWorkCore`，每个 mixin 继承它。原因：只搬 mixin 时 mypy 报 441 个"没有这个属性"，其中 388 个指向这些共用方法。
- 跨领域调用（约 25 个方法）在调用方 mixin 里写 `if TYPE_CHECKING:` 同签名存根，沿用原有 ProviderAccountingMixin 的写法。原类对 ProviderAccountingMixin 的继承改挂到提供方调用 mixin 上。
- 唯一的非搬移改动：`SqliteExecutionUnitOfWork._invalidate_cancel_activation(...)`（静态方法里按类名调用）改成 `WorkflowCancelMixin._invalidate_cancel_activation(...)`。
- mypy 范围（pyproject）加入新子包；24 个文件 0 错，SDK 总数仍 314。

验证：350 个方法与辅助定义 AST 逐字比对，只差上面一处；类的方法解析顺序与 `__slots__` 核对（实例仍无 `__dict__`）；单片校验全过（导入冒烟、启动与控制通道快照、禁区比对、棘轮、启动耗时、导入隔离、改坏清单资产测试）；直接引用执行存储的 83 个 SDK 测试文件 0 失败。后端测试用的是钉版 SDK 包，看不到工作树改动，留到 5F 全量回归。

执行存储类没有改坏清单条目、没有接缝条目，所以无需改清单。

## 中途发现

- **提交时误带文件**：先 `git add` 了新子包、再按路径提交计划文档，第二次提交把暂存区里的新子包一起带上，导致禁区比对把 HEAD 当成"新旧两份都在"而报字面量减少。撤回该提交（未推送）后重新提交。以后按路径提交前先看暂存区。
- **重生成文件时后台测试仍在跑**：重跑拆分工具会先删子包再写回。这次内容只差两行文档字符串，测试没受影响；以后跑测试期间不重生成。

拆长函数验证：mypy 0 错、ruff 无新增、禁区比对（字面量多重集不变）、棘轮、单片校验全过；执行存储与派生、启动相关的 90 个 SDK 测试文件 0 失败。
