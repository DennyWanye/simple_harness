### 1.3 Schema 放哪里

都放在 SDK 现有公开合同的两处。不新建目录。

| `taskgraph.execution_snapshot` | `taskgraph-execution-view-v1` | `sdk/.../graph/schemas/` | 执行图合同族，与另外八份同处 |

### 1.7 守什么保证

1. 这四类消息不合公开合同时，Host 不转发，回具名协议错。
2. 前端只把合公开合同的数据交给界面；坏消息标协议错，界面保留上次画面并标已过期。
3. 前后端用同一批 Schema 文件；Host 包内文件与仓库源码字节相同。
4. SDK 不会把不合合同的执行视图交出去（与另外四个视图一样报 `GRAPH_INTEGRITY`）。
5. 不合法不变成业务状态：不填 0、不填空列表、不映射成 UNKNOWN。

### 1.10 与第 2 批裁决的两处不同（写明，不停工）

1. 裁决第 5 件说 Host 任务投影"不在运行时自己核自己"，Schema 放 Host 目录"如 `contracts/host-mission-list-v1`"。本车道说明要求"放在 SDK 现有公开合同同一处""Host 转发前按它校验"。按车道说明做。理由：详情里有一大半是原样转交的 SDK 读模型行，Host 并不是全部字段的权威；Host 端核一次能在日志里留下具体位置，前端只能看到一句话。代价：改 Host 投影要同步改 SDK 里的 Schema 并发版（字节一致用例会提醒）。
2. 裁决第 5 件范围还列了 `mission_events`、`mission_approval_list`、`mission_notices`。U09 条文（`07-补齐清单.md` L265）与车道说明只列四类。本车道只做四类，另三项见偏差单 R4-1。
