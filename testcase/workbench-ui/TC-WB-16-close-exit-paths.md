# TC-WB-16 — 红钮与退出路径矩阵（B13）

> 对应 AC：WB-1（窗口生命周期面）、WB-10（各退出路径后几何恢复）｜ 行为契约：**B13**（裁决第 8 条：红钮=完全退出，与托盘「退出」等价，沿用 Destroyed→exit(0) 连带回收后端的现状设计，防 8100 孤儿端口）
> manual_required: true
> 判定纪律：三条退出路径全部按"完全退出"单一分支判定；**任何分裂态**（如红钮退出但托盘图标残留、窗口消失但后端进程存活、进程退了但 8100 端口仍被占）即 FAIL。

进程/端口核对命令（每条路径退出后执行）：
`pgrep -fl "simple.harness\|deskpet\|tauri" ; lsof -nP -iTCP:8100 -sTCP:LISTEN ; true`
预期：主进程、backend 进程零残留；8100 端口无 LISTEN。
**dev 模式豁免注**：dev 下 pgrep 会命中 dev 包装进程（`cargo tauri dev`/vite dev server 等）——启动后先记录这些包装进程 PID 作对照，退出核对时豁免**且仅豁免**这些已登记 PID；应用主进程与 backend 进程必须零残留。更干净的做法：本用例以**打包版**执行（无包装进程，核对命令零输出即过），二选一并记录所用方式。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 启动应用；拖拽窗口到非默认尺寸/位置（记录+截图，作为三条路径共用的几何锚点）。 | 窗口接受拖拽。 |
| 2 | **路径 A：标题栏红钮**。点击 mac 红色关闭钮。 | **完全退出**：窗口关闭、**托盘图标消失**、执行核对命令零残留、8100 无 LISTEN。窗口关而托盘残留 = FAIL（分裂态）。 |
| 3 | 重新启动。 | 正常启动；窗口几何恢复为步骤 1 的锚点值（红钮退出前几何已持久化）。 |
| 4 | **路径 B：Cmd+Q**。按 Cmd+Q。 | 同路径 A 判定：全清退出，核对命令零残留。 |
| 5 | 重新启动。 | 几何仍恢复锚点值。 |
| 6 | **路径 C：托盘「退出 Simple Harness」**。点击托盘退出项。 | 同路径 A 判定：全清退出，核对命令零残留。 |
| 7 | 重新启动。 | 几何仍恢复锚点值；三条路径的恢复结果一致。 |
| 8 | 隐藏语义反证：点击托盘「隐藏主窗」。 | 窗口隐藏但**应用仍在运行**（托盘图标在、进程在）——隐藏仅经托盘「隐藏主窗」路径，红钮不承担隐藏语义（B13）。 |

判定：步骤 2–7 三条路径全部"完全退出 + 重启几何恢复"且步骤 8 隐藏路径独立成立才 PASS。
