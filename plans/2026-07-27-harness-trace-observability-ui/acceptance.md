# 验收标准：Harness 执行轨迹可观测性与消息页交互优化

## 范围

- 包含：定位并修复 session `501eeac7-650a-4982-96f9-c52adebb718b` 中的 `provider_dispatch_unknown_after_handoff` 失败。
- 包含：细化 Text/Code 主生产链路的 Harness 分层事件，优先覆盖 `ProductTurnPreparer`、Run/Kernel、Driver 路由、AgentLoop/Workflow、模型调用、工具/Effect、完成与失败收口。
- 包含：消息页左侧「Harness 运行观察」的信息架构、展开详情、时间/耗时、滚动与增量更新交互、视觉层级和可访问性优化。
- 包含：在 Harness 观察区顶部展示当前项目 Context 状态，提供默认圆环摘要、展开明细、容量变化与压缩前后历史。
- 包含：历史 session 回放与实时运行使用同一结构化投影；新增数据默认可用，不保留默认关闭的已完成功能 flag。
- 明确不包含：重写整个 Harness、改造消息正文业务逻辑、把内部 Trace 上传到云端、在本期实现通用 Trace 查询平台。

## 功能验收条款

| AC-1 | 失败根因闭环 | 能从 session、持久化事件和生产调用链还原 `provider_dispatch_unknown_after_handoff` 的触发条件，形成具体到函数/状态转换的根因说明；修复后同类 handoff 不再落入 unknown，失败时也有稳定错误分类与可理解摘要。 | 必须 |
| AC-2 | Harness 主链全景 | 一次普通消息从产品准备到最终完成/失败的关键层级均出现在左侧轨迹中，顺序与父子关系能说明“用户命令如何在 DeskPet Harness 中运行”，不得只显示零散模型调用。 | 必须 |
| AC-3 | ProductTurnPreparer 细节 | `prepare_context`、`route_intent`、`plan_decision` 等实际执行步骤分别可追踪；每步显示状态、开始时间、结束时间、耗时，展开后可看到该步的结构化输入、实际产出、决策理由/路由结果及关联 ID。上下文详情能看出最终准备了哪些消息、历史/摘要、附件、工具、预算与约束。 | 必须 |
| AC-4 | 模型调用细节 | Harness 中每次模型调用独立显示 provider、model、attempt、开始/结束时间、耗时、状态和 token/usage（底层有数据时）；展开后能查看实际请求消息/关键参数和模型完整输出，不用另查日志。流式输出在完成后形成稳定快照。 | 必须 |
| AC-5 | 工具、Driver 与 handoff 细节 | Driver 选择、handoff、工具准备/执行、Workflow spawn、重试与完成守门均有结构化节点；展开后包含输入、输出/receipt、错误类型、重试关系和上一跳/下一跳，能直接识别 handoff 后由谁接管。 | 必须 |
| AC-6 | 默认隐藏与快速浏览 | 所有高体积详情默认折叠；摘要行保留步骤名、状态、时间和耗时。用户可逐项展开/收起，并有当前层级的全部展开/全部收起；展开长文本支持复制，JSON/文本均可读且不撑破布局。 | 必须 |
| AC-7 | 完整信息默认显示 | 不判断字段是否敏感，也不做遮罩；用户展开 Harness 或 Context 详情后直接看到完整原始信息，并可复制。高体积详情仍默认折叠。 | 必须 |

| AC-10 | 视觉与滚动条 | 使用与 DeskPet 深色主题一致的层级、间距、状态色、连接线、悬浮/聚焦态与细滚动条；原生滚动条不再覆盖内容或成为视觉主体，鼠标、触控板和键盘滚动均可用。 | 必须 |
| AC-11 | 历史与实时一致 | 打开历史 session 和观察新运行时使用同一轨迹组件与字段语义；刷新/重连不重复节点、不回退终态，缺失新字段的 legacy 事件有明确降级展示且不报错。 | 必须 |

| AC-16 | Context 变化历史 | 每次 Context 准备、追加、回收、page-in、摘要或压缩均形成有序历史样本并持久化，至少包含时间、事件类型、压缩原因、压缩前大小、压缩后大小、变化量、容量占比及关联 run/span。刷新、重连和打开历史 session 后仍可查看；重复事件按稳定 ID 去重。 | 必须 |
| AC-17 | Context 折线图 | Context 展开面板以折线图展示变化历史：X 轴为本地时间，Y 轴为 Context 大小；普通采样连续成线，压缩事件同时显示压缩前和压缩后数据点并用明显标记/连线表达下降。支持悬浮或键盘查看精确值、事件与关联步骤，并可切换绝对大小/容量占比；无历史、单点和超长历史均有可用表现。 | 必须 |
| AC-18 | Context 口径一致 | 圆环、明细、折线图和 ProductTurnPreparer 展开详情使用同一份版本化 Context 指标契约；大小优先使用实际 token 计数，无法获得时才使用明确标注的估算值。压缩后的当前值必须等于对应压缩事件的 after 值，不允许前后端各自推算造成漂移。 | 必须 |
| AC-19 | Context 真机闭环 | 真实消息页验收中触发多轮 Context 增长和至少一次真实压缩/摘要：圆环随增长更新，展开明细与持久化事件一致，折线图同时出现压缩前后点；刷新后历史恢复且图表数值不变。若无法在安全时间内自然触发压缩，必须使用真实生产入口的受控低预算配置触发，不得用前端伪造事件替代。 | 必须 |

## 非功能 / 边界

- 错误态：单个详情字段无法序列化、超长或缺失时，轨迹主体仍可显示；详情区给出局部降级，不使整个消息页白屏。
- 幂等：相同 `run_id/span_id/event_id/seq` 的重放只更新既有节点，不重复追加；终态不会被迟到的 running 事件覆盖。
- 性能：大轨迹必须采用有界渲染策略（虚拟化、分段或等效方案）；以至少 500 个节点的 fixture 验证 DOM/更新开销不会随全部历史无界增长，连续追加时输入与滚动仍可交互。
- 数据边界：数据保存在现有本地 Trace/Session 边界内，不为 UI 新增云端遥测；Inspector 本身不再判断字段敏感性，展开详情即显示原始值。
- 兼容：不破坏现有聊天消息、Artifact、workflow progress、历史 session 和 legacy trace 展示。
- 时间语义：统一展示本地可读时间；耗时基于单调时钟或持久化 duration，跨刷新后不重新计算出负值。
- Context 计量：历史样本使用版本化单位与 estimator/tokenizer 标识；模型/估算器变化后不得把不同口径的点无提示连成同一条精确曲线。
- Context 保留：变化历史采用有界持久化和降采样策略；压缩事件、峰值、终态和最近窗口不得被普通采样淘汰。
- 测试分类：本需求的展示/交互是确定性 UI，不套用输入语义敏感功能的三类问题矩阵；真实 UI 验收仍需至少覆盖普通成功、handoff/多阶段和失败三个运行形态。

- AC-1 至 AC-19 全部有 `AC -> task -> code -> testcase -> result` 证据。
