# F1 手测指南（你自己测，截图发我）

> **F1 是什么**：`assembler` 的 `ComponentRegistry.fanout` 从前是**一个整体超时**包住
> 所有组件 → 任一组件慢（比如 memory 撞 BGE-M3 冷加载）就让**全部组件**一起变空，
> 日志只打 `fanout_timed_out pending=[全部]` 无法定位。F1 改成**每个组件独立计时 +
> 独立软超时**：慢的单独降级，快的照常返回真内容，每个 slice 记 `duration_ms`/`status`。
>
> **你要验证的核心结论**：真实运行的桌宠里，code mode 跑任务时 assembler 正常工作，
> **不再出现 `fanout_timed_out pending=[全部]` 那种全体塌缩**，且 workspace_memory
> 组件能把"刚读过的文件"带进上下文。

## Part A — 不需要 LLM 的 F1 证据（现在就能测）⭐

F1 的修复本质是**后端 assembler 逻辑**，UI 不需要 LLM 也能触发 assembler 运行。

`G:\projects\deskpet-stage2-f1f2\plans\manual-results-2026-05-31-f1\tauri-clean.log`，

**然后**：打开日志文件，搜索这几个关键词，**截图发我**：
- 搜 `fanout_timed_out` → **期望：搜不到，或即使有也只列单个组件名，不是"全部组件"**
- 搜 `component` → 看有没有 `component_done` 带 `duration_ms`
- 搜 `assembl` → 看 assembler 活动

> **判定**：
> - 搜不到 `fanout_timed_out pending=[memory,persona,tool,time,workspace,workspace_memory]`
>   这种**全体塌缩** → **PASS**（这正是 F1 修复掉的旧 bug）
