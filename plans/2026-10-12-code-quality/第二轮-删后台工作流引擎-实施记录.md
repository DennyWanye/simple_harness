## 二、与方案草稿不同的地方

| 方案原写 | 实际 | 原因 |
|---|---|---|
| 激活阶段 `legacy`/`draining` 直接报错 | 照常推进；排空清单里有旧运行才报错 | 全新库的种子就是 `legacy`（schema.py 禁区），直接报错会让每个新装用户启动失败（处置表坑 1） |
| effects 只留类型 | 留 `StagedFileLifecycle` 行为 | registry.py（字节冻结）顶层导入它 |
| `collect_subagent_research` 只服务 v7，删 | 保留 | 它在 deepresearch 工具自己的扇出路径上 |
| research_core 与 research_tools 互相函数内导入 | 改为模块顶层互相导入 | 函数内导入标"循环依赖"会让循环依赖指标涨；两边导入期都不读对方的属性，顶层互导安全 |
| `host/ppt_outline.py` 逐函数判定 | 整个删除 | 全部函数都只服务旧引擎的 ppt_pro v1 与已删的大纲卡 |
| 只删 `[workflows]` | 同时删 `[research_v5]` | 只有旧 v5 定义读它 |

## 三、留下的东西

- `deskpet/workflows/`：`contracts.py`（JSON 值与工具效果类型）、`errors.py`、`effects.py`（工具效果类型与暂存文件提交）、`harness_delivery.py`（事件投影）、`store/`（执行账本、表结构、写通道）。包名不改：冻结工具清单钉了 `deskpet/tools/registry.py` 的字节，它从本包导入。
- 引擎专用表（`workflow_*`、`eval_*`、`trace_*`）留空表，表结构属禁区，以后的"存储层整理"一起处理。
- SDK 产品定义只用来生成能力目录，生产里没有持久工作流在跑；要让深度研究或 PPT 持久运行是另一个功能项目（与 F-WF-1 一起定）。
- `ppt_tools.set_ppt_pro_services` 已无调用方，但 ppt_tools.py 字节冻结，不改。
