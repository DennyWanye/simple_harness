# SDK 侧交接：统一主 Session、按需 HTN/TaskGraph 委派与 Realtime

日期：2026-10-24。交付对象：Simple Harness SDK / Service SDK 维护者。

**执行要求：请在 SDK 侧实现并发布可安装制品。AIPhone 暂不实现业务连接逻辑，待 SDK 发版、提供兼容清单与验收证据后再接入。本文是待实现合同，不是已交付功能说明。**

本说明可独立转发。接口名称是语义草案，维护者可按现有命名调整，但不能遗漏行为。仓库与制品保持现有私有分发范围，不将私有源码或制品上传公开仓库。

## 1. 要实现的用户体验

用户通过文字或 Realtime 语音进入同一个逻辑主 Session：

1. 日常聊天、解释、简单工具查询直接处理，主回合不进入 HTN/TaskGraph。
2. 主 Session 模型判断需要复杂执行、持久交付或独立审阅时，调用 SDK 内置委派命令。
3. SDK 建立关联 mission，由现有 HTN、TaskGraph、执行器与审阅流程完成；主 Session 可以继续交流。
4. 任务进度、需要用户回答的事项与最终结果回到原 Session；通话在线时可以播报，离线时保存在会话中。
5. 文字创建的任务可以用语音查询或取消，语音创建的任务也可以在文字界面继续处理。

"子代理"在这里指独立受委派工作单元；内部仍可有多个规划、执行和审阅角色。第一版只允许一层委派，默认最多一项同时在途的委派，允许会话先后处理多项任务。

目标是复用现有 SDK，不新造 Agent Runtime。普通回合不执行规划，不等于承诺 Host 启动时完全不初始化编排基础设施。

## 3. 能力归属与建议结构

| 归属 | 必须承担的工作 |
|---|---|
| 编排 SDK | 主 Session 的持久身份/历史/事件、文本 ReAct、委派控制、任务关联、权限与预算、任务执行、结果 inbox、恢复 |
| Service SDK Realtime | 通道绑定、工具目录协商、语音模型事件/工具调用规范化、结果回写、上下文同步、播报调度、打断/挂断、重连、诊断 |
| SDK 联合适配 | 将 Realtime 与主 Session/委派连接；若跨进程，提供版本化协议、鉴权、幂等与可恢复客户端，不由每个 App 重写 |
| TokenSeller/chinzy | 现有凭据签发、relay、上游协议适配和计费；新增 wire 能力如需服务端改动须列为配套交付，不能只改客户端能力标志 |
| AIPhone | UI、麦克风采集、扬声器播放、播放进度上报、用户输入、设备只读工具、配置凭据、SDK 进程安装与生命周期 |

SDK 拥有通用编排、会话和语音连接逻辑；手机音频驱动与 UI 仍在宿主。录音、播放的适配接口应可被其他宿主实现。不要为了"都在 SDK"把手机专用设备代码硬编码进核心库。

**一个逻辑主 Session 不要求所有通道使用同一个模型或网络连接，但必须只有一个已提交会话历史和一套业务权限。**文本可沿用现有 ReAct，语音优先保留原生 Qwen Realtime 的听说与工具调用。相同语音输入不能同时驱动原生语音模型和另一条 `chat()` 去作业务决策、重复创建任务或双重播报。

第一阶段必须验证原生语音的工具配置、可信调用关联、历史注入、后台结果播报能力。若当前线路不支持，明确 `unsupported` 和具体缺口；转写→文本 Session→语音合成是不同延迟/听感的替代架构，不能静默切换后称为原生 Realtime 验收通过，需回传取舍再定。

## 4. 需要补齐的公开接口

| 接口语义（建议名） | 必要输入/行为 | 必要结果 |
|---|---|---|
| 打开/恢复主会话 `session_open` | 会话标识、可信用户/租户、配置版本；策略含模型决定委派、能力范围、预算、最多在途数和深度 | session_id、配置版本、状态、实际可用能力、事件游标 |
| 输入文字 `session_send` / 兼容 `chat` | session_id、文本、幂等键；同会话顺序接纳，重复请求可查询 | turn_id、受理/完成状态；流片段只是预览，提交结果可读 |
| 会话查询 `session_snapshot/history/events` | 会话、分页或 after_seq；鉴权；游标过期给出明确重取方式 | 已提交历史、任务关联、审批、待交付事实和稳定事件 ID |
| 委派 `delegate_task` | 模型仅提出目标、成功条件、资料引用、简短原因；可信上下文由 SDK 注入 | delegation_id、mission_id、幂等回执、真实状态；立即返回，不等待任务完成 |
| 查询/取消 `task_status/task_cancel` | 关联委派标识；所有权验证、幂等取消 | 最新任务状态，区分取消已受理和取消已完成 |
| 回答/审批 `session_respond` | request_id、版本、答案或决定、可信操作人、幂等键 | 对应现有 mission 回写回执；过期/越权明确拒绝 |
| 停止回合 `session_interrupt` | session/turn 标识，明确作用域 | 当前回合停止状态；不暗中取消已受理任务 |
| 绑定语音 `realtime_attach` | session_id、通道身份、profile、必要能力、音频格式、授权；SDK 装配工具目录 | binding_id、连接 generation、能力协商结果、业务事件关联 |
| Realtime 工具循环 | 可配置 schema 目录；接纳完整、验证后的调用；内部 dispatch；结果 ACK/续答 | 稳定调用关联、SDK 业务回执、工具错误；不让 App 执行或解析模型命令 |
| 投递后台结果 `session_deliver`（可内部实现） | 任务持久事件，关联会话和版本；摘要/产物引用；选择当前可用通道 | 持久投递状态；离线不丢；无旧调用可依附时仍可合法通知，不能伪造 function_call_output |
| 播报状态/打断 `realtime_playback/interrupt` | response/item、generation、实际播放位置；停止本地排队音频与必要生成 | 区分生成结束、传输结束、实际播放/被截断；过期帧不再播放 |
| 挂断/解绑 `realtime_detach` | 连接标识及原因 | 音频/网络资源释放；逻辑 Session 与 mission 保留 |
| 关闭会话 `session_close` | 区别归档、关闭连接、关闭 Host；明确子任务策略，默认保留任务 | 可恢复记录；不以关窗口推断取消任务 |

受控作用域至少区分 session 与 mission：可信上下文包含 principal/tenant、session_id、turn_id、call_id，mission_id 在普通会话中可为空。不得由模型传入身份。现有只读工具保持只读；创建/取消任务是内置控制能力，设备写操作继续走既有连接器和审批。

任务事件统一携带 schema_version、event_id、session_id、seq、类型以及适用的 turn/delegation/mission/request 标识；语音另外携带 binding_id、generation、response/item/call 标识。不要用 transport correlation 替代长期业务身份。各类事件明确必填/可选字段、时间戳、可重放范围和大小上限。

错误应使用稳定码并说明是否可重试：例如 invalid_request、unsupported、forbidden、idempotency_conflict、stale_version、busy、budget_exhausted、unavailable、timeout、outcome_unknown。沿用已有等价码即可，不强制重复造枚举。为首次受理、执行等待、结果确认分别定义超时；超时不等于命令未执行。

## 5. 文本与任务闭环的强制语义

1. **决策与准入分开。**主 Session 模型决定是否委派；SDK 校验目标、工具、权限、预算和并发，不靠长短或关键词强制建任务。缺少搜索能力时不能编造 GitHub 热点。
2. **持久创建。**意图、预算预留、mission、关联和回执必须能对账。跨数据库使用持久命令/outbox/reconciliation，不能声称不存在的跨库原子事务。同一操作重试只创建一个任务；同键不同规范拒绝；同目标的新意图可建新任务。
3. **防止模型重复委派。**稳定键来自已提交用户输入和真实调用身份；新 call_id 不应绕过同一意图的去重。不能只按目标文本去重而吞掉用户明确的新工作。
4. **结果可恢复。**终态事实与产物引用进入持久 inbox；至少一次传输、幂等应用。网络与模型调用不承诺天然 exactly-once；结果未知时不得自动重放收费请求或改写成成功。
5. **会话顺序。**同一会话只有一个逻辑写入调度者；文本、已提交语音事项、任务完成和用户审批按明确顺序处理。任务长时运行不持有会话锁。回传总结默认不自动派生新任务。
6. **结果真实性。**创建回执不等于完成；取消受理不等于取消完成；只有任务权威终态才能宣称成功。产物正文视为资料，不能提升为系统指令。
7. **预算归属。**chat、mission、Realtime 分项可观测，统一会话限额不重复结算。Realtime 音频计费单位不能直接当作文本 token 相加；公布计量/金额换算、未知用量处理、预留释放和结算权威。检查大额聊天预留是否挤占任务额度；保留受限的结果回传额度，耗尽时仍可无模型展示真实状态。
8. **权限交集。**任务能力不超过宿主与主 Session 的授权；模型不能自行批准外部动作。普通委派是否需确认由明确策略决定，不能把 auto_mode 等同于无限授权。
9. **取消竞态。**创建中取消需持久化并在创建成功后收敛；已完成的任务不倒改成取消。停止当前回合/通话不会撤销已经受理的任务。

## 6. Realtime 专项要求

### 6.1 工具调用与文字/语音共存

- SDK 把同一套委派/查询/取消能力提供给原生语音模型，只有完整且经过 schema、身份与预算校验的工具调用能执行。参数 delta、部分转写、关键词匹配和模型说"已创建"均不能作为任务命令。
- 原生语音路径中转写用于显示/历史，不再送到另一条自动任务创建链。关联用户音频 item、response、tool call 和 mission；重复事件、重连重放去重，旧 generation 调用拒绝。
- 转写晚到、为空或失败时也必须有策略：原生工具调用能与已提交音频输入可靠关联才可接纳；身份或目标不明则拒绝/澄清，不凭空生成用户文本。
- 同一逻辑会话任一时刻只有一个回合决策执行者。通话期间文字输入可走原生模型已协商的文字入口，或有序排队到切换后的文本引擎；首版必须选定并公开行为。不得两个引擎同时回答同一输入。取消等确定性控制走受控命令，不被漫长模型回合阻塞。
- 当前模型/provider 不支持所需文本或历史注入时，明确报不支持或在安全边界重建连接，不能静默丢失会话上下文。

### 6.2 后台任务完成与播报

- 工具调用先快速返回"已受理 + 任务 ID"；不能占住语音工具结果 ACK 等到任务结束。
- 最终任务结果属于新的持久事实，不是对已结束 tool call 的第二份结果。SDK 提供合法的上下文注入/主动通知途径，支持任务数分钟后完成时播报。
- 用户正在讲话时延后结果播报；当前有输出时按明确优先级排队，不能重叠播放。错误/需审批和普通进度分别处理，不朗读每条内部调度事件。
- 生成完成、已发送音频和用户实际听到必须分别记录。播报被打断时保留未播内容与任务结果，不默认自动从头重播，也不把未听完视为批准。
- 挂断后任务继续；完成结果留在 Session。再次接通按未处理结果与上下文策略恢复，不擅自开麦或自动发起通话。

### 6.3 打断与取消的分离

| 用户动作 | 预期影响 |
|---|---|
| 说话打断/停止播报 | 清理本地待播放队列并按能力取消仍在生成的 response；不取消后台任务 |
| "取消刚才那个任务" | 主会话识别具体任务，调用同一 SDK 取消入口；多个可能目标时澄清 |
| 挂断 | 关闭当前 Realtime、麦克风、播放和网络资源；保留逻辑会话与任务 |
| 关闭 App | 按宿主生命周期解绑通道；后台 SDK 任务继续 |

必须保留现有避免自动打断重复发 cancel 的行为；已结束的 response 仅清播放队列，不能盲发 response.cancel。按上游实际协商结果决定取消责任方。

Qwen 当前声明不支持 truncate：不能伪造成功或保证其服务端历史已删除未播放内容。SDK 要记录播放范围与中断事实，并验证后续上下文校正/重建策略；若只能保留有限一致性，公开限制并验收，不向用户谎报"已经听到"。

### 6.4 连接、恢复与授权

- 业务 session_id 稳定，Realtime connection/generation 可更换；不把断线等同于结束业务 Session。
- `resume=False` 时以新连接恢复经 SDK 选择的已提交上下文与未处理结果，不重放原始音频或重复命令。是否恢复、恢复多少、历史超限如何压缩需有公开规则与证据。
- 重连次数、退避、超时、凭据刷新和费用有上限；失败时文字历史和任务仍可查询。区分 mint、连接、握手、首事件、工具 ACK、首音频与关闭阶段。
- 工具白名单、schema 与权限通过 SDK 配置下发并确认，不能只靠 instructions 文本约束。能力声明须与真实线路测试一致。
- 默认语音可发起获准的只读/内容任务；语音中的"好""可以"不能自动成为任意待审批高风险动作的授权。需明确绑定 request_id 与可信用户操作；不能满足时保留 UI 确认卡。
- 不默认持久化原始音频；凭据不进入历史、事件或诊断。转写及会话记录提供宿主可配置的保留策略。

## 7. 兼容与发行要求

1. **兼容旧消费者。**旧 chat 默认仍只读；旧 create_mission、事件、取消及已有 Realtime 独立使用路径继续可用。新能力显式启用，不强制所有消费者升级为统一会话。
2. **版本与依赖。**提供完整兼容表：Harness、Service SDK、可选 Memory、Python、平台、schema、Realtime 控制协议/能力版本以及需要的 TokenSeller 版本。至少验证目标 Linux ARM64/Python 3.13；保留原有受支持平台检查。
3. **依赖解决方案。**优先发布能在新虚拟环境解析安装的 SDK 组合；若保留隔离进程，跨进程连接与恢复同样由 SDK 提供。不得要求 AIPhone `--no-deps` 强装冲突包、同时混用同名包版本、复制 SDK 内部代码或关闭类型检查。
4. **工具目录与执行池身份。**已有会话工具冻结；新策略启用必须有配置版本、迁移/新代会话方案。不能悄改提示、工具或池身份导致旧数据打不开。
5. **schema 迁移。**迁移前检查与备份；明确哪些可逆。旧 wheel 不读取不兼容的新 schema。提供保留升级后新数据的失败处理方案，不能无提示覆盖备份回滚。
6. **协议与错误。**新增字段、枚举和本地控制消息明确版本兼容；双方不匹配应启动失败或能力降级并可诊断，不能静默丢掉任务事件。
7. **性能与并发。**分开计量 SDK 排队、模型延迟和音频播放延迟。验证任务与聊天/语音共享资源时的优先级和无饥饿，不承诺能抢占上游在途推理。在候选验收前冻结同设备基线与阈值，不能事后改阈值掩盖退化。
8. **SDK 实现标准。**按各 SDK 仓库规范，主体开发由主代理完成；开发中只做阻塞所需局部检查，主体完成后做适用回归、公开接口检查与独立累计评审。禁止用全局 ignore/noqa 或删除断言替代修复。

## 8. 验收标准与责任分阶段

SDK 发版门槛与 AIPhone 接入后验收分开。SDK 必须先交可消费候选与自身证据；手机硬件项目不能靠脚本结果代签。所有证据记录候选提交、wheel SHA256、配置/协议版本、运行标识与实际结果，保护凭据、音频和私有对话。

### A. SDK 发行前必须通过

| 编号 | 场景 | 判定标准 |
|---|---|---|
| A01 | 普通文本/只读查询 | 主会话正常响应，有真实工具回执；该请求不产生 mission 或 HTN/TaskGraph 执行 |
| A02 | 文本复杂任务 | 真实模型作委派决策；一个关联任务实际规划、执行、审阅并交付可校验文件；回到原 Session |
| A03 | 幂等与竞态 | 同键重试一个任务、异规范冲突；创建中/运行中/完成后取消状态确定；新意图不被误去重 |
| A04 | 创建/回传故障注入 | 每个持久关键点退出并恢复，无重复/失联任务、丢结果或重复应用；未知上游结果如实暴露 |
| A05 | 预算/权限/审批 | 无越权、双记费用、失控预留；耗尽仍可读任务事实；审批绑定正确请求，过期回复被拒 |
| A06 | 真线路语音工具闭环 | chinzy→实际上游配置确认 tools；真实语音模型发起调用；SDK 建任务、回写结果并续答；不能只用模拟工具事件证明 |
| A07 | 三轮录音对话 | 连续三轮输入转写、回复文本和音频完成，连接可继续；分别保留结构化证据与受控音频校验 |
| A08 | 语音委派→异步播报 | 录音发起任务→任务运行期间继续闲聊→任务完成→原 Session 收结果→在线合法播报；不是重复提交旧 tool result |
| A09 | 跨通道一致性 | 文字建任务语音查询，语音建任务文字查询/取消；相同输入仅一个业务决策路径，历史和任务不串会话 |
| A10 | 打断分层 | 输出中插入录音，旧音频停止且后续能响应；无重复 cancel/旧帧串音；仅打断不取消任务，显式任务取消才生效 |
| A11 | 断线/挂断/重启 | 断线和挂断不丢任务；新连接不复用旧 generation 或重复命令；恢复上下文和待交付事实；关闭资源回零 |
| A12 | 超时/不支持/坏消息 | 按阶段报告失败；工具参数分片/重复/畸形不误执行；能力缺失不伪装通过；无无限重试 |
| A13 | 实际声音投递语义 | 生成、传输、播放确认分离；中断保留正确事实，未播完不等于用户已听或已批准 |
| A14 | 仓库外与兼容 | 空目录仅装发布 wheels，经公开接口跑通文本及录音 Realtime 委派；不导入 AIPhone 或私有属性；旧只读/旧语音消费者仍通过 |
| A15 | 质量与发布 | 适用格式/lint/严格类型/边界/回归通过，独立评审收敛；迁移与回退演练，制品清单完整 |

A06/A08 需要冻结真实场景和预期，再核验模型真实调用；人工路由集包含直接回答、澄清、缺能力、委派，报告误委派/漏委派，不以一次演示替代质量评价。系统约束应确定通过。电话声音效果不能从 A07–A13 推导已完成真人验收。

### B. SDK 发版后，AIPhone 再接入并验收

| 编号 | 手机 Linux 验收 | 通过标准 |
|---|---|---|
| B01 | 安装与默认入口 | 校验清单，干净环境安装；App 文字/Realtime 进入同一逻辑 Session；仅一份 SDK 业务权威 |
| B02 | 实际文字/语音任务 | 从 App 创建、持续交流、查看产物、任务等待用户、取消；均由手机 SDK 完成，无 Mac 执行依赖 |
| B03 | 三轮真人麦克风 | 真人连续三轮获得可理解回复、对话可继续；核对麦克风、转写、响应、播放日志和本人听感 |
| B04 | 真人说话打断 | 说话时停止旧播报，正确回答新请求；无明显回声/自触发/双重回复；任务不被误取消 |
| B05 | 资源/稳定性 | 正常挂断、异常断线、后台任务并行与至少 120 秒通话检查；采集/播放/网络关闭后回零，不妨碍设备其他输入 |
| B06 | 服务/整机重启 | 重启 SDK 进程及手机后 Session/任务/待交付结果可恢复；不重复建任务，不自动开麦 |
| B07 | 升级与回退 | 确切候选制品、schema、配置有记录；旧功能与数据按兼容合同保留，回退按已验证流程执行 |

如真人暂不可配合，B03/B04 明确标为未完成，不能以预录音或设备采集到环境声替代。SDK 可交合格候选供接入，但不得宣称 AIPhone 整体验收完成。

## 9. 推荐实施顺序

1. **锁定合同与可行性门槛：**匹配源码/制品，选择兼容包或 SDK 自有跨进程方案；用小范围真实链路验证 Realtime tools、背景结果注入、历史续接和当前 Qwen 限制。能力无法满足时先提交明确缺口与替代方案，不能把不支持留给 App 临时绕过。
2. **完成 SDK 主体：**统一 Session、内置委派、可信作用域、持久关联/inbox、预算与取消；接入 Service SDK 的真实工具循环、通道调度和生命周期。
3. **完成 SDK 验证：**运行 A01–A15、适用回归和独立评审；在仓库外新环境验证发布 wheels，整理残留问题。
4. **发布并交回：**给出版本、私有制品、哈希、兼容表、接口说明和运行示例。涉及 TokenSeller 的配套候选与上线顺序单独注明，不把 SDK 发版当作生产服务已变更。
5. **AIPhone 再接入：**消费新 SDK 的公开入口，接手机音频/UI/三项只读工具，执行 B01–B07。此阶段之前 AIPhone 不编写另一套委派或语音业务连接逻辑。
