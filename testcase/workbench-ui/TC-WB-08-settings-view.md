# TC-WB-08 — SettingsView 设置页面化与逐项保留

> 对应 AC：WB-8 ｜ 行为契约：B6、B12（自启开关入设置页）
> manual_required: true
> 权威快照（裁决第 2 条，`plans/2026-08-04-workbench-ui/oracle-clarifications.md`）：以改版前 SettingsPanel 分区为准，核对表见步骤 2；「桌宠形象」为**唯一**预期消失项。
> 执行隔离：使用可删除的测试 profile；只填测试用 dummy key，不改生产凭据。所有可编辑项都必须记录原值，并在本例结束前恢复。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 点击侧栏底部「⚙️设置」。 | 设置以**页面**呈现于内容区：无 backdrop 遮罩、无浮层定位。 |
| 2 | 按下方分区核对表逐项打勾并分类：<br>**可编辑**：① Provider/模型配置（含编辑弹层内的 API key 管理）、④ 数据目录、⑤ Agent 有效执行预算、⑦ 自启开关；<br>**只读**：② Embedder 状态卡、③ 模型上下文卡；<br>⑥ 原「云端 API key 管理」能力现在并入①，不要求重复出现独立卡片；<br>⑧ 「桌宠形象」区块。 | ①–⑦ 的能力**逐项存在**（缺任一能力即 FAIL）；②③不得伪装成可保存表单；⑧「桌宠形象」区块/下拉**不存在**（唯一预期消失项，出现即 FAIL）。 |
| 3 | 观察 Embedder 状态卡和模型上下文卡；覆盖正常态，并在可构造时记录未加载/错误态。不要寻找或点击不存在的「保存」。 | 两卡只展示当前状态/上下文信息，没有可编辑输入或保存按钮；未加载/错误须诚实显示，不能无限 loading，也不能因无法编辑判失败。 |
| 4 | 在测试 profile 中记录原 Provider 列表。通过「+ 添加」创建一次性 `wb08-reversible-fixture`：测试名称、`http://127.0.0.1:9/v1`、至少一个测试模型、非生产 dummy key；保存后立即将其停用。不要点「自动获取」。 | 卡片出现且停用态明确；列表/编辑弹层中的 key 只显示掩码，截图和日志均不得出现明文；由本次 UI 操作触发的后端 provider add/update 回执成功。 |
| 5 | 完全退出并重启，回到设置页，打开该 fixture 的编辑弹层核对非敏感字段。 | fixture、停用态、模型与默认模型均保持；API key 仍为掩码/留空保留语义，证明保存结果由重启后的后端列表重新投影，而不是前端临时态。 |
| 6 | 删除 `wb08-reversible-fixture`，确认删除；离开设置再返回一次。 | fixture 消失，后端 delete/list 回执成功；其它 Provider 的顺序、启用态、模型与凭据均未改变。 |
| 7 | 记录 Agent 有效执行预算原值 `N`；选取范围内不同值 `N'`（优先 `N+1`，到上界则 `N-1`）并输入。该项随输入即时应用，没有独立保存按钮；随后离开设置再返回。 | UI 无报错；重新读取的预算为 `N'`，且本次 UI 操作触发的后端 timeout set/get 回执一致。只看到输入框数字变化、没有后端重读证据 = FAIL。 |
| 8 | 完全退出并重启，核对预算仍为 `N'`；随后恢复 `N`，离开设置再返回核对。 | 重启后仍为 `N'`；恢复后重新读取为 `N`。 |
| 9 | 记录「当前生效」数据目录原值 `D`。新建一个**空的、专用于本例**的绝对目录 `D'`；不勾选迁移现有数据，应用 `D'` 后按 UI 提示完全退出。 | 应用成功并明确提示需要重启；不得复制、移动或删除 `D` 中的现有数据。 |
| 10 | 重启应用，进入设置页，并核对本次启动的 backend 日志。 | UI「当前生效」为 `D'`，backend 启动配置中的 user-data 路径也为 `D'`；两者不一致或只改输入框 = FAIL。 |
| 11 | 将数据目录恢复为 `D` 并再次完全退出/重启；核对 UI 与 backend 启动配置后，确认 `D'` 没有从 `D` 迁入的旧数据，再在应用退出状态删除整个专用测试目录 `D'`。 | UI 与 backend 均恢复 `D`；`D'` 只允许包含本例启动时新生成的测试 profile 数据，不得含 `D` 的历史副本；测试目录清理完成。若恢复失败，不得继续删除任何目录。 |
| 12 | 记录自启开关原值，并核对系统观察面（`~/Library/LaunchAgents` 对应 plist 或系统设置·通用·登录项）。 | 「开机自动启动」开关存在；UI 原值与系统观察面一致。 |
| 13 | 将自启开关切到**原值的相反值**。该开关即时生效，没有独立保存按钮。 | 切换无报错；同一系统观察面同步改变。仅 UI 态变化不算真实生效。 |
| 14 | 完全退出应用并重启，回到设置页。 | 自启开关保持步骤 13 的值，且仍与系统观察面一致。 |
| 15 | 将自启开关恢复到步骤 12 的原值，并再次核对系统观察面。 | UI 与系统观察面均恢复测试前状态。 |
| 16 | 最终完全退出并重启，复核 Provider fixture 不存在、预算=`N`、数据目录=`D`、自启=原值。 | 四类可编辑设置全部完成“修改→保存/即时应用→重启或后端/系统观察→恢复”；无残留才允许 PASS。 |

> **已退役项（不编号、不判定）**：旧数据兼容/升级配方于 2026-08-09 经用户裁决退役。产品不承诺旧会话、旧 provider 或 relay key 迁移；处置方式是删除旧数据，不是升级兼容。

判定：步骤 1–16 全部满足且最终恢复检查无残留才 PASS。只读卡只判展示与错误诚实性；不得因其没有保存能力判 FAIL，也不得用只读卡观察代替四类可编辑设置的持久化验证。
