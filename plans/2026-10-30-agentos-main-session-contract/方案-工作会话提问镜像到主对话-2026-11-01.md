# 方案：工作会话的提问镜像到主对话（2026-11-01）

用户 2026-11-01 拍板："改，在这里做"。来源：桌面真机一局（opt.224）发现的设计空白。

## 一、问题

- 工作会话（子会话）的任务要人裁决时，SDK 只把 `needs_response` 写进工作会话自己的事件流。
- 父会话（主对话）事件流里没有这条事件。桌面主对话只有任务卡上的 BLOCKED 字样，没有可点的裁决卡。
- 父会话的 `respond()` 其实已经能答子任务的请求（它遍历 `tasks()`，含子任务）。缺的只是"告诉父会话有这件事"。

## 二、做法（同一件事只留一条路径）

### SDK（`host/inbox.py`）

1. 父会话每一拍镜像子会话时（`_mirror_children`），除子结果外，再按**子事件序号游标**读子事件流里的 `needs_response`，原样镜像到父事件流：
   - 事件 `kind` 仍是 `needs_response`，顶层加 `child_key`，payload 加 `child_key / child_session_id`；
   - 事件键沿用 `request:{request_id}:{version}`，重复补读、重开都不重复发；
   - 父账本 `requests` 也登记一行（带 `child_key`），答过以后再答报 `stale_request`，与父自己的请求同口径。
2. 游标 `cursors["child_events:{child_key}"]` 随镜像同事务推进。子会话先补读、父后镜像（崩溃点）也不漏。
3. 审批类请求的 payload 补 `kind`（review / arbitration / action / source_change），卡片才能给对的按钮。
4. `capabilities()` 新增 `child_request_mirroring`。协议版本不变（只加字段）。

### Host（`backend/deskpet/orchestration/session_bridge.py`）

- `needs_response` 白名单加 `kind / child_key`；任务投影加 `child_key`。

### 桌面端（`tauri-app/src/views/PrimaryChatView.tsx`、`ChatMissionCard.tsx`）

- 裁决卡：有 `child_key` 时先写一行"工作会话「X」的任务在等你裁决"。
- 审批类按 `kind` 给按钮：复核 → 复核通过 / 复核不通过；仲裁 → 裁决选项（met / unmet，要写依据）；其余 → 批准 / 拒绝。规划问题不变。
- 任务卡标出所属工作会话。

## 三、不做

- 不改任务编排页；它仍能答，同一条 `respond`。
- 不给子会话新接口；镜像方向只有子 → 父。
- 语音：父会话语音播报本来就播 `needs_response`，镜像后自然会播，不另加逻辑。

## 四、验证

- SDK：`tests/orchestrator/host/test_session_tree.py` 新用例——子会话先补读、父后镜像、父直接作答、重开不重复、答后 stale；审批类带 `kind`。
- Host：`backend/tests/orchestration/test_session_bridge.py` 投影保留 `kind / child_key`。
- 桌面端：`SessionPrimaryChatView.test.tsx` 子会话提问卡、仲裁卡。
- 改坏检验（事件按请求键去重，所以"不推进游标"不会重复发事件，用例用游标断言抓它）：① 去掉游标推进；② 镜像时丢 `child_key`。两处改坏都要让用例变红。
- 发版 opt.225 后在桌面开发数据副本上起一次，确认主对话出卡。

## 五、独立核验与处置（2026-11-01）

评估文件：《评估-工作会话提问镜像-独立核验-2026-11-01.md》（opus 只读子代理）。必须处理：无。六条建议的处置：

| # | 建议 | 处置 |
|---|---|---|
| 1 | 父账本 `requests` 行那条路径没有用例保护 | 已补：请求从快照消失后再答仍报 `stale_request`；改坏"镜像时不写 requests 行"用例变红 |
| 2 | 任务找不到时卡片默认显示，若将来桌面端开放子会话归档会残留 | 不改：桌面端现在没有归档入口；开放归档时一起处理 |
| 3 | 界面又白名单了一次 `met/unmet` | 已改：按 SDK 给的 `options` 出按钮 |
| 4 | 语音播报的 payload 带 `child_session_id` | 不改：与子结果通知同口径，不是泄漏 |
| 5 | 旧数据第一次跑新代码会一次性镜像子会话全部历史提问（语音会播已答过的） | 不改：开发期不兼容旧数据；写在这里当发版说明 |
| 6 | 文档先写了"已发版" | 发版脚本跑完后核对提交号 |

改坏检验结果：不推进游标、丢 `child_key`、不写 `requests` 行，三处都让用例变红，恢复后哈希一致。
