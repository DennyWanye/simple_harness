# SDK 任务编排宿主入口（方案与实施记录）

- 日期：2026-10-19
- 依据：用户"Python 应用，我期望使用这个 sdk 做编排"；两点决定：这一版只支持 DeepSeek；桌面端后端这一轮一起改用新入口。
- 分支：orch-host（主检出）。

## 一、问题

真机测试证明的是"SDK + 桌面端后端自己写的接线"这个整体。接线约 7350 行在 `backend/deskpet/orchestration/`，其中外部应用也必须有的约 2000 行：建模型连接、选计费器、规划世界、拼装与启动、驱动循环、沙箱探测、建任务门口检查。别的 Python 应用只装 SDK 就没有这些，也没有说明文档。

## 二、方案

1. SDK 加公开包 `agent_orchestrator.host`：
   - `OrchestrationHost`：`open(root, principal=, model=ModelConfig, tokenizer_path=, settings=HostSettings, auto_mode=, publish_dir 在 settings 里, models_dir=, notify=)`；也可注入 `provider= / counter=`（测试替身或别的接法）。
   - 拼装顺序照后端：实例锁 → 部署验收门 → 发布连接器 → 沙箱探测 → 部署策略 → 原生执行池 → 用户任务部署 → Orchestrator → 门面。
   - 操作：建任务（含附资料）、资料三动作、列表／详情／事件／审批、授权规划、回答提问、确认完成要求、改要求、提交操作、取消／接管／裁决、评论、取产物、状态、全局月配额。
   - 驱动：`run_forever`（常驻，含退避、重建、降级）、`run_until_settled`、`run_once`／`drain`。
   - 门口检查与后端一字不差：空目标／空要求、密钥、`pytest:` 要沙箱、`action:` 要连接器、补 `file:` 来源、默认运行档与预算（同幂等键重试沿用原任务的）。
2. 随之进 SDK 的：`host/settings.py`（模型配置、运行参数）、`host/provider.py`（提供方与计数器选择）、`host/instance_lock.py`（跨平台文件锁）、`host/script_runner.py`（沙箱脚本执行器，原 `skill_script_runner.py`）、`host/embedding.py`（BGE-M3 向量端口，原 `native_plane.py`）、`host/tokenizer.py`（钉死分词文件的取得与核对）、`deployment/goal_world.py`（规划世界，按 `domain` 加前缀；桌面传 `desktop`，类型名与原来逐字相同）。
3. 证明：SDK 测试 `tests/orchestrator/host/`（脚本模型跑完一局、门口检查、实例锁、无计数器、发布目录）；例子 `examples/orchestration-host/demo.py --scripted`；独立验收：仓库外空项目只装 wheel，真实 DeepSeek 跑完一个任务。
4. 桌面端后端改用同一入口（同一件事只留一条路径）：`OrchestrationService` 只补桌面自己的——配置段读取、提供方链读取、钉版核对与部署清单写盘、进度推送、通知存档、存储用量、界面投影、诊断、技能目录、执行图读写、保证通道读；删 `provider.py`、`runtime_profile.py`、`hierarchical.py`、`native_plane.py`、`skill_script_runner.py`、`lock.py` 与 `settings.py` 的大半。
5. 发版 opt.194，独立核验，真机一局。

## 四、第 2 片：桌面端后端改用新入口（已完成，待发版）

后端 `deskpet/orchestration/` 只剩桌面自己的事。`OrchestrationService` 持有一个 `OrchestrationHost`，旧的私有属性名（`_orchestrator`、`_control`、`_native`、`_duties`、`_driver`……）保留为对宿主的转发属性，投影、诊断、技能目录、执行图读写照旧用它们。

- 删除：`runtime_profile.py`、`hierarchical.py`、`native_plane.py`、`skill_script_runner.py`、`lock.py`；测试 `test_source_runtime_profile.py`、`test_thinking_pools.py`、`test_startup_failure_recovery.py`、`test_frozen_sandbox_admission.py`、`test_bge_m3_onnx_port.py`、`test_skill_script_runner.py` 搬进 SDK `tests/orchestrator/host/`（`test_provider.py`、`test_host_recovery.py`、`test_sandbox_probe.py`、`test_embedding_port.py`、`test_script_runner.py`）。
- `settings.py`：`OrchestrationSettings(HostSettings)` 只加总开关、存储提醒阈值、转发主机、思考开关、回显别名。
- `provider.py`：只剩提供方链快照（`ProviderSnapshot`）、`model_config()`（快照 → SDK `ModelConfig`）、钉死分词文件路径、模型目录。
- `wiring.py`：不再建提供方；给宿主一个带"按端点加额外请求头"钩子的 httpx 客户端。
- `service_domains/core.py`：拼装参数一处交给宿主（`world_domain="desktop"`、宿主指纹、通知存档回调、自动模式读取、模型目录、执行图端口、`extra_secrets=(密钥,)`）；桌面补钉版核对（宿主启动前）、部署清单写盘、通知续读、诊断探测、重建后重连（`on_rebuilt`）。
- `service_domains/commands.py`、`runtime.py`、`status.py`：命令与读取全部转发；`HostRequestError` → `OrchestrationRequestError`（子类）。
- 测试改接点：`_layered_child.py`／`_layered_lane.py` 打桩 `agent_orchestrator.host.host.embedding_port`；`_pool_identity.py` 直接用 SDK `NativePools`；`test_deployment_manifest.py`／`test_global_budget_setting.py` 打桩 `OrchestrationHost.taskgraph_acceptance_status`；`test_wiring_isolation.py` 改为核对交给服务的快照带回显别名，再经 `model_config` 到 `ModelConfig`（别名到每个池的提供方由 SDK `test_provider.py` 钉）；`test_hierarchical_host_integration.py` 用 `goal_world("desktop")`；`test_review_fixes.py` 白盒改到宿主（`_host._rebuild`、`_host._failures`）。
- 执行池身份：`test_pool_identity_bytes.py` 对基准逐字节相同（拼装函数同一份）。
- 对着 SDK 源码跑后端测试的办法：后端虚拟环境装的是钉版轮子（opt.193 没有 `agent_orchestrator.host`），所以 `PYTHONPATH` 指到 SDK `src`；源码清单的验收门是 NOT_RUN，发版门才把它写成 VALIDATED，所以本机 pytest 加一个临时插件把 `taskgraph_acceptance_status` 当作 VALIDATED（只在本次测试调用里，不进仓库）。子进程起服务的 `test_layered_scripted_lane.py` 一条因此在发版前红，发版后对着钉版轮子重跑。
- 禁区比对（`scripts/code_quality/guard.py`，对 HEAD）：报告存 `禁区比对-第2片.txt`。减少的字面量都是搬进 SDK 的那些（SDK 一侧已在第 1 片提交里），增加的是转出名与新函数名；工具说明、提示词没有变（执行池身份测试逐字节相同）。
- 文档：`ARCHITECTURE/AGENT_ORCHESTRATION.md` 新头、`AGENT_HARNESS.md` 两处路径、`backend/deskpet/orchestration/__init__.py` 文件头。

## 五、独立核验与仓库外验收（发版前）

- 独立核验（opus 子代理，只读）：`独立核验-opt194.md`，结论 PASS，"必须处理"为空。采纳的建议：①配了 DeepSeek 但缺分词文件时原因说"只支持 DeepSeek"会误导 → 宿主分开说（`_no_pool_reason`）；②驱动循环每轮的存储用量刷新丢了 → 宿主加 `on_round` 回调，桌面挂 `StorageUsage.schedule_if_stale`；⑤没起来时每次列任务、每个节拍各打一条带堆栈的日志 → 这两处降为 debug。记下不做的：③钉版核对在拿锁之前（只在同目录两个不同版本进程同时在时有影响）；④执行池身份测试不经宿主拼装（本次逐行对过参数）。
- 仓库外验收（脚本模型）：`~/sh-ext-accept/`，只装从源码构建的 wheel（`uv pip install <wheel>`），跑 `demo.py --scripted`。**第一次 FAILED（planning_failed）**：任务要求 `file:NOTES.md` 由沙箱里宿主解释器跑 pytest 核对，空项目没有 pytest → 核对失败 → 修复轮把脚本回复用完。这是只在仓库外才暴露的缺口（仓库虚拟环境一直有 pytest）。改法：`pytest>=8.3,<9` 从 `testing` 扩展改为 SDK 正式依赖（锁文件随之变），接入说明写明。改后重装重跑：**COMPLETED（verification_passed）**，用量 settled 1050。
