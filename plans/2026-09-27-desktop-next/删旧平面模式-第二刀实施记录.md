# 删旧平面模式 · 第二刀实施记录

日期：2026-10-02。依据：`删旧平面模式-第二刀施工清单.md`（一名 Opus 只读盘点写成）。范围：冲突任务、
冲突那一支的人工仲裁、冲突预留、最终独立综合、系统尾池、改图台账；前端"冲突核对预留""最终独立
综合"控件与文档冲突仲裁展示。保留并改造：两步结论矛盾时"都标有争议、不进知识库、如实写进最终报告"。

## 动手前定下的事（清单第〇节 12 条）

按"技术取舍交独立盘点员建议、主会话裁决"的约定，12 条全部采纳盘点员的建议：

- 前端仲裁按钮还给"收尾判定交人裁决"用，只删文档冲突那部分（选项只认 met / unmet）。
- `_dispute` 改成双方互记对方（`disputed_by` 对称）；`Claim.conflict_id`、`Claim.resolved_by` 删。
  已入库的旧知识被后来者反驳时照旧留在知识库、只标 `disputed_by`（不加新规则）。
- 领域档案内容不动（冲突模板、综合默认策略、`arbitration` 判据种类、仲裁者/综合者模板键都留到
  第三刀）；`ARBITRATION_PREFIX`、`CONFLICT_POLICY` 两个常量搬进 `governance/domains.py`。
- 三张晋级空表这一刀不删（保证通道每次读证据都按表名清单读它们，要先改读取方式）。
- 任务种类收成只有 `work`；改 `contracts/models.py` 后同步网络文档编码登记里它的哈希。
- 删综合会改保证通道本地核验输入的格式（去掉 `require_synthesis_knowledge` 字段与 schema 里
  对应项）。按"开发期不兼容旧数据"直接删；在途任务受不受影响放到真机局观察。
- 删系统尾池时，顺带消失的两道校验（审阅主体名、最终审查不得挪用别的账户）已没有要保护的东西。
- 知识共享演示（命令行 `demo --scenario knowledge-sharing` 与夹具 `COMPARE_*`）和 Host 的仲裁夹具
  `native_arbitration` 原定第三刀，因依赖已删字段提前到这一刀。
- SDK 一次发布，Host 与前端同一次提交钉版（门面已把两个旧字段当未知字段按名拒绝）。

## 做了什么

### 争议改为从声明本身得出（先做，测试先行）

- `verification/conflicts.py` 新增 `mission_disputes(store, mission_id)`：取"有争议"或被别人
  记了 `disputed_by` 的声明，每条给出 `claim_id / key / stance / status / source_task /
  disputed_by / in_knowledge`，按 id 排序。纯读。
- `commit_service._dispute`：双方互记对方；冲突表那一段（并入已有冲突、文档冲突重算、取消文档
  仲裁、开冲突任务）删除。
- 最终报告：`conflicts`、`unresolved_conflicts` 两个键换成 `disputes`（同一函数）。门面快照也带
  `disputes`，Host 详情直接读它（不在 Host 再写一份派生）。证据导出的 `knowledge.json` 同样换成
  `disputes`。
- 摘要、压缩去掉"未决冲突"；文档上下文去掉"人工裁决注记"；检索给出的争议条目里
  `conflict_id/resolved_by` 换成 `disputed_by`。
- 新测试 `step04/test_disputes_on_leaf_steps.py`（2 条，分层步骤世界）：①两条都只是"支持"的
  相反结论 → 双方都标有争议、互记对方、知识库为空、派生列表两条；②与已验证知识相反 → 后来这条
  有争议且不进知识库，旧知识仍是已验证并记着反驳者，派生列表里 `in_knowledge` 分别为真/假，摘要里
  有它、没有"未决冲突"键。改前跑：导入失败（函数还不存在）；改后通过。
- 故意改坏：去掉"互记对方" → 2 条失败；去掉"有矛盾就封顶为有争议" → 失败；用备份恢复后通过。
  另试了"去掉 `continue`"——不失败，因为声明已是有争议状态、本来就不会入库，真正守这一点的是封顶
  那一行，所以改坏换成了封顶那一行。

- 核验员顺带指出（原有缺陷，不是本刀引入）：同一份结果里两条声明反驳同一条旧声明时，第二次写入用的是
  循环前读到的旧副本，会冲掉第一条的反驳记录。现在争议直接从这个字段读出，漏一条就是报告漏一条，所以修了：
  `_dispute` 写入前重读对方当前状态。新增第 3 条测试（一份结果两条相反结论）；去掉重读则失败，恢复后通过。
