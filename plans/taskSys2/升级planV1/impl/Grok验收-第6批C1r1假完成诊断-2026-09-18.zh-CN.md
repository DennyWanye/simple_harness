### 1.2 三条 hidden 与题面的对应

| hidden 测试 | 题面是否明示 | 最接近的暗示 | 基线会怎样 |

## 3. 判定理由

### 3.1 为什么不是 A（SDK 编排缺陷 / P0）

A 的成立条件是：编排在**自己的准则已被证据证伪**时仍 COMPLETED。本局没有这条链。

- 确定性 `code_test` 跑的是工作区 `tests/`，6 passed，命令不含 hidden。
- 根准则 SEMANTIC，证据要求是 covering tests 绿；covering tests 确实绿。
- 系统未自填 PASS；评审员 `official=1` 的 ACCEPT 来自 `<critic_verdict>`。
- hidden 失败发生在 Host 事后 `grade.py`，编排不可见——这是题目设计（「隐藏目标不得出现在提示、workspace、success_criteria 或 Verifier」），不是漏跑。

可选 P1（**不阻塞**）：不要让根评审去猜 hidden。若要加强「生产说明也要覆盖」，应改**题面契约**或模型侧覆盖，而不是让 SEMANTIC 评审在 `findings.md` 里搜「Residual gaps」当 fail-closed——那会误伤诚实。

N2 / root-reviewer-v3 的已知风险（计划一致性审计 §3.3）是「按 `mission_goal` 改写准则后 COMPLETED、hidden 仍红」。本局形态相似，但 **N2 没有放宽本局主句**：主句是并发 `summary()`，hidden 红的是另外三条。不是「解释权把失败说成成功」。

### 3.2 为什么是 B（模型答题质量）

1. 模型在 facts/diagnosis/findings/summary/apply REPORT 里 **自己推导** 了半开窗口、空 rate、回拨时钟，并选择不修。
2. 用户主句要求的并发 `summary()` **已修且有测试**；hidden 并发条 PASS。
3. 「不要只让可见测试变绿」被理解成「加并发测试」，而不是「把 README 生产说明做成契约测试」。
4. **第 5 批对照（同题、同模型 grok-4.6）：**
   - C1-r0（`f2dfa64`）：hidden **同一 3 条红**，当时编排因 N14（测试文件不在树）REJECT，`declared_complete=false`，`false_completion=false`。交付窗口仍闭-闭。
   - C1-r1：`collector.window` 做成 `[start,end)`，`rate()` 有空/非正跨距守卫，**hidden 4/4 PASS**；编排因 N14 两次 REJECT 未 COMPLETED。官方 hidden 绿、公开自写测试仍有红。
5. 第 6 批修了 N14（tests 端口进树，一次根评审即 ACCEPT），模型这回走了「只修并发、边界当残留」的路径。同模型能做全套 hidden，本局是覆盖范围选择，不是编排看不见。

### 3.3 为什么 C 为辅（题目构造）

- `construction.json` 宣称 hidden 判「并发安全」；文件名 `test_hidden_concurrency.py`；4 条里 3 条与并发无关。
- 「空窗口/空指标不报错」在 README、用户一句话、Mission 附录里都没有。
- 公开测试故意不钉窗口端点，等于把半开策略藏进 hidden，而题面只说「相邻时间片」。
- 用户 2026-09-16 冻结「夹具一字未动」，构造缺口是题集身份，不是本批 SDK 回归。

C 不能单独解释「模型已经把缺口写进 findings 却不修」——那一部分仍是 B。
