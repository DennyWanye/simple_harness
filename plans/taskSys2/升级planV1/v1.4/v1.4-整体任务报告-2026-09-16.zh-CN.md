## 5. 执行顺序（§23）

```text
P0（完成）
→ P1.1 → P1.1b → P1.1c
→ P2.1 → P2.1b → P2.1c → P2.2 → P2.2b
→ P1.2 → P1.3
→ P2.3a → P2.3b → P2.3c（首次 Grok 验收）
→ P5.1 → P3.0 → P3.1 → P3.5 → P3.6 → P3.2 → P3.3 → P3.4 → P3 其余
→ P6.0 → P6.1 → P6.2 → P6.3 → P5 → P4 → P7.1 → P7.2 → P7 → P8 → P9
```

设计原则：HTN 纯函数最先；P1 只做 P2 依赖的部分并在接线前补齐；首次 Grok 验收之前不引入 AER 的热文件改动；每片先写红测试、独立回归、旧模式零回归、推 main、更新 HANDOFF 与 ARCHITECTURE；热文件（commit_service、event_handler、versioning、action_commits、connectors）单代理；最多 3 个子代理并行。
