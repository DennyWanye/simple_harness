# 第 7 块：子 Agent、多成员、完整结果——一页方案

日期：2026-10-21

## 现状对照

| 要求 | 现在 | 要补 |
|---|---|---|
| 子 Agent：工具白名单、层数和轮次上限、共用父任务预算、权限只缩不放 | 编排里的"子 Agent"就是计划里的子步骤：规划器把目标拆成子目标，每个叶子步骤是一个独立 Agent；工具 = 任务名单 ∩ 步骤名单 ∩ 部署策略（只缩不放）；预算从任务总账扣（子账挂在任务账下）；层数 `max_depth`、扩展次数 `max_expanded_nodes`、候选 `max_candidates` 都在计划预算里 | 写清口径 + 两条测试：子步骤拿不到父步骤没有的工具；子步骤的动作要自己的批准（批准父动作不等于批准子动作） |
| 多成员 | 一人一个宿主（各自数据目录、各自当事人）；同一目录有实例锁，第二个宿主起不来 | 写清做法 + 一条测试：两个宿主各自的任务互相看不见、动不了（跨宿主用对方任务号调读写一律 not_found） |
| 资料和技能注入带来源和版本 | 资料：`register_source` / `supersede_source` / `revoke_source`，带版本；技能：目录按安装版本钉死 | 写清 |
| 外部内容当作不可信 | 任务 `untrusted_sources` 前缀；读到的内容标成数据；授权只认宿主与 SDK 给的身份 | 一条测试：外部内容里写的"批准 / 允许"不产生任何审批 |
| 工具和技能更新：旧任务用旧集合、新任务用新集合；在途待批和未结清动作不丢 | 任务建立时冻结工具名单；重开宿主换工具集，旧任务仍按旧名单（名单外的调用被拒成事件）；审批卡与动作账本持久 | 一条测试：换工具集重开，等批的审批卡与未结清动作还在、能继续 |
| 超过 32 KB 的工具结果能完整读取；大文件给受控读取引用 | 超限的工具结果：完整记录进执行库，模型拿到预览 + `journal_read_back`（`session_history_read(seq)` 精确回读）；工作区大文件 `workspace_read_file` 自动分页（`next_offset` + `expected_sha256`） | 一条测试：应用工具回 100 KB 的结果，模型能用 `session_history_read` 读全；写清 |

## 做法

主要是把现有机制讲清楚并用测试钉住，不新增机制：
1. 新测试文件 `tests/orchestrator/host/test_members_and_subagents.py`：上面表里的 5～6 条。
2. 接入说明加 §4d"子 Agent、多成员、外部内容、工具集更新、大结果"。
3. 要是测试发现哪条不成立，就补机制（优先补约束，不加语义规则）。
