# 拆类核对脚本（阶段 6 起用）

拆巨型类（`split_class.py`）之后，每片跑 `check_split.sh <原文件快照> <源文件> <类名> <子包目录>`，路径相对 backend：

- `same_methods.py`：搬前搬后每个方法与类属性语法树逐字相同（类型检查存根不算）。
- `dir_cmp.py`：原类与新类的属性集合（`dir()`）一致。
- `ext_names.py`：全后端（产品、测试、脚本）从原模块导入的名字，原模块是否都还有；缺的用 `add_reexports.py` 以同名别名转出。
- `patch_check.py`：测试打桩是否落空（打在门面上、读的人在子模块里）。
- 日志记录器：原文件按 `__name__` 或不带名字取的记录器，搬家后名字会变，要钉回原模块名。
- 函数身份：工具处理函数身份、工作流节点清单、工具生命周期哈希都用"模块名:限定名"，交出函数的代码不能搬。
- `method_diff.py`：列出不逐字相同的方法的差异（常见是函数内相对导入多一个点）。
- `split_groups.py`：按源码连续区段生成 `split_class.py` 的分组 JSON。
