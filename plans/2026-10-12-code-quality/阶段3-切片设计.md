## 上提规则（工具 lift_imports.py 自动判断，判不清就不动）

可上提：

- 标准库导入：不在函数内 `if` 下即可。
- 项目内部导入：不在函数内 `if` 下、不被 `try … except ImportError` 包着，且上提后不形成循环（逐条加进依赖图再判，避免多条合起来成环）。
- 第三方导入：只上提直接写在函数体第一层、轻量的（不含 torch、PIL、pptx、浏览器与语音识别等重型或平台专用包）。

不上提，留在函数内并补注释写原因：

- 可选依赖（try ImportError 包着）。
- 平台专用（函数内 `if` 下，例如 Windows 专用包）——这台机器测不出来。
- 重型第三方包（影响启动耗时）。
- 会成环的：按 3.3 处理（共用部分抽到下层模块，或改成参数传入）。

一律跳过的文件：禁区（迁移、表结构、编解码器钉死的契约文件、工作流节点文件——它们按源码文本算身份）。

## 行为风险与对策

1. **测试打桩失效。** 函数内 `from X import Y` 每次调用重新取 `X.Y`，测试对 `X.Y` 打桩能生效；上提后模块导入时就绑定了 `Y`，打桩静默失效。对策：工具先扫全部测试里对 `X.Y` 的打桩（字符串路径、`setattr(模块, "Y")`、`patch.object`），命中的不上提。
2. **名字冲突。** 上提后名字变成模块全局。对策：模块里已有同名全局、或同一函数里该名字另有赋值、或两个函数用同一别名导入不同对象，都不上提。
3. **导入期顺序与副作用。** 对策：启动快照、控制通道快照每批必跑；导入冒烟用全新进程逐个导入改动模块。
4. **启动耗时。** 对策：每批前后量 `import main` 耗时，涨幅超过 10% 停下查。
5. **SDK 源码改动。** SDK 改动随阶段 4 的 SDK 发版一起出（发版脚本会重生成部署清单）。阶段 3 期间不发 SDK。
