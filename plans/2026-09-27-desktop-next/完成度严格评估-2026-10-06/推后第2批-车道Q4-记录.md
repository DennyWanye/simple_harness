### 1.4 前后端怎么共用同一份

### 1.5 改成什么

U03（Host）：

- `projection.py` 加一个对外合同投影：`project_reply(动词, 回复)`、`project_error(动词, 错误回执)`。
  - Assurance 三个读动词：用 SDK 的 `assurance.contracts.validate` 按 host-*-v1 核，核过后出一份新拷贝。
  - 执行图四个有合同的读动词（snapshot、why_not_ready、diff、convergence）：用 SDK 的边界 codec（`from_json(...).to_json()`）核并重建。理由：T06 定了"执行图合同在生产代码里只走 codec 一条路径"，codec 与 Schema 一致由 SDK 用例守住。
  - 错误回执：`assurance_error` 核 host-error-v1；`taskgraph_error` 核 taskgraph-error-v1。
- 不合合同：Host 拒绝，回 `error_code = "protocol_error"`，一句大白话，不带数据，不带原回执；原因写进 Host 日志。
- 接入点：`handlers.handle` 一处。这几个动词的回复只能经投影出门。

U02（前端）：

- 新文件 `tauri-app/src/ws/orchestrationContracts.ts`：
  - 一个 JSON Schema 子集核对器，只实现两组文件实际用到的关键字。碰到没实现的关键字直接报错，不猜。
  - `guardIncoming(message)`：对上面几个动词的 `_response`，按同一张合同核 `data` 和错误回执。不合格就把消息改成协议错（`ok:false`、`error_code:"protocol_error"`、一句大白话），数据不往下传。
- `ControlChannel.onmessage` 收到消息后先过 `guardIncoming`，再分发。所有编排视图只走这一个入口。
- 界面：
  - 保证视图：原有"读失败保留上次画面并显示原因"的路径直接显示这句大白话。
  - 改计划进度：协议错时"已过期"后面写这句大白话。
  - 为什么还不开工：显示这句大白话。

协议错那句话（Host 与前端同一句）："收到的数据格式不对，没有显示，请稍后重新读取。"

### 1.6 删掉哪条旧路径

- Host：这几个动词"拿到 SDK 回复就 `_ok`"、"错误回执原样挂上"的直通删掉。只剩经投影一条。
- 前端：`assuranceStore.ts` 手抄的 `parseSnapshot` / `parseReview` / `parseUseCheck` / `parseError` 与 `invalid` 一族整段删掉；`MissionAssurance.tsx` 里"Assurance 错误回执格式无效"分支删掉。形状只由 Schema 核一次。视图里只留请求对应关系的核对（请求号、任务号、视图与序号），这不是形状校验。

### 1.7 守什么保证

1. SDK 回复不合公开合同时，Host 不转发，报具名协议错。
2. 前端只把合公开合同的数据交给界面。坏消息标协议错，界面保留上次画面。
3. 前后端用同一批 Schema 文件。Host 用的包内文件与仓库源码字节相同。
4. 不合法不变成业务状态：不填 0、不填空列表、不映射成 UNKNOWN。

### 1.9 按核心思想自查

- 这是秩序，不是语义：只核"形状合不合公开合同"。不判断内容对错，不加业务规则。
- 同一件事一条路径：Host 只在 `handlers` 一处投影；前端只在 `ControlChannel` 一处核；手抄解析器删掉。
- 不加兼容：不留旧直通，不留"宽松模式"。
- 不改工具说明、不改模板文字、不改并发上限。不改 SDK 源码。
